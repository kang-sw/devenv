Maximum-delegation posture for this session: delegate all task execution; do not execute inline. The lead reads this playbook, writes delegate prompts, adjudicates results, asks the user for approval or judgment, and writes the final synthesis. No inline reads, searches, edits, tests, commits, or artifact writing to solve the task.

Prefer a fork for ad-hoc work where the lead's current conversation context is necessary: context-rich code or file edits, authoring that depends on the live discussion, or complex-instruction queries. Because a fork inherits context, it avoids re-injecting discussion history and is the preferred delegated substitute for work the lead would otherwise do inline. Use a fresh spawn when the task can be specified by naming an artifact, command, or scoped question. The lead passes the artifact path/name, minimal task context, constraints, and stop condition; the spawned delegate reads the artifact directly. If a fork does not execute the task and instead reports delegation instructions back to the lead, treat that as a failed fork. Re-dispatch the same work as a fresh spawn with only the minimal context, relevant artifact paths, constraints, and stop condition needed for stateless execution.

Treat a subagent as forked only when it inherits the current conversation context and executes separately from the lead without sharing the lead's active reasoning or control flow.

If no host-specific invocation guidance is injected, treat forked delegation as available only when the host clearly provides inherited current context plus isolated execution. If no forked mechanism exists, or if availability is uncertain, ask the user whether to suspend maximum-delegation posture. Only after explicit approval may the lead proceed inline under the session's ordinary workflow rules.

Keep the fork prompt concise, usually under 300 words, because it inherits context. Open with a plain lead handoff: "You are the executing delegate for this task in the current workspace; this handoff is the delegation boundary. From this point, do not fork, spawn a subagent, start another agent process, or delegate again; work directly in this forked workspace." Then state only the context needed to complete the task, permitted files/actions, constraints, and concrete stop condition. Require this exact return format: `Outcome: ...`; `Files changed: ... or none`; `Verification: command/result summary, or not applicable`; `Blockers: ... or none`; `Commit: <hash> or none`. Close with the same boundary in shorter form: "Again: do not fork, spawn a subagent, start another agent process, or delegate again. If direct work is impossible, report the blocker instead." Do not use XML wrappers, all-caps role resets, "forget your posture" language, or first-output-must-be-tool-call directives; those prompt-injection-style controls add noise in an inherited-context fork and may be copied into the response instead of guiding execution.
