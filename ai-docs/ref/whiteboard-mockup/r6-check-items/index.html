check는 사용자에게 "읽어 보세요", "확인해 주세요", "진행해도 될까요?"를 요청하는 게이트입니다. 선택지를 고르는 결정(policy)도, 알리기만 하는 통보(announced/technical)도 아닙니다.

  • 항목 하나에 체크박스 하나, 한 번에 하나씩 체크합니다.
  • 체크하면 ok, 옆의 ✕ 는 no이며 펜으로 메모를 남길 수 있습니다.
  • 답은 아래 답변 바에 쌓이고, 복사 버튼으로 보내기 전까지는 보내지 않은 상태입니다.

Mockup notes (not part of the board)

  1. Placement. Template order is recap, check list, topic body, then the existing policy and ack items. The check list uses the recessed .acks surface and the ack row's own checkbox row, so it reads as a sibling of acks, with no class tag and a list header with progress instead.
  2. Staging. Tick a box (ok), press the x (no), or write with the pen: the reply bar's answer block updates exactly like policy and ack answers, and nothing is sent until the existing copy button. Try it; staged.png is that state.
  3. Waiting count. Open checks fold into the existing amber "answer needed" chip in the topic bar and page header: 3 = 2 open checks + 1 policy. Answered rows (573, 574) leave the count. The ack chip stays acks only; the topic bar's bulk buttons never tick checks, since a gate is answered one item at a time (the all-ok box in the reply bar likewise covers acks only).
  4. Answers. ok and no are plain values in the existing answer-block grammar (571=ok, 572=no^note); a note on an unanswered row is a note alone (=^note), as for acks.
