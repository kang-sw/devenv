r5 status band mockup static placeholder data; real page look from dashboard.css

What this is. Three ways to put the terminal status band on the live session page, drawn in place on a trimmed copy of it (header, agents/conversation split, composer). Each variant is shown at desktop width and at a 390 px phone width, then through every state the band can be in. The mailbox id of the terminal band is left out everywhere: the page header already carries it.

Priority order (yours). Folder, branch state, branch sync, usage or cost when available, and above all current context usage. In every variant the context bar is the only element with a bar and the largest type.

Element sheet

Context usage, the loudest element. Three states share one language: fill colour, a triangle glyph and a short flag from 80%, a filled percent pill at 95%. Ticks on the bar mark 80% and 95%. The glyph and flag mean the state never depends on colour alone.

Variant A — one-line strip under the page header

Placement: a card between the header and the agents/conversation split, flex: none like .top. Shows: folder, branch, sync, dirty stat, context bar (grows to fill the row), weekly usage, cost. Drops: model and effort (the host chip is in the header), mailbox id (already in the header), agenda keys. Wide: one line, 32 px tall. Phone: context takes the first row alone, identity wraps beneath it; weekly usage hides below about 560 px, cost stays. Phone height: two rows, 56 px. Cheapest on a desktop screen; always above the fold on a phone.

Variant B — two-row band like the terminal

Placement: a card between the header and the split, same slot as A. Shows everything the terminal band shows: folder, branch, sync, dirty stat, model and effort on row 1; context bar, cache rate, weekly usage, cost on row 2; agenda keys on row 3. Phone: row 1 keeps folder, branch, sync and the dirty stat, row 2 splits into the bar row and a usage/cost row; model, effort and the agenda row hide. Height: about 80 px on both widths, the tallest option, taken from a page that already fits little on a phone. Best when the page really replaces the terminal.

Variant C — context folded into the composer edge

Placement: no band at the top. The composer card grows a context row above the textarea (bar, percent, tokens/limit, cache rate) and a one-line footer under it (folder, branch, sync, dirty stat; weekly usage and cost on the right). Everything stays next to the thumb on a phone and survives scrolling, and the header gains no height.
