## 1. Exposure and timing

- **VERIFIED:** The live mod is the strongest candidate. CC's `turn.step` stream maps `thinking_delta` to a `thinking` chunk carrying text while iterating model events (CC bytes 297803280–297806180). The repository already taps that stream, but uses thinking only for phase/rate telemetry and collects only ordinary text as replies (`agents-plugin/hooks/claude-mod/register.ts:1670–1690`; `dashboard.ts:374–395,1579–1590` in the same directory).
- **INFERRED:** A nonempty, explicitly summarized thinking delta could reach the mod before request/turn completion. **UNVERIFIED:** Actual first-summary latency, chunk cadence, and current-model delivery under explicit summarization. This was source inspection, not a streaming experiment.
- **VERIFIED:** Classic Stop/SubagentStop schemas expose a transcript locator and optional last-assistant text, not an explicit summary delta (CC bytes 280526451, 280532400–280534700). Those are settlement observations, not evidence of mid-thinking availability. Transcript timestamps identify records, not when bytes became readable; no write/flush timing was measured.
- **VERIFIED:** Headless stream JSON is another candidate transport. CC recognizes partial-message output; its internal stream carries thinking deltas. The current hosted Claude arguments request verbose stream JSON without partial messages, and its mapper handles assistant text/tool calls, not summaries (`Go/wsagent/claude.go:111–117,715–723,1226–1277`). **UNVERIFIED:** Current-model partial stdout behavior and transcript persistence of explicitly requested summaries. Neither transport independently establishes public-summary semantics.

## 2. Usable content on the current model

- **VERIFIED:** Samples contained 15, 10, and 12 thinking blocks: all 37 had empty or absent thinking text (zero UTF-8 bytes) and nonempty signatures. No `redacted_thinking` blocks or explicit summary blocks were observed in sampled message content. Thinking-bearing records had timestamps in 29 cases. None supplies usable display text; signatures are not summaries.
- **VERIFIED:** The installed settings schema describes `showThinkingSummaries` as requesting **API-side thinking summaries**, shown in the conversation/transcript view (CC bytes 279045670–279046040). Its resolver maps explicit true/false to `summarized`/`omitted`; interactive default resolution uses false (CC bytes 281945900–281947500). Changelog 2.1.89 records the default-generation change (`Changelog:8008,8053`). This supports an opt-in candidate, not proof that these sampled sessions requested summaries.
- **INFERRED:** Newer-model signature-only output can coexist with thinking activity when display text is omitted. **UNVERIFIED:** Whether explicit `summarized` produces nonempty public summaries for this model/account/provider, their length distribution, and delivery timing. The only observed thinking-text length class was zero.
- **INFERRED:** Redacted opaque data, empty blocks, and signature-only blocks are unusable. Generic nonempty `thinking` is also insufficient: older/raw thinking must not be relabeled as a summary. A producer would need verified explicit summary-mode provenance and a supported model/provider contract. CC separately documents `highlights` as short titles rather than prose summaries, with hosting/rejection restrictions (CC bytes 280938100–280939750); that is not interchangeable evidence for summarized prose.

## 3. Go admission and directional compatibility

- **VERIFIED:** This is more than adding an Anthropic validation string. Existing source validation accepts only the two OpenAI Responses pairs; terminal admission additionally requires Pi, real slot ownership and a non-hosted owner, then rejects a non-Pi adapter's optional projection (`Go/wslive/reasoning_summary.go:29–68,88–153`; `Go/mcp/summary_owner.go:11–43`; `Go/mcp/live_snapshot.go:483–509,608–613`). Hosted admission likewise requires a Pi lead and observed turn identity (`Go/wsagent/runner_summary.go:13–45,72–114`).
- **INFERRED:** A future implementation needs a source-specific negotiated contract; explicit public-summary provenance; producer/request/attempt/block identities and monotonic revisions; bounded text-only projections; real terminal/hosted ownership fencing; abort/retry/gap handling; and natural-settlement retention. It must preserve current byte/count bounds and exclude signatures, opaque data and raw thinking. Hosted Claude would also need native stream mapping. Existing Pi admission cannot simply be widened while pretending Claude already supplies those facts.
- **INFERRED — T0 candidate:** Old Claude producers calling a new receiver can remain unchanged. A new producer facing the current receiver must detect unsupported Claude admission and explicitly report summary unavailability without sending/claiming accepted summary intent. The generic capability name alone does not prove source support. Current negotiation/refusal is at `Go/mcp/live_snapshot.go:483–509,608–613`; retain all legacy calls. This is a proposed design condition, not a settled implementation grade.
- **INFERRED — T1 retained-display candidate:** A new receiver writing Claude-source history in the existing optional field would meet today's dashboard, which hides it because source validation fails (`Go/wsdashboard/reasoning_summary.go:28–46`; `Go/wslive/reasoning_summary.go:118–119,142–153`). Today's ring reader decodes it, and appends create separate files rather than rewrite retained entries (`Go/wslive/ring.go:173–207,251–260,346–365`). A future reader admitting that source could redisplay the retained bytes on reopen; normal retention trimming still applies (`ring.go:249–260`). Thus this path is display-degraded, not overwrite recovery. Cross-version fixtures remain required; existing historical compatibility tests cover the earlier Pi addition, not Claude (`Go/wslive/summary_compat_test.go:18–31,82–127`).

## 4. Recommendation and gaps

- **INFERRED:** **Do not build a transcript-scraping producer for current default output.** The authorized sample has no usable summary text, and transcript timestamps cannot establish live availability. Conditional build feasibility exists for an explicitly opted-in live mod source, with headless support assessed separately.
- **UNVERIFIED:** Before approving implementation, establish the current model/provider's public-summary contract, actual summarized-mode output and timing, empty/redacted/rejection behavior, request/retry identity guarantees, and directional admission/history fixtures. Any live experiment or summary-setting change requires separate authorization. No code, settings, owner sessions or shared runtime were changed; no launches, monitors, timers, subagents or independent audit were started.
