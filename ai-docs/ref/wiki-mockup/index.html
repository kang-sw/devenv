What this is. The tracker drawer drawn open, with the Items panel's header switch set to Wiki. Click around: the tree, the picker (handbook), a wiki: link (book mark) or an #maya-12 reference in the page, the pen to edit, the search box. The scene buttons above jump to fixed states; the legend below says what each part shows.

Reading

  • Items | Wiki takes the Items header's title spot as a mode switch (item window segment look, so it does not read as one more scope pill). Under Wiki the Items panel holds the wiki; the tab pane on the right is unchanged.
  • Picker: wiki/ + name, a menu of the store's wikis (one refs/heads/wiki/<name> each) with page count and last change, then New wiki.
  • Tree from folder paths (page path = file path without .md); _attachments/ is not listed. The search box filters by path and text, with a snippet for a body hit.
  • Page: tracker renderer look (the shared .md rules), path crumb, last author, time, commit. wiki:<name>/<path> links carry a book mark and switch the panel (a missing page is dashed and opens a new page there); #ID opens the item window; attachment:<sha256> images come from the wiki tree's _attachments/ through the wiki image route.
  • The more menu copies the absolute link and points history and restore at the Support agent (agent tools only, per the ticket).

Editing and refused save

  • Edit replaces the page in place with the shared editor (.tked: Write / Preview tabs, the server-rendered preview), a pasted image pending (held daemon-local for the preview, committed into _attachments/ by the save), Save / Cancel, and the base commit as a quiet mono label at the bar's end.
  • Refused save: the reason (who, which commit, merge base), the ways out (Copy mine, Reload theirs, Edit again on theirs as the new base), then yours and theirs side by side (stacked when the page column is under 640px). Overlapping lines use the tracker's concurrent-write tone; lines changed on one side only (they would have merged) get a light wash.
  • Empty store: no wiki yet; the call to action creates wiki/<name> with its first page (a wiki is created by its first save). Name rule shown live: [a-z0-9][a-z0-9-]*, up to 64.

Layouts, item link, notes

  • A: Items panel two thirds, tab pane one third. D: Items | Notifications | tab pane. Narrow: one tab pane; Wiki is its own tab after Items, and the tree folds into a Pages control above the page. Store page: the same switch, full page, a wider tree.
  • Item link: the item window of #maya-12, whose body links wiki:handbook/process/release; clicking it closes the window and switches the panel to that page (brief flash on the page head).
  • Mockup only: Save is refused the first time (raj saved meanwhile) and succeeds after Edit again; "New page" opens the editor with a path field. New classes are .wk-* and a.wlink (marked NEW in the stylesheet); everything else is lifted from tracker.css and page.css.
