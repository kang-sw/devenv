# Dogfood gaps: agy tune visibility, bound-child release safety, and merged impl branch identity

## Background

Three ws tool surprises were observed by the develop main lead during 2026-11-20/21 dogfooding. The observations below are distinguished from what this checkout's source verifies.

1. **Observed:** `config.tune` returned `unknown config key` for `agy.model_wait_retries`, prompting a manual global override. **Verified:** both package manifests declare that key (`agents-plugin/agy-config-manifest.json:13-17`, `agents-plugin-wsflow/agy-config-manifest.json:13-17`), and both Codex MCP declarations include the agy manifest alongside the Claude and dashboard manifests (`agents-plugin/.mcp.json:4-9`, `agents-plugin-wsflow/.mcp.json:4-12`). The server loads only paths in its process's `WS_MCP_CONFIG_MANIFESTS` at construction (`agents-plugin-tool/internal/mcp/config_manifest.go:18-26,106-129`; `agents-plugin-tool/internal/mcp/process_env.go:142-159`), adds only loaded keys to `config.list`, and rejects an undeclared key in `config.tune` (`agents-plugin-tool/internal/mcp/server_dispatch.go:388-415`). Thus the error proves the serving instance had not loaded that agy key; the source alone does not establish why the observed instance's manifest set differed from the package declarations. The original claim that the shipped catalog omits agy keys is incorrect. `claude.*` keys are declared in `agents-plugin/config-manifest.json:3-12`; no `codex.*` manifest key is declared in these two packages, so the observed comparison to tunable `codex.*` keys is unverified. **Expected:** a serving instance for either package exposes and tunes every declared agy key using its declared scope and validation, regardless of which harness first starts the shared daemon.
2. **Observed:** release cleaned a worktree while its child was still running. **Verified:** `agent.spawn(worktree: ...)` sets the child's root and cwd to that path (`agents-plugin-tool/internal/wsagent/agent_tools.go:669-708`). `worktree.release` resolves a path or worker key, then checks lease ownership unless forced (`agents-plugin-tool/internal/mcp/server_dispatch.go:903-933`; `agents-plugin-tool/internal/mcp/worktree_release_lock.go:87-97`). A matching lease authorizes the caller without checking child state (`agents-plugin-tool/internal/mcp/worktree_tools.go:778-787`); release then runs reset/clean and drops the lease (`agents-plugin-tool/internal/mcp/worktree_tools.go:840-901,659-682`). Existing `agent.list` data gives each child address, cwd, and state (`agents-plugin-tool/internal/wsagent/agent_tools.go:150-167,769-795`); `running`, `background`, `starting`, `idle`, and `waiting` are non-closed states (`agents-plugin-tool/internal/wsagent/agent_tools.go:201-227`). The runner also retains each conversation's root and status (`agents-plugin-tool/internal/wsagent/runner.go:1211-1233,1646-1660`). **Expected:** before hygiene, refuse a non-forced release while a non-closed bound child exists, and identify it; `force` remains the explicit override.
3. **Observed:** `git.resolve_impl_branch` suggested a previously merged branch name twice. **Verified:** ticket branch identity is deterministic from base and ticket stem (`agents-plugin-tool/internal/mcp/impl_identity.go:5-11`); `git.resolve_impl_branch` validates the resulting ref name but does not inspect its existence or merge state (`agents-plugin-tool/internal/mcp/impl_identity_tool.go:19-39`). `route.resolve_implement` likewise derives a ticket slug from the stem and observes the resulting target branch (`agents-plugin-tool/internal/mcp/implement_resolver.go:660-667`; `agents-plugin-tool/internal/mcp/session_state.go:1115-1124`). If that branch exists with zero commits ahead of its merge root, the route intentionally returns `recreate` with the *same* name; if unique commits remain, it stops (`agents-plugin-tool/internal/mcp/implement_resolver.go:529-543,866-889,1006-1021`). The original claim that the route directly calls `git.resolve_impl_branch`, or blindly suggests switching to an already-merged branch, is incorrect. **Expected:** resolve the owner policy in (1944) before changing the deterministic identity or the route's recreate behavior.

## Decisions

1. **Agy config visibility — proposed fix:** make the shared daemon's catalog and tune validation include the package's agy manifest for each supported serving context, and test both package variants and a daemon started by another harness. Diagnose manifest rejection separately through the existing `config.list` manifest errors before changing manifest contents (`agents-plugin-tool/internal/mcp/server_dispatch.go:388-415`; `agents-plugin-tool/internal/mcp/config_manifest.go:106-129`). Reject blindly accepting arbitrary `agy.*` strings: it would bypass manifest type and bounds validation (`agents-plugin-tool/internal/mcp/config_manifest.go:223-284`). **T0, proposed:** the new server adds keys to an unchanged `config.list`/`config.tune` shape; old callers still send the same arguments. An old server without the agy declaration refuses an agy write before storage (`agents-plugin-tool/internal/mcp/server_dispatch.go:411-417`), while a new server writes string overrides in the existing generic map, which older config readers can parse (`agents-plugin-tool/internal/wsconfig/config.go:34-47`). Reopening with the new server reads the retained map; no new on-disk field is proposed. Verify the actual daemon startup path before implementation.
2. **Bound-child release guard — proposed fix:** query the daemon runner's live child data under the target's release reservation, compare the child's canonical root/worktree path and non-closed state, then refuse before pre-release hooks or hygiene unless `force` is true. Use the existing child address in the error (`agents-plugin-tool/internal/wsagent/agent_tools.go:669-708,769-795`; `agents-plugin-tool/internal/mcp/worktree_release_lock.go:62-97`). Reject treating the lease worker key alone as proof no child is live: the current matching-lease path returns success without a child check (`agents-plugin-tool/internal/mcp/worktree_tools.go:778-787`). **T0, proposed:** the new handler reads existing child state and keeps `worktree.release` arguments and lease format; an old caller can invoke it and receives a refusal while the child is live, with no write. An old handler reads the same lease and can still release, so this is a forward safety fix, not a downgrade guarantee (`agents-plugin-tool/internal/mcp/server_dispatch.go:903-933`; `agents-plugin-tool/internal/mcp/worktree_tools.go:778-787,899-901`). Reopening a new version requires no data migration because no new state is written.
3. **Merged branch identity — proposed fix, pending (1944):** have both resolvers apply the same branch-existence and ahead-of-merge-root policy before suggesting a target, with a regression for a fully landed leftover and an unlanded collision. If (1944) chooses fresh names, mint a collision-free new name consistently in both tools; reject changing only `git.resolve_impl_branch`, which would leave route naming inconsistent (`agents-plugin-tool/internal/mcp/impl_identity_tool.go:29-39`; `agents-plugin-tool/internal/mcp/session_state.go:1115-1124`). **T0, proposed for a tool-output-only naming change:** both old and new tools read Git refs and return strings; neither writes a shared store (`agents-plugin-tool/internal/mcp/impl_identity_tool.go:29-39`; `agents-plugin-tool/internal/mcp/implement_resolver.go:529-543,866-889`). Old callers can read the new name from the unchanged response shape; old servers may still return the deterministic old name. A new version reobserves Git refs on each call, so no history migration is needed. Reassess if (1944) requires a new persistent identity or tool argument.

## Open Decision Queue

- **(1944) Owner policy — merged implementation branch identity:** Should a fully landed leftover keep today's canonical ticket branch name through explicit delete-and-recreate, or should each new run receive a distinct fresh branch name? The current route deliberately chooses `recreate` while `git.resolve_impl_branch` only returns the deterministic name (`agents-plugin-tool/internal/mcp/implement_resolver.go:866-889,1016-1019`; `agents-plugin-tool/internal/mcp/impl_identity_tool.go:29-39`). Settle this before Phase 1 changes branch naming.
