# Dashboard Composer Footer Controls and ws-Compaction Context Meter

## Background

The live session composer (`dashboard.tmpl` `#composer`) currently has two UX and behavioral gaps:

1. **Asymmetric, noisy `.cfoot` chrome without inline controls.** `r-sline` (`pageview_band.go`, `dashboard-conversation.css`) renders workspace folder, 5h/7d quota chips, and session cost (`~$USD`), producing cluttered footer noise on Claude and uneven empty/folder-only rows on AGY, Codex, and Pi. Meanwhile, switching **Model** and **Effort** requires opening the top-bar session menu (`dashboard-leads.js` `leadRows`). Removing `.cfoot` quota chips also risks hiding Codex's 5-hour window (`300m`), because `plan_usage_probe.go` currently keeps only `10080m` (`604800s`) weekly windows.
2. **Native-window context meter disconnected from ws compaction.** `pageview_band.go` `contextBar` scales `r-ctx` to raw `UsageContext.Window` (e.g., `1.0M`), draws hardcoded `.t80`/`.t95` CSS ticks, and displays trailing `.sb-flag` rectangle badges (`high`, `near limit`), even though ws compaction triggers at resolved `compaction.{lead,worker}_{advisory,hard}` thresholds (`wsconfig/compaction.go`). Hosted sessions in `wsagent/compaction.go` also lack the 1/3 and 2/3 intermediate nudges already present in `agents-plugin/hooks/claude-mod/timing.ts` (`agents-plugin/hooks/claude-mod/timing.ts#L85-L125`; no top-level `claude-mod/` directory exists, and `agents-plugin-wsflow/hooks/claude-mod/timing.ts` mirrors it) and `agents-plugin-pi/src/goal-loop.ts`.

Approved text mockup: [composer-meter-v2.html](ai-docs/assets/mockups/261120/composer-footer-context-meter/composer-meter-v2.html) (with sibling `composer-meter-v2.css` and `composer-meter-v2.js`). The mockup shows a third Permission trigger; it is **deliberately omitted** by settled decision (38) (Decision 1), so the implemented strip has two controls.

## Decisions

### 1. Composer Footer (`.cfoot`) Redesign
- **Uniform stripped `.cfoot` across all 4 harnesses (`claude`, `codex`, `agy`, `pi`).** Remove workspace folder, 5h/7d usage chips, and session cost (`~$USD`) from `.cfoot` across all harnesses (`BandView` / `r-sline` no longer emits folder, limits, or cost in the composer footer; top-bar `/rail/usage` owns plan quota visibility).
- **Codex 5h window promotion (`plan_usage_probe.go`, separate Codex history file) — (37)=a.** Accept the 5-hour window (`Seconds == 18000` / `Minutes == 300`) as `wslive.LimitFiveHour` (`"five_hour"`) alongside `seven_day` in `queryCodex` and `codexUsageEntry` (windows ordered `five_hour` then `seven_day`), so removing `.cfoot` usage loses zero Codex quota telemetry. The live window rides the existing `plan-usage.json` entry. Codex `five_hour` history samples persist in a **separate** `plan-usage-codex-history.json` (same sample shape, 14-day age limit, 5000-sample cap, and pruning as `plan-usage-history.json`), following `261119-feat-ws-agy-plan-usage-display` D12 (`plan-usage-agy-history.json`, `agyHistorySpec` in `plan_usage_agy.go`): its own `planUsageHistorySpec` and validator, its own memo, and a `/rail/usage?history=1` projection member emitted only when Codex five-hour samples exist, so Claude/Codex-only responses keep their current member set. The shared `validPlanUsageSample` and `plan-usage-history.json` stay unchanged; no Codex `five_hour` sample is ever written there.
  - *Rejected:* (b) not persisting Codex 5h history (loses pace parity with Claude 5h); (c) writing into `plan-usage-history.json` (an older build rejects the whole file — Decision 3).
- **22px slim borderless ghost tonal strip outside SSE-swapped `r-sline`.** Place the 2-button control strip (`.fpills` / `.fpill`, `min-height: 22px`, no resting border, subtle `--wb-wash` hover) inside `.cfoot` as a sibling *outside* `{{region . "sline"}}` so open popovers and keyboard focus survive SSE region swaps. Each trigger shows a `12px` monochrome Lucide SVG icon (`cpu` for Model, `gauge` for Effort, as in the mockup) + concise value + tiny chevron (`▾`), with no uppercase `MODEL`/`EFFORT` prefixes.
- **Two controls only: Model and Effort — (38), owner decision.** The strip carries exactly `Model` and `Effort`, uniform across all 4 harnesses (`claude`, `codex`, `agy`, `pi`), wired strictly through `dashboard-leads.js` `leadChoices` / `leadModels` / `leadEfforts` against `GET /support/choices` and `POST /agents/<id>/settings` (`model`, `effort`). The strip has no Permission control: no `leadModes`, no `permission_mode` / `permission_level`, no `POST /agents/<id>/settings/permission`. Permission selection stays in the existing top-bar session menu and with `261115-feat-ws-permission-profile`, whose unfinished common-level UI obligations (full warning and acknowledgement, preflight, intent/observation/enforcement display) are too entangled to carry in a footer strip now. The v2 mockup's third Permission trigger (and its Pi `shield-off` + `—` disabled variant) is an intentional delta, not a gap.
  - *Rejected:* a native-mode-only Permission slot with Pi disabled ((38)(a)); a common-level Permission slot adopting permission-profile's UI obligations ((38)(b)).
- **Child-agent preview & read-only enforcement.** Expose read-only settings metadata on `SessionView` (`IsChild`, immutable spawn `Model` and `Effort`, and `CanEditSettings`) and enforce `local && own` (`CanControl`) plus a child refusal on `POST /agents/<id>/settings` in `wsagent/http.go` (currently `leadControl` gates `settings` only when `r.IsLead(id)`). Live child pages (`/s/<child-id>`) and any subordinate shared composer shell (`261115-feat-ws-whiteboard-agent-card`) render both controls `disabled` with a `10px` `lock` icon in place of chevrons.
  - *Child predicate:* `isChild(rec) = rec.Parent != nil || cardBound(rec)`. `Record.Parent` (`wsagent/record.go`) is the `Runner.Spawn` turn-report parent, so it covers `agent.spawn` workers but is nil for dashboard/REST-opened conversations. Whiteboard card children are child *leads* that `261115-feat-ws-whiteboard-agent-card` Technical settlement 4 deliberately leaves with conversation `ParentRef` **unset** (to avoid `Runner.CloseConversation` cascading and turn-report parentage); their lineage is the actual key parent / active card binding. This ticket must not set `ParentRef` on card children to make the predicate match. Since the agent-card ticket has not landed, `cardBound` is a declared hook here (a single predicate function the guard and `SessionView.IsChild` both call, returning false until a card binding exists) that agent-card's Phase 2 fills from its active card binding or actual key parent. Because card bindings live in the `wsdashboard` store and `wsagent` cannot import `wsdashboard`, the hook is an injected func on the `wsagent` runner options (beside the existing `Trusted` func the HTTP gate already calls), nil-safe and defaulting to false, wired from `cmd/ws-mcp` / `wsdashboard`; a "non-lead" test would miss card children either way.
  - *Refusal layer:* the refusal sits in the HTTP route only (`wsagent/http.go` `serve`), answering `403` with a plain-text reason like the existing cross-origin refusal. `Runner.SetSettings` / `conv.setSettings` stay unguarded: support-drawer conversations are parentless non-lead `Runner.Create` conversations switched in-process through `Support.Select` → `Runner.SetSettings` (`wsagent/support.go`), never over HTTP, and must keep model/effort switching. `settings/permission` already refuses non-lead selection (`wsagent/permission.go`, permission-profile Phase 2a); this ticket adds no second permission guard.
- **Strip visibility by viewer and session kind.** The strip renders only on hosted session pages (the same `data-hosted` gating the session menu uses in `dashboard-leads.js`); external terminal and handed-off sessions omit it, and their meter falls back to the native window with no compaction ticks (no `UsageContext.Compaction`). A hosted lead viewed from a non-local origin (`CanControl == false` because `CanControl = st.Lead && local`, `wsagent/http.go`) renders both controls disabled with a distinct localized "controls are available on the host machine" tooltip, not the child "fixed at spawn" lock, so locks key on `IsChild`, not on `can_control`. Precedence: a child page always shows the child lock and "fixed at spawn" tooltip, whatever the viewer's origin; the host-machine tooltip applies only to non-child hosted pages viewed with `CanControl == false`.
- **Supersedes `261107-feat-ws-dashboard-status-band`'s `#r-sline` composition.** That ticket made `#r-sline` a size container carrying folder, `both`/`hi` limit chips (narrow-phone `.sb-use.both:not(.hi)` hide below 360px), and cost; this ticket removes those chips from the composer footer by owner decision, so its narrow-phone chip rule retires with them.
- *Rejected alternatives:* keeping Claude-only usage chips; placing triggers inside SSE-swapped `r-sline`; thick bordered capsule pills with uppercase prefixes.

### 2. Context Meter (`r-ctx`) & Hosted 1/3·2/3 Nudge Parity
- **Hosted 1/3 & 2/3 milestones (`wsagent/compaction.go`).** Port the intermediate milestones from `agents-plugin/hooks/claude-mod/timing.ts` (`thresholdsFor`, `levelAt`, `observe`; `agents-plugin/hooks/claude-mod/timing.ts#L90-L125`) and `agents-plugin-pi/src/goal-loop.ts` into `conv`: `m1 = advisory + (hard - advisory) / 3`, `m2 = advisory + 2 * (hard - advisory) / 3` whenever `c.compactAdvisoryEnabled` is true and `hard > advisory` (both finite). Latch each milestone per compaction epoch in memory on `conv`, re-arm on usage drop below the milestone (or live `refreshCompaction`), and reset on `wslive.CompactEnd`. Latch semantics follow the existing advisory/hard latches: `CompactStart` *latches* every milestone (as it does `compactAdvised`/`compactHardIssued`), `CompactEnd` clears them, a hard crossing latches m1 and m2 along with the advisory, and a milestone stays pending until its reminder is delivered at idle, with one delivery covering any lower thresholds crossed in the same jump (`timing.ts` `observe`).
- **No duplicate hosted plugin milestones.** Before the daemon emits milestones, a hosted Claude session must not also run claude-mod's advisory/milestone turns (gated today only by the advisory knob, `agents-plugin/hooks/claude-mod/register.ts`); verify the hosted suppression exists or add it via the existing `resolveHostedMode` gate, matching `261117-feat-ws-hosted-compaction-lifecycle`'s "no duplicate hosted plugin advisories" requirement (Pi suppression is already cited there).
- **Compaction metadata on `wslive.UsageContext`.** Add optional additive `Compaction *UsageCompaction` (`json:"compaction,omitempty"`) to `wslive.UsageContext` (`Soft int64 json:"soft,omitempty"`, `Hard int64 json:"hard,omitempty"`, `Milestones []int64 json:"milestones,omitempty"`, `AdvisoryEnabled bool json:"advisory_enabled,omitempty"`, all resolved absolute token counts; JSON cannot carry Inf, so an infinite or unresolved threshold is encoded as `0`/omitted, `Milestones` is empty unless both milestones are active, and the meter treats `Hard == 0` as "fall back to native window"), populated by `wsagent` from lead vs worker `compaction.{lead,worker}_{advisory,hard}` thresholds and preserved through `wslive.normalizeUsage`. `pageview_band.go` `contextBar` consumes it server-side.
- **Bar scaling & text format.** Scale bar width and percentage to `hard` (falling back to native `window` when `hard` is unset/infinite): `x% [ progress bar ] <current> / <hard> (<native>)` (e.g., `28% [...] 51,293 / 180K (1.0M)`). Omit `(<native>)` when `hard == native` or in narrow (`<= 360px` container / rail-hover compact, i.e. the existing `.shp .sb-ctx` scope in `dashboard-rail.css`; the mockup's `.is-compact` class is a stand-in for that scope, not a new class) views. Overflow (`current >= hard`) shows unclamped `x%`, `100%` clamped bar fill, and inverted `crit` badge. Unknown (no current token count yet, e.g. a hosted session before its first usage report, whether or not `Compaction` is present) shows `?` in place of `x%` and the current count, an empty bar, the ticks when `Compaction` is present, and no floating icon (mockup `renderGallery` "Unknown"; the existing `contextBar` no-usage path).
- **Dynamic ticks & floating boundary icon (no trailing status boxes).** Remove hardcoded `.t80`/`.t95` ticks and trailing `.sb-flag` rectangle badges (`high`, `near limit`). Render dynamic percentage tick markers (`m-soft`, `m-tick` for active 1/3 and 2/3) inside `.sb-bar` and float one `12px` crisp SVG icon directly above **only the most-recently-crossed boundary**: none below Soft -> amber `info` over Soft -> amber `bell` over 1/3 -> warm-orange `bell-ring` over 2/3 -> red `zap` right-aligned over Hard (`100%`). Rich hover/focus tooltip (`.ctx-tip`) displays Current / Soft / 1/3 / 2/3 / Hard / Native.
- *Rejected alternatives:* scaling against native 1M window; hardcoded 80%/95% ticks; ghost 1/3·2/3 ticks without hosted `wsagent` nudge parity; trailing `SOFT CROSSED` / `OVER HARD` rectangle badges.

### 3. Compatibility Tier: T0 Transparent
This change is **T0 transparent** under `ai-docs/manuals/release-compatibility.md`:
- `wslive.UsageContext` adds optional `omitempty` JSON fields; `wslive.ReadSnapshot` (`snapshot.go:429-441`) and `normalizeUsage` (`state.go:1335-1359`) ignore unknown fields and default absent ones without touching persisted schema version.
- `planUsageWindow` in the live cache `plan-usage.json` already accepts `five_hour` for any harness (`plan_usage.go` load validation), so the live Codex 5h window is T0.
- Codex `five_hour` history goes to the new `plan-usage-codex-history.json`, which older builds never open (T0, same argument as `261119-feat-ws-agy-plan-usage-display` D12); `plan-usage-history.json` stays byte-compatible. Writing those samples into `plan-usage-history.json` would not be T0: an older build's `parsePlanUsageHistoryWith` rejects the whole file on one sample failing `validPlanUsageSample` (`plan_usage_history.go:166-171`, rule at `:61`, pinned in `plan_usage_compat_test.go`), its history view then reports unavailable, and its append path stops to preserve the file (`:252-255`). The new `/rail/usage?history=1` member is additive and emitted only when Codex five-hour samples exist.
- `wsagent/http.go` keeps the existing `/agents/<id>/settings` vs `/agents/<id>/settings/permission` route split (`http.go:290-325`) and adds only the `local && own` gate and child refusal on `settings` writes; `settings/permission` is untouched.
- `SessionView` is server-rendered only (`pageview.go:45-120`), never persisted to disk.
