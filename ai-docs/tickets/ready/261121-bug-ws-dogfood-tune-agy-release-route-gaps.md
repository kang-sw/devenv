# Dogfood gaps: agy tune visibility, bound-child release safety, and merged impl branch identity

## Background

Three ws tool surprises were observed by the develop main lead during 2026-11-20/21 dogfooding. The observations below are distinguished from what this checkout's source verifies.

1. **Observed:** `config.tune` returned `unknown config key` for `agy.model_wait_retries`, prompting a manual global override. **Verified:** both package manifests declare that key (`agents-plugin/agy-config-manifest.json:13-17`, `agents-plugin-wsflow/agy-config-manifest.json:13-17`), and both Codex MCP declarations include the agy manifest alongside the Claude and dashboard manifests (`agents-plugin/.mcp.json:4-9`, `agents-plugin-wsflow/.mcp.json:4-12`). The server loads only paths in its process's `WS_MCP_CONFIG_MANIFESTS` at construction (`agents-plugin-tool/internal/mcp/config_manifest.go:18-26,106-129`; `agents-plugin-tool/internal/mcp/process_env.go:142-159`), adds only loaded keys to `config.list`, and rejects an undeclared key in `config.tune` (`agents-plugin-tool/internal/mcp/server_dispatch.go:388-415`). Thus the error proves the serving instance had not loaded that agy key; the source alone does not establish why the observed instance's manifest set differed from the package declarations. The original claim that the shipped catalog omits agy keys is incorrect. `claude.*` keys are declared in `agents-plugin/config-manifest.json:3-12`; no `codex.*` manifest key is declared in these two packages, so the observed comparison to tunable `codex.*` keys is unverified. **Expected:** a serving instance for either package exposes and tunes every declared agy key using its declared scope and validation, regardless of which harness first starts the shared daemon.
2. **Observed:** release cleaned a worktree while its child was still running. **Verified:** `agent.spawn(worktree: ...)` sets the child's root and cwd to that path (`agents-plugin-tool/internal/wsagent/agent_tools.go:669-708`). `worktree.release` resolves a path or worker key, then checks lease ownership unless forced (`agents-plugin-tool/internal/mcp/server_dispatch.go:903-933`; `agents-plugin-tool/internal/mcp/worktree_release_lock.go:87-97`). A matching lease authorizes the caller without checking child state (`agents-plugin-tool/internal/mcp/worktree_tools.go:778-787`); release then runs reset/clean and drops the lease (`agents-plugin-tool/internal/mcp/worktree_tools.go:840-901,659-682`). Existing `agent.list` data gives each child address, cwd, and state (`agents-plugin-tool/internal/wsagent/agent_tools.go:150-167,769-795`); `running`, `background`, `starting`, `idle`, and `waiting` are non-closed states (`agents-plugin-tool/internal/wsagent/agent_tools.go:201-227`). The runner also retains each conversation's root and status (`agents-plugin-tool/internal/wsagent/runner.go:1211-1233,1646-1660`). **Expected:** before hygiene, refuse a non-forced release while a non-closed bound child exists, and identify it; `force` remains the explicit override.
3. **Observed:** `git.resolve_impl_branch` suggested a previously merged branch name twice. **Verified:** ticket branch identity is deterministic from base and ticket stem (`agents-plugin-tool/internal/mcp/impl_identity.go:5-11`); `git.resolve_impl_branch` validates the resulting ref name but does not inspect its existence or merge state (`agents-plugin-tool/internal/mcp/impl_identity_tool.go:19-39`). `route.resolve_implement` likewise derives a ticket slug from the stem and observes the resulting target branch (`agents-plugin-tool/internal/mcp/implement_resolver.go:660-667`; `agents-plugin-tool/internal/mcp/session_state.go:1115-1124`). If that branch exists with zero commits ahead of its merge root, the route intentionally returns `recreate` with the *same* name; if unique commits remain, it stops (`agents-plugin-tool/internal/mcp/implement_resolver.go:529-543,866-889,1006-1021`). The original claim that the route directly calls `git.resolve_impl_branch`, or blindly suggests switching to an already-merged branch, is incorrect. **Expected:** per (1944)=a, the canonical name is kept; `worktree.acquire` and the route decide recreate-or-block, and `git.resolve_impl_branch` stays pure name resolution whose description says so (Decision 3).

## Decisions

1. **Agy config visibility — proposed fix:** make the shared daemon's catalog and tune validation include the package's agy manifest for each supported serving context, and test both package variants and a daemon started by another harness. Diagnose manifest rejection separately through the existing `config.list` manifest errors before changing manifest contents (`agents-plugin-tool/internal/mcp/server_dispatch.go:388-415`; `agents-plugin-tool/internal/mcp/config_manifest.go:106-129`). Reject blindly accepting arbitrary `agy.*` strings: it would bypass manifest type and bounds validation (`agents-plugin-tool/internal/mcp/config_manifest.go:223-284`). **T0 for old calls and persisted data, conditional on gating new calls:** the new server adds keys to unchanged `config.list`/`config.tune` shapes, while scalar values use the existing generic overrides map that older config readers parse (`agents-plugin-tool/internal/mcp/server_dispatch.go:388-417`; `agents-plugin-tool/internal/wsconfig/config.go:34-47`). A new caller sending an agy key to an old server without the declaration gets a pre-write refusal; that direction is T3 unless the caller checks `config.list` capability or requires an updated daemon (`agents-plugin-tool/internal/mcp/server_dispatch.go:411-417`; `ai-docs/manuals/release-compatibility.md`, Tools and Protocol Mapping). Reopening with the new server reads retained overrides; no new on-disk field is proposed. Verify the actual daemon startup path before implementation.
2. **Bound-child release guard — daemon-wide and atomic with spawn:** `worktree.release` refuses (unless `force`) while any non-closed child anywhere in the daemon — not only the caller's direct children — is bound to the target worktree, naming the child address. Two parts: (a) a daemon-wide runner query for non-closed conversations whose canonical root equals the worktree path (the runner already retains each conversation's root and status, `agents-plugin-tool/internal/wsagent/runner.go:1211-1233,1646-1660`; `AgentList` is scoped to direct children, `agents-plugin-tool/internal/wsagent/agent_tools.go:150-167,769-795`, so it is not sufficient); (b) one shared per-worktree admission boundary: `agent.spawn(worktree: ...)` takes the same worktree reservation that release holds (`agents-plugin-tool/internal/mcp/worktree_release_lock.go:62-97`) for its validate-and-bind step (`agents-plugin-tool/internal/wsagent/agent_tools.go:669-708`), so a spawn cannot slip in between release's check and its reset/clean. (c) the guard runs in the daemon, not in a connection-local MCP server: a release from a spawned agent's attached MCP server (which has no runner handle and today forwards only `agent.*` calls over its capability token) must reach the same daemon-side query, so the release path goes through an internal daemon query/forwarding seam rather than skipping the guard when no runner is local. This matters once ready ticket 261116-feat-ws-subagent-worktree-lease exposes `worktree.release` to workers. Regressions: a live direct child, a live nested (grandchild) child, a spawn racing a release on the same worktree, and a release issued from a token-bearing spawned-agent caller each block a non-forced release; `force` still releases. Rejected: checking only the lease worker key (the matching-lease path returns success without a child check, `agents-plugin-tool/internal/mcp/worktree_tools.go:778-787`); checking via `AgentList` (direct children only, and racy without the shared boundary). **T0:** `worktree.release` and `agent.spawn` arguments, the lease format, and stored state are unchanged; an old caller gets a refusal while a child is live, with no write. An old handler reads the same lease and can still release, so this is a forward safety fix, not a downgrade guarantee (`agents-plugin-tool/internal/mcp/server_dispatch.go:903-933`). No new state is written, so reopening needs no migration.
3. **Merged branch identity — keep the canonical name, recreate ((1944)=a, owner 2026-11-21):** a fully landed leftover keeps the deterministic ticket branch name and is deleted and recreated. Acquisition already does this since `eb40f685e` (merged with 261121-bug-ws-dogfood-context-routing-gaps), and the route returns `recreate` for it (`agents-plugin-tool/internal/mcp/implement_resolver.go:529-543,866-889`). `git.resolve_impl_branch` stays pure name resolution with its current text and JSON (`branch`, `merge_root`, `ticket_stem`) unchanged (`agents-plugin-tool/internal/mcp/impl_identity_tool.go:19-39`); the only change there is its tool description stating that it does not inspect whether the branch exists or has landed, and that `worktree.acquire` / the route decide recreate-or-block. `eb40f685e` already carries acquire regressions for a fully landed leftover (recreate) and an unlanded one (preserve/refuse); Phase 1 confirms they cover the reported flow and adds one only for a missing case. Rejected: adding a branch-state classification to `git.resolve_impl_branch` (a new output contract that callers could mistake for the acquisition decision, and it would duplicate the route's authoritative check); minting a fresh name per run ((1944) option b), which changes naming in both tools and breaks branch-to-ticket lookup. **T0:** no response-shape change; a tool-description edit refreshes the tool list only; neither tool writes a shared store.
