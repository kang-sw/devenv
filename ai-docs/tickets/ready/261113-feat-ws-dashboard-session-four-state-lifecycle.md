# Dashboard session list: four-state session lifecycle

## Background

Owner request (2026-11-13). The dashboard's left session list now dims processless hosted rows through RailRow.Stopped(), but does not yet expose the requested four-state lifecycle or a persisted hidden state (agents-plugin-tool/internal/wsdashboard/pageview_rail.go#L612-L624; agents-plugin-tool/internal/wsdashboard/rail_test.go#L1047-L1093; no hidden field in agents-plugin-tool/internal/wsagent/record.go or agents-plugin-tool/internal/wsdashboard/registry.go). The owner wants each session in the list to be in one of four states:

1. Active-on (켜짐) - visible; the session's process is running.
2. Active-off/asleep (잠듦) - visible; no process; the next message or mail wakes it.
3. Hidden/archived (보관) - no process; removed from the default list and available inside the left archived group; incoming mail does not wake it.
4. Pending deletion (삭제 대기) - the existing 7-day prune window.

Recorded as todo for later; the UI track (dashboard web frontend owner) is the expected implementer.

## Decisions

- The four states above, as the owner stated them (2026-11-13).
- (402) (owner, 2026-11-13): hidden sessions appear as a collapsed group with a count, refined by the owner: the current stopped-sessions slot splits into two halves, hidden sessions on the left and pending-deletion/stopped on the right. The two halves act as one tri-state radio: none expanded / hidden expanded / stopped expanded. Rejected: a filter toggle only.
- (403) (owner revision via MAIN 10:44:20, 2026-11-15): incoming message/mail does not wake a hidden/archived session; it remains archived with no process. This reverses the original 2026-11-13 mail/message-wake decision: the previously rejected alternative of remaining hidden with mail queued until unhide is now chosen. Rejected: treating archived sessions like visible asleep sessions. Passive incoming messages/mail remain distinct from the explicit own-page-input exception settled in (1120); do not infer wake behavior from the old decision.
- (404) The pending-deletion state is the existing age-based registry prune window: PruneRegistrations deletes eligible session directories, not just rows, when LastSeen (max of registered, heartbeat, ended) is older than RegistryRetention of 7 days; it exempts open runner records, Agent rows, unreadable runner records, and handed-off Pi conversations stored inside the directory (agents-plugin-tool/internal/wsdashboard/registry.go#L54-L56, agents-plugin-tool/internal/wsdashboard/registry.go#L221-L230, agents-plugin-tool/internal/wsdashboard/registry.go#L331-L436). The call is guarded by d.pruned at the first eligible dashboard registration, not unconditionally at process start (agents-plugin-tool/internal/mcp/dashboard_sessions.go#L299-L327). The pending-deletion row shows that window and stays recoverable until the prune removes it. Rejected: (a) manual-delete only - it would disable the existing automatic prune.
- (405) (technical mechanism explicitly revised by MAIN 10:44:49, 2026-11-15): persist hidden state in a separate dashboard-owned per-session sidecar under dashboard state, keyed by session id and written atomically, outside both agent.json and Registration. This replaces the original 2026-11-13 optional session-record field/T0 mechanism, not its restart-survival intent. Compatibility verdict: T1 display-degraded. Old v0.49 readers/writers address agent.json and registration.json, not the new sidecar; their ordinary rewrites leave its bytes intact, while the old rail can display the session normally (v0.49.1:agents-plugin-tool/internal/wsagent/record.go#L166-L210; v0.49.1:agents-plugin-tool/internal/wsdashboard/registry.go#L214-L254, v0.49.1:agents-plugin-tool/internal/wsdashboard/registry.go#L260-L308; v0.49.1:agents-plugin-tool/internal/wsdashboard/pageview_rail.go#L270-L273, v0.49.1:agents-plugin-tool/internal/wsdashboard/pageview_rail.go#L323-L335). A new reopen must read the retained sidecar to restore hidden state; this new reader/writer remains to be implemented and tested. This is retained-data display degradation, not T2 overwrite recovery or a promise that an old runtime enforces archive behavior. No disk T3 boundary or supported-version exclusion is approved. Rejected: the agent.json field candidate, because v0.49 drops unknown fields; Registration-only storage for the same loss risk; and display-only derived state, because it loses hidden state on restart.
- (1118)=a (owner via MAIN 10:44:20, 2026-11-15): expose hide/unhide only for dashboard-hosted leads. External terminal rows retain their existing ownership and controls. Rejected: adding an external process stop/restart contract in this slice.
- (1120) (explicitly settled by MAIN 10:48:07, 2026-11-15; "announced default, owner may override"): incoming mail remains queued while archived and is delivered after unhide. Direct input submitted on that archived session's own page explicitly unhides and starts it. This explicit page interaction is the exception to revised (403)'s passive incoming-message/mail no-wake rule. Manual unhide returns to visible asleep under settled (1117); queued mail can then wake it.

- (1117)=a (owner via MAIN 10:48:58, 2026-11-15): manual unhide returns the session to asleep (visible, no process). Queued mail or the next message then wakes it through the ordinary path; manual visibility restoration alone does not launch an empty interaction. Rejected: an unconditional process launch on manual unhide.

- (1125)=b (owner via MAIN, 2026-11-15T10:58:49Z): mockup first. MAIN's Claude agent owns the mockup and later approved visual implementation. This worker completes only separable backend Phase 1: atomic T1 sidecar, non-visual lifecycle derivation/data paths, archive no-wake/queued delivery, own-page direct-message exception, manual-unhide asleep and focused Go tests. ## Verified Implementation Evidence

- Current rail classification splits Sessions/Ended by Live, while Stopped is a separate processless-hosted presentation predicate. The ended disclosure is `rsessions` / `.rended`, not a hidden-session control (agents-plugin-tool/internal/wsdashboard/pageview_rail.go#L391-L411, agents-plugin-tool/internal/wsdashboard/pageview_rail.go#L612-L624; agents-plugin-tool/internal/wsdashboard/assets/dashboard.tmpl#L388-L393). Do not equate heartbeat liveness with process presence.
- Runner.Stop only stops the process and retains held messages. CloseConversation closes the lifetime; close stamps ClosedAt, drops held input and stops watching. Reopen explicitly clears ClosedAt and resumes on subsequent input/mail (agents-plugin-tool/internal/wsagent/runner.go#L912-L919, agents-plugin-tool/internal/wsagent/runner.go#L981-L1008, agents-plugin-tool/internal/wsagent/runner.go#L3309-L3331; agents-plugin-tool/internal/wsagent/handoff.go#L231-L290). Thus today's Stop is active-off, not itself a pending-deletion transition; closed hosted rows are eligible for age-based pruning. Keep the historical wording in the four-state request distinct from these current mechanisms.
- Existing message and mail delivery converge on kick, which starts a missing process when input exists, subject to replay/holder guards; mailChanged refuses closed conversations (agents-plugin-tool/internal/wsagent/runner.go#L855-L890, agents-plugin-tool/internal/wsagent/runner.go#L1438-L1477, agents-plugin-tool/internal/wsagent/runner.go#L1901-L1930).
