# Teach supported reviewer wrappers to bounded delegates

## Background

Bounded `delegate-implementer` workers attempted independent review with `ws/playbook.render(name: "code-reviewer")`. The observed refusals were `ws-pi-agent: delegated playbook lacks trusted shipped provenance` and `ws-pi-agent: nested spawn requires trusted render provenance`. The owner1089 implementation repeated this at commit `3083d8037`; a lead-rendered reviewer subsequently ran. These are reported runtime observations, not a replay proving an adapter defect.

Source establishes that `code-reviewer.md` is a shared include, intentionally not a delegated render target. Structured reviewer wrappers are the supported path. Ticket-worker guidance already supplies the mapping, but the bounded delegate floor and Pi Lead Guide do not name it. The worker lifecycle text already supplies the exact findings-file grant instruction. Missing wrapper guidance does not conclusively establish why a particular caller chose the include (mapping: agents-plugin-pi/rsrc/ticket-worker/ticket-worker.md#L81-L88; existing grant instruction: agents-plugin-pi/src/spawner.ts#L3753).

Grounded implementation paths and reuse points:

- Canonical floor: `agents-plugin/rsrc/delegate-implementer/delegate-implementer.md`; byte-identical current copies: `agents-plugin-wsflow/rsrc/delegate-implementer/delegate-implementer.md` and `agents-plugin-pi/rsrc/delegate-implementer/delegate-implementer.md`. Lines 7–10 make the lead's assignment governing; the floor currently contains no review dispatch section. `agents-plugin-pi/pi-lead-guide.md#L33` and `#L59-L64` teach generic spawn and worker-owned rendering, without reviewer-wrapper selection. Add conditional mapping, not an allocation rule or a second copy of the existing grant instruction.
- Resource manifests: `agents-plugin/rsrc/manifest.json`, `agents-plugin-wsflow/rsrc/manifest.json`, `agents-plugin-pi/rsrc/manifest.json`. Existing drift guards are `TestWsflowRsrcMirrorUpToDate` in `agents-plugin-tool/internal/wsrsrc/wsflow_mirror_test.go` and `TestPiMirrorUpToDate` in `agents-plugin-tool/internal/wsrsrc/pi_mirror_test.go#L20-L82`; Pi's tree is hand-synced, not generated by the wsflow regeneration test.
- Existing rendered-text test reuse: `agents-plugin-tool/internal/mcp/playbook_render_plan_test.go#L51-L91` renders the real delegate floor in ws/wsflow modes; `agents-plugin-tool/internal/mcp/lead_delegate_test.go#L10-L84` pins the lead's delegation contract; `agents-plugin-tool/internal/mcp/playbook_tools_test.go#L2563-L2604` already pins ticket-worker wrapper mapping and conditional allocation. These are extension points, not claims that bounded-delegate mapping coverage exists today.
- Existing Pi coverage: `agents-plugin-pi/test/spawner.test.ts#L1737-L1743` checks lifecycle-guide prose; `agents-plugin-pi/test/reviewer-artifact.integration.test.ts#L67-L175` pins exact-file grants, supported wrapper admission and flat-include rejection. No dedicated Pi Lead Guide reviewer-mapping assertion was found (`grep 'delegate-implementer|pi-lead-guide|Worker subtrees' agents-plugin-pi/test` finds guide-copy fixtures, not mapping assertions). Tests were read, not run; admission expectations remain unchanged.

## Decisions

- MAIN confirmed this scope on 2026-11-15 at 09:57:48Z: teach and pin the existing supported mapping in `delegate-implementer` and the Pi Lead Guide, with regression coverage. Implement after ready promotion with a Pi worker.
- When an assignment requires independent review, render `reviewer` for a single full-scope reviewer, or `code-review-correctness`, `code-review-fit`, and `code-review-test` for the selected partitions. Never render the flat `code-reviewer` include as a delegated role.
- Preserve `260915-bug-ws-pi-delegated-render-provenance-breaks-review`. Adapter admission, provenance registration, capability/depth ceilings and exact findings-file grants remain unchanged. Reject accepting the include or bypassing admission: the existing refusal is correct.
- This is dispatch guidance, not a requirement to add independent review to assignments that do not require it. Preserve the bounded delegate floor's existing relationship to the lead's assignment.

## Reproduction

1. A lead renders `delegate-implementer` and gives a bounded Pi worker an assignment requiring one independent review.
2. The worker selects `code-reviewer` rather than a structured wrapper.
3. Rendering is refused with `ws-pi-agent: delegated playbook lacks trusted shipped provenance`; a nested spawn without registered provenance is refused with `ws-pi-agent: nested spawn requires trusted render provenance`.
4. Correct dispatch uses the existing structured wrapper and the existing exact findings-file grant. A successful root-owned spawn alone is not proof of nested provenance.
