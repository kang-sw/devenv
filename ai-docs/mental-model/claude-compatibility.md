# Claude Compatibility

## Entry Points

- Root `CLAUDE.md` is a compatibility shim whose body is `@AGENTS.md`. {#260505-claude-root-compatibility-shim}
- `claude-plugin/` is retired; do not reintroduce it as a live fallback or mirror target. {#260510-claude-plugin-retirement-freeze}
- `agents-plugin/.claude-plugin/plugin.json` is the Claude-facing compatibility manifest for the active plugin package. {#260505-claude-plugin-manifest-marketplace}
- `agents-plugin-wsflow/.claude-plugin/plugin.json` is the Claude-facing compatibility manifest for the agentless derivative package and must use package-local no-agent MCP environment. {#260513-wsflow-claude-compatible-package}
- `install.sh update` refreshes the installed `agents-plugin/` and `agents-plugin-wsflow/` snapshots plus shared marketplace metadata. {#260505-claude-install-update-snapshot} {#260513-wsflow-installer-snapshot}

## Module Contracts

- Shared workflow semantics belong in `AGENTS.md`; Claude-only files are compatibility adapters.
- The installed Claude-compatible plugin is a snapshot of `agents-plugin/` under the user's Claude plugin cache.
- Claude bootstrap has its own `WORKFLOW.md` mirror and installs `ai-docs/WORKFLOW.md`, but the copied guide is only a plugin-less maintenance fallback; it must not become a Claude-specific authority over ws runtime or parser behavior. {#260506-bootstrap-workflow-guide}
- Former global Claude home instructions are historical reference material at `ai-docs/ref/claude-home-legacy.md`; `install.sh` no longer links them. {#260505-claude-global-home-instructions}

## Coupling

- Bootstrap has a compatibility boundary: downstream Claude shims should point at host-neutral `AGENTS.md`, while legacy Claude bootstrap remains a fallback reference. {#260505-downstream-claude-bootstrap-shim}
- Versioned bootstrap migrations after the host-neutral cutover must update canonical `AGENTS.md` and keep `CLAUDE.md` as the `@AGENTS.md` shim; adding guide pointers to the shim would silently undo the compatibility boundary.
- Marketplace identity and installed plugin paths are generated by installer logic around the `agents-plugin/` and `agents-plugin-wsflow/` Claude compatibility manifests. {#260505-claude-plugin-manifest-marketplace} {#260513-wsflow-installer-snapshot}

## Extension Points & Change Recipes

- **Change Claude-compatible plugin metadata**: edit `agents-plugin/.claude-plugin/plugin.json`, then validate the plugin package.
- **Change wsflow Claude metadata**: edit `agents-plugin-wsflow/.claude-plugin/plugin.json`, keep the no-agent MCP environment aligned with `.mcp.json`, and validate the wsflow package.
- **Change Claude local installer registration**: update `install.sh` so the marketplace snapshot, enabled plugin list, stale installed-plugin repair, and manual fallback messages stay aligned for every local plugin. {#260513-wsflow-installer-snapshot}
- **Change home-level Claude guidance**: update root `AGENTS.md`; do not revive installer-managed global Claude instructions. {#260505-claude-global-home-instructions}

## Common Mistakes

- Reintroducing a separate `claude-plugin/` source tree.
- Mentioning `ws-*` shell helpers in shared Codex skill guidance instead of MCP primitives.
- Updating only the full ws Claude manifest when copied launcher or no-agent metadata also affects `agents-plugin-wsflow/.claude-plugin/plugin.json`.

## Technical Debt

- Runtime Claude invocation of `agents-plugin/` remains manual closeout beyond manifest validation.
