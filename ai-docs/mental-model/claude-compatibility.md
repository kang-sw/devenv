# Claude Compatibility

## Entry Points

- Root `CLAUDE.md` is a compatibility shim whose body is `@AGENTS.md`. {#260505-claude-root-compatibility-shim}
- `claude-plugin/` is the stable Claude package and legacy fallback reference. {#260505-claude-plugin-compatibility-package}
- `claude-plugin/bin/*` contains CLI fallback tools still used by Claude workflows. {#260505-claude-ws-cli-fallback-suite}
- `install.sh update` refreshes the installed Claude plugin snapshot and marketplace metadata. {#260505-claude-install-update-snapshot}

## Module Contracts

- Shared workflow semantics belong in `AGENTS.md`; Claude-only files are compatibility adapters.
- The installed Claude plugin is a snapshot under the user's Claude plugin cache; live edits under `claude-plugin/` require update/install before Claude sees them.
- Every new `claude-plugin/bin/` script needs a Windows-compatible `.cmd` shim. {#260505-claude-bin-windows-shims}
- Legacy named-agent CLI state is Git-repo scoped and backend-specific. {#260505-claude-named-agent-cli-runtime}

## Coupling

- Bootstrap has a compatibility boundary: downstream Claude shims should point at host-neutral `AGENTS.md`, while legacy Claude bootstrap remains a fallback reference. {#260505-downstream-claude-bootstrap-shim}
- CLI fallback behavior duplicates some documentation parsing; infra/project-tree/spec parsing changes should check both fallback scripts and bundled convention/docs behavior.
- API docs CLI fallback is `ws-ask-api` / `ws-ask-api-internal` and uses the `ai-docs/.deps/` cache. {#260505-claude-api-docs-cli-fallback}
- Marketplace identity and installed plugin paths are generated by installer logic around the Claude plugin manifest. {#260505-claude-plugin-manifest-marketplace}

## Extension Points & Change Recipes

- **Add a Claude fallback command**: add the script, add `.cmd`, update installer/snapshot assumptions if needed, and decide whether MCP parity is required.
- **Change compatibility skill semantics**: check the shared workflow rule it adapts and explicitly document why behavior differs by host.
- **Change home-level Claude instructions**: edit `claude-plugin/CLAUDE.home.md`, not generated installed files. {#260505-claude-global-home-instructions}

## Common Mistakes

- Editing `claude-plugin/` and expecting Claude to reload live source without refreshing the snapshot.
- Adding Unix-only bin scripts.
- Mentioning `ws-*` shell helpers in shared Codex skill guidance instead of MCP primitives.

## Technical Debt

- Legacy CLI Codex JSONL parsing exists for compatibility fallback behavior.
- Gemini backend exists in legacy CLI as scaffolded unsupported behavior.
