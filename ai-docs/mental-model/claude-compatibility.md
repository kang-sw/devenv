# Claude Compatibility

## Entry Points

- Root `CLAUDE.md` is a compatibility shim whose body is `@AGENTS.md`. {#260505-claude-root-compatibility-shim}
- `claude-plugin/` is frozen legacy fallback, not an active mirror target for Codex workflow changes. {#260510-claude-plugin-retirement-freeze}
- `claude-plugin/bin/*` contains CLI fallback tools still used by Claude workflows. {#260505-claude-ws-cli-fallback-suite}
- `install.sh update` refreshes the installed Claude plugin snapshot and marketplace metadata. {#260505-claude-install-update-snapshot}

## Module Contracts

- Shared workflow semantics belong in `AGENTS.md`; Claude-only files are compatibility adapters.
- The installed Claude plugin is a snapshot under the user's Claude plugin cache; edit `claude-plugin/` only for explicit Claude compatibility or retirement work.
- Claude bootstrap has its own `WORKFLOW.md` mirror and installs `ai-docs/WORKFLOW.md`, but the copied guide is only a plugin-less maintenance fallback; it must not become a Claude-specific authority over ws runtime or parser behavior. {#260506-bootstrap-workflow-guide}
- Explicit compatibility-ticket edits under `claude-plugin/bin/` need Windows-compatible `.cmd` shims. {#260505-claude-bin-windows-shims}
- Legacy named-agent CLI state is Git-repo scoped and backend-specific. {#260505-claude-named-agent-cli-runtime}

## Coupling

- Bootstrap has a compatibility boundary: downstream Claude shims should point at host-neutral `AGENTS.md`, while legacy Claude bootstrap remains a fallback reference. {#260505-downstream-claude-bootstrap-shim}
- Versioned bootstrap migrations after the host-neutral cutover must update canonical `AGENTS.md` and keep `CLAUDE.md` as the `@AGENTS.md` shim; adding guide pointers to the shim would silently undo the compatibility boundary.
- CLI fallback behavior duplicates some documentation parsing; change fallback scripts only when a ticket explicitly keeps Claude behavior in scope.
- API docs CLI fallback is `ws-ask-api` / `ws-ask-api-internal` and uses the `ai-docs/.deps/` cache. {#260505-claude-api-docs-cli-fallback}
- Marketplace identity and installed plugin paths are generated by installer logic around the Claude plugin manifest. {#260505-claude-plugin-manifest-marketplace}

## Extension Points & Change Recipes

- **Add a Claude fallback command**: add the script, add `.cmd`, update installer/snapshot assumptions if needed, and decide whether MCP parity is required.
- **Change compatibility skill semantics**: require an explicit Claude compatibility or retirement ticket before editing frozen fallback skills.
- **Change home-level Claude instructions**: require an explicit compatibility ticket, then edit `claude-plugin/CLAUDE.home.md`, not generated installed files. {#260505-claude-global-home-instructions}

## Common Mistakes

- Mirroring Codex workflow changes into `claude-plugin/` without an explicit compatibility or retirement ticket.
- Adding Unix-only bin scripts.
- Mentioning `ws-*` shell helpers in shared Codex skill guidance instead of MCP primitives.

## Technical Debt

- Legacy CLI Codex JSONL parsing exists for compatibility fallback behavior.
- Gemini backend exists in legacy CLI as scaffolded unsupported behavior.
