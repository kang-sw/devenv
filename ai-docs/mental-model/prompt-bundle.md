# Prompt Bundle

## Entry Points

- `wsagent.Manager.Register` materializes each agent's `system.md` from the auto-prepended `delegate-orientation` doc (loaded from rsrc unless `SuppressOrientation`) joined with the caller's self-contained `SystemPromptText`. The former embedded prompt-stem chain (`Prompts`/`PromptRefs`/`ConditionalPromptRefs`) was removed in 260611 Phase 6b. {#260505-agent-prompt-registration-tier-resolution}
- `wsdoc.ReadInfra` (backing the `infra.read` MCP tool) loads infra docs from the rsrc tree by bare stem via `wsrsrc.Load`, rejecting path-escaping names (260611 Phase 6b moved this off `wsprompt.ReadInfra`).
- `runtime.info` / `runtime.capabilities` report version + source commit only; prompt bundle metadata was removed with the embedded bundle (260611 Phase 6b), so neither the runtime contract nor the launcher validates a prompt bundle hash. {#260609-playbook-tools}
- `wsrsrc.Load` loads a named playbook from the filesystem rsrc tree (`agents-plugin/rsrc/`): validates manifest schema-version, verifies per-file hashes, applies harness overlay, resolves playbook-local includes before root-level flat fallbacks, and substitutes declared variables. `PlaybookMeta` now includes a `Role` field parsed from `role:` frontmatter (values: `lead`, `implementer`, `reviewer`, `delegate`, `leaf`; empty when absent) and a `Tier` field parsed from `tier:` frontmatter (first-class capability tier `small`/`medium`/`large`/`xlarge`; empty when absent). Phase 2 (260611) routes that tier: `playbook.render`/`print` return it as a `recommended-tier` line (via `withRecommendedTier`) and `ws.mercenary.register` passes it through (now in the capability vocabulary directly — the `firstClassTierToAlias` bridge was retired by `#260620-tier-vocabulary-collapse-direct-model-map`) so a mercenary's model follows the playbook frontmatter tier instead of defaulting to the `medium` tier. The shipped tree now carries delegate playbooks `implementer/` (`role: implementer`, `tier: medium`, uses `{{.RoleModel}}`) and `reviewer/` (`role: reviewer`, `tier: large`, uses `{{.RoleModel}}`); the tier lives only in frontmatter (the body no longer hardcodes a tier literal), so the render-minted child-key splice and the tier-derived model-hint var are reachable on a real shipped asset (not only in-memory fixtures). Phase 4 (260611) completed the shipped delegate set: the three `code-review-correctness/fit/test` partitions (`role: reviewer`; correctness `tier: large`, fit/test `tier: medium`) plus `reference-discovery` (`tier: small`), `mental-model-updater` and `plan-populator-survey` (`tier: medium`), and `plan-populator-research` (`tier: large`), all `role: delegate`. MCP tools: `playbook.print` returns rendered text inline; `playbook.render` writes to a worktree-scoped tmp file (via `GeneratePaths("prompt")`) and returns the path. Both append the `recommended-tier` line when the playbook declares a tier. {#260609-rsrc-playbook-distribution} {#260609-playbook-tools}

## Module Contracts

- **The rsrc tree (`wsrsrc`, filesystem `agents-plugin/rsrc/`) is the single prompt source of truth.** 260611 Phases 4–6b converged active prompt consumers onto it — delegate playbooks, `infra.read`'s docs, and the `delegate-orientation` auto-prepend — then deleted the `wsprompt` go:embed loader entirely. The retired `api.ask` prompt stems were removed with the agent-backed API ask path, and the retired wsflow `prompt.render` tool was removed after `playbook.render` absorbed its legacy five-stem context bridge. There is no longer a second embedded prompt loader; the historical "deliberately parallel, non-overlapping loaders" rule is gone. Prompts/infra docs/playbooks are all plain files under the rsrc tree, manifest-checked at load time, and changing them needs only a `manifest.json` regen (no binary bump or `runtime.json` refresh).
- rsrc compatibility is gated on `manifest.schema_version` alone — not content-hash equality. Text-only edits to rsrc files ship without a binary bump as long as `SupportedSchemaVersion` is unchanged; increment it only when the playbook schema shape changes.
- rsrc failure is always loud: `ErrManifestMissing`, `ErrSchemaMismatch`, `ErrHashMismatch`, `ErrFileMissing`, and `ErrPlaybookNotFound` are returned as typed errors with no embedded fallback. `ErrPlaybookNotFound` is for a requested top-level playbook stem absent from both manifest and disk; `ErrFileMissing` remains the integrity signal for manifest-listed files missing from disk or disk files missing from the manifest. Per-file sha256 hashes in `manifest.json` are tree-integrity checks, not binary-coupling.
- rsrc variable substitution is declared-only in `wsrsrc.Load`: a key in `vars` absent from `variables:` frontmatter → `ErrUndeclaredVar`; a declared variable whose `{{.Name}}` appears in the body but is absent from `vars` → `ErrUnprovidedVar`; declared variables not used in the body are silently ignored. The rsrc format also has implicit namespace variables (`McpNamespace`, `SkillNamespace`) that validation allows without frontmatter declarations; their values are owned by the MCP playbook layer, not `wsrsrc.Load`.
- `playbook.print` / `playbook.render` call `wsrsrc.Load` once with nil vars so manifest, overlay, and include behavior stays in `wsrsrc`; the MCP playbook layer then substitutes declared playbook vars plus implicit namespace vars. This is the deliberate boundary for product-mode namespace values, which depend on runtime environment rather than resource frontmatter. {#260609-playbook-tools}
- `PlaybookMeta.Role` determines child-key eligibility for `playbook.render`: `implementer`/`reviewer`/`delegate` map to `roleDelegate`; `leaf` maps to `roleLeaf`; `lead` or absent → no mint. Minting occurs only when the caller's `session_key` is lead-scoped; non-lead callers and unrecognized roles never produce a child key. The minted child key is spliced as a delimited credential block at the start of the rendered body so the delegate's ws calls are pre-keyed. `root_override`, when provided, rebinds both the auto-include resolution root and the child-key binding root. {#260610-mercenary-delegation-surface}
- Every `delegates:true` rendering appends a continuity tip (in `delegationTip`) that is safe for both full ws and wsflow. In full ws mode, the tip also includes the mercenary path, noting that `ws.mercenary.call` is reachable on request with the embedded `session_key` and a prompt from `playbook.render`; in no-agent/wsflow mode, mercenary text is omitted. `playbook.render` reads the global-only `"workflow.prefer_mercenary"` item; only value `on` makes implementer and reviewer renderings receive the mercenary-primary guidance block (from `mercenaryGuidanceBlock`). Product-mode selection removes that full-ws-only block in wsflow. {#260610-mercenary-delegation-surface} {#260513-wsflow-agentless-runtime-mode}
- Playbook rendering merges vars in four layers (later wins): caller context → terminology table → model aliases → namespace vars. Terminology and model alias vars are applied only when declared in the playbook; namespace vars are implicit, available to every playbook, and override caller context so product namespace output cannot be spoofed. Caller-supplied keys outside declared vars plus implicit namespace vars surface `ErrUndeclaredVar` before substitution. {#260609-playbook-harness-rendering}
- Harness terminology is a static bundled table (claude/codex/neutral); `terminologyForHarness("")` returns the neutral row for any unrecognized harness. The tier-derived model-hint var (`RoleModel`) resolves from wsconfig at call time from the playbook's own `tier:` — never bundled in `agents-plugin/rsrc/`. Structural per-harness divergence uses harness overlay files. {#260609-playbook-harness-rendering}
- Product-mode selection is marker-based and runs in the playbook tool layer: `<!-- ws:full-only:start/end -->` blocks are emitted only outside no-agent mode, `<!-- ws:wsflow-only:start/end -->` blocks are emitted only in no-agent mode, and marker comments are stripped from every rendered output. Playbook namespace output is explicit: shared rsrc text uses `{{.McpNamespace}}` for MCP notation such as `ws/tickets.find` and `{{.SkillNamespace}}` for skill notation such as `ws:lead-discuss`; actual tool identifiers such as `ws.ferrule` remain literal unless intentionally modeled separately. {#260513-wsflow-agentless-runtime-mode} {#260609-playbook-tools}
- **Override-marker pass** (`applyOverrideMarkers`) runs in `renderPlaybookBody` **before** `selectProductModeBlocks`, so both full-only and wsflow-only sections see override substitution before product-mode stripping. Markers have the form `<!-- ws:override:<pointId> desc="..." --> ... <!-- ws:/override:<pointId> -->`. Resolution order per point: `prompt.<pointId>.<harness>` in the layered config → `prompt.<pointId>.all` (cross-harness bucket) → inline seed body. Marker lines are always stripped from output regardless of whether the override is stored. An empty seed body (open marker immediately followed by close) is an extension slot that renders the stored override or nothing. Nested override blocks inside a seed are processed recursively so no inner marker line survives. An unclosed open marker (no matching close before EOF) is NOT treated as a block — its line is emitted unchanged so no playbook content is consumed. `buildOverrideLookup(s, sessionKey)` is the single construction site shared by both `playbook.print` and `playbook.render` dispatch paths; keyless renders use only code-owned builtin prompt defaults, while user/project/global prompt overrides require a non-empty `session_key`. The `config.prompt.set(pointId, harness, prompt, scope?)` setter is **implemented** (Phase 1): lead-only via the existing `config.*` prefix gate, writes through the layered config resolver under key `prompt.<pointId>.<harness>` (`*`→`all` bucket), default scope is project for unregistered `prompt.*` keys, session-scope writes require `session_key`, and the tool is visible in both full-ws and wsflow (mode-neutral). The `config.prompt()` listing is **implemented** (Phase 2): a read-only no-arg tool where `scanOverridePoints` tree-scans the rsrc `.md` files for declared open markers (deduped by pointId, first non-empty `desc` wins, sorted) and reports each point's id + `desc` + any current override values per harness bucket/resolved scope via `resolver.Get`, ending with a one-line `ws:lead-tune` pointer. It mirrors `config.show` (optional `session_key`; session-scope values shown only when supplied; keyless caller passes the `config.*` gate), is keyed on declared markers (orphan `prompt.*` values are not surfaced), and is registered in both `runtime.json` files to satisfy the launcher-contract exact-equality test. Shipped `lead-workflow-manual` now keeps only empty-slot `UserPreferenceSection` for standing preferences; `DelegationSection` is removed, so `config.prompt`/`config.tuning` omit it and orphan `prompt.DelegationSection.*` values remain ignored. {#260619-prompt-override-marker-engine} {#260619-delegation-section-override-point}
- Builtin prompt override defaults are reserved for shipped harness feature-surface splits that should resolve as `prompt.<pointId>.<harness>` values without copying harness-only text into shared rsrc seeds. Current use: the generic `prompt.PreferSubagentInvocationGuidance.codex` default fills an empty `lead-prefer-subagent` slot with Codex `spawn_agent(fork_context:true, ...)` invocation guidance while Claude renders the empty shared seed. {#260619-prompt-override-marker-engine}
- `playbook.print` has one code-side pragmatic concatenation hook: when the rendered playbook is `lead-workflow-manual` and global `"workflow.prefer_subagent"` resolves to `on`, it renders `lead-prefer-subagent` through `renderPlaybookBody` with the same override lookup, harness defaults, and product-mode filtering, then appends it as `<playbook name="lead-prefer-subagent" title="Prefer Subagent">...</playbook>`. This is not source-template syntax; standalone `playbook.print`/`playbook.render` for `lead-prefer-subagent` remain Markdown, and explicit invocation may duplicate the short posture. {#260609-playbook-tools} {#260505-workflow-primitive-reference}
- `config.tuning()` is the read-only lead-tune catalog. Prompt knobs reuse the same `scanOverridePoints` marker scan and `buildPromptOverrideListing` current-value shape as `config.prompt`; non-prompt knobs derive field metadata from their existing writer tool schemas, so enum/property drift belongs in the writer schema, not in `lead-tune` prose. Workflow preference knobs use `workflow.prefer_subagent` / `config.workflow_prefer_subagent` and `workflow.prefer_mercenary` / `config.workflow_prefer_mercenary`; because those items are global-only, their current values are read from global/builtin state rather than the caller's session key. In wsflow/no-agent mode the catalog remains visible but omits full-ws-only knobs such as `workflow.prefer_mercenary` and `agents.tier`, while keeping `workflow.prefer_subagent`. {#260625-tuning-catalog}
- wsflow `playbook.render` has a legacy prompt-render bridge: in no-agent mode,
  when `name` is one of `reference-discovery`, `plan-populator-survey`,
  `plan-populator-research`, `code-reviewer`, or `mental-model-updater`,
  caller `context` is appended as a sorted free-text `## Render Context` block
  instead of being treated as template variables. The bridge does not apply to
  `implementer`, arbitrary playbooks, or full ws mode, where undeclared
  `context` keys still raise `ErrUndeclaredVar`. {#260609-playbook-tools}
- rsrc includes are bare stems that resolve in order: `<root>/<playbook>/<include>.<harness>.md`, `<root>/<playbook>/<include>.md`, then `<root>/<include>.md`. Include fragments are appended to the parent playbook body before variable substitution and are not standalone playbook variants.
- rsrc playbooks resolve to `<root>/<name>/<name>.md` (subdir); when that base file is absent, `Load` falls back to a flat `<root>/<name>.md` (260611 Phase 6, `resolvePlaybookPath`), so a var-free flat dep like `code-reviewer` (which also serves as a flat include target) is loadable as a playbook in its own right. Subdir always wins; the fallback only fires when the subdir base is absent.
- Agent registration takes one self-contained `SystemPromptText` (the caller renders it via `playbook.render`); the runtime joins the orientation doc and that text with a `\n\n---\n\n` separator and writes the result to `system.md`. There is no multi-prompt chain or per-prompt frontmatter concatenation any more.
- Model selection at registration is unchanged by the bundle retirement: `model` may name a `light`/`core`/`deep` alias (read-compat) or a concrete backend model; the `tier` input takes the capability vocabulary; with no `model`/`tier` set, registration defaults to the `medium` tier before harness-aware backend/model resolution. (The removed path also previously derived a tier from the first embedded prompt's `model:` frontmatter — that source no longer exists; tier now flows through the `tier` register arg, a render pass-through of frontmatter.)
- Public named agents get `delegate-orientation` prepended unless suppressed; the document is loaded from the rsrc tree (`loadDelegateOrientation`), and `agent.PromptRefs` records `["delegate-orientation"]` when it is applied. {#260505-workflow-delegate-prompt-boundaries}
- `infra.read` resolves docs from the rsrc tree by bare stem; path-escaping names (`/`, `\`, `..`) are rejected before the load.

## Coupling

- Editing rsrc text (`agents-plugin/rsrc/`) requires no `runtime.json` refresh; regenerate `manifest.json` via `wsrsrc.GenerateManifest` (and the wsflow mirror) instead. There is no prompt bundle hash to keep in sync (retired 260611 Phase 6b).
- Prompt/infra/playbook text, filenames, additions, deletions, and moves change only `manifest.json` (regenerate via `wsrsrc.GenerateManifest`); they do NOT touch `runtime.json` or any binary-compatibility hash. The prompt bundle hash and its `runtime.json`/launcher validation were retired in 260611 Phase 6b, so prompt edits never require a binary bump.
- Shipped skills name rsrc delegate playbooks (resolved by `wsrsrc`, manifest-checked). The former API-doc prompt stems (`pre-router`, `api-doc-manager`, `api-doc-cargo-brief`) and `renderAPIPrompt` caller were removed with `api.ask`, so they are no longer valid rename targets.
- wsflow distributed lead skills are now thin `wsflow/playbook.print` shims over the same rsrc lead playbooks; adding, removing, or renaming a shipped wsflow skill requires both the package-local shim and a matching shared playbook stem.
- The rsrc delegate playbooks are the canonical bundled-delegate surface: full-ws workflow skills render them via `ws/playbook.print`/`ws/playbook.render` to hand a worker a self-contained prompt (Phase 5, 260611, migrated every delegate off `register(prompts:[stems])`). The `implementer`/`reviewer`/`reference-discovery`/`mental-model-updater`/`plan-populator-*` playbooks are rendered, not registered by stem. `explore` (`agents-plugin/rsrc/explore/explore.md`, `kind:render`, `delegates:true`) remains in the rsrc tree as a compatibility/fallback playbook for unknown or unsupported harness contexts; shipped skill guidance now dispatches host-native exploration workers directly, so changing `explore` should be treated as fallback-surface work rather than the normal scoped-fact-finding path.
- The legacy `skeleton-populator`/`skeleton-reviewer`/`sprint-survey` stems were confirmed dead and deleted with the `wsprompt` package (260611 Phase 6b); they are no longer bundled or registrable.
- `reference-discovery` (renamed from `project-survey`) and `plan-populator-survey` cover different axes and are frequently conflated by callers: `reference-discovery` is a `small`-tier, docs-only agent that returns a `[Must|Maybe]` list of spec/mental-model/ticket docs and never reads source; `plan-populator-survey` is a `medium`-tier agent that reads source and writes a file-backed source reference map. The discriminator is docs-vs-source, not the shared `survey` word; pick by what the caller needs (doc list for the brief vs source map for the plan). Because `tools:` and prose constraints are not runtime-enforced, a caller's free-form spawn prompt can override either agent's scope — match the spawn prompt to the agent's role.
- `plan-populator-survey` and `plan-populator-research` are stable prompt stems with different responsibilities: survey collects evidence-only risk signals or exits to research, research makes planner judgments and escalation calls.
- The three `code-review-{correctness,fit,test}` partition playbooks share the reviewer base through `includes: [code-reviewer]` — a root-level flat dep (`agents-plugin/rsrc/code-reviewer.md`) with no frontmatter and no model-var placeholder. Editing that file changes all three partitions; it must stay var-free so partitions with different tiers (`large` vs `medium`) do not collide on an undeclared model var. Playbook-local includes are for fragments owned by that playbook, such as `lead-write-ticket/task-list.codex.md`; they should not replace shared root-level deps used by multiple playbooks.
- wsflow delegate context materialization now lives only in `playbook.render`:
  in wsflow mode the five legacy render-eligible stems append caller context as
  a free-text Render Context block, while arbitrary playbooks and full ws still
  use declared template variables. `playbook.print` and `playbook.render` no
  longer rely on broad namespace string substitution: their wsflow-safe output
  comes from product markers plus explicit namespace variables. The wsflow
  package ships a generated byte-identical rsrc copy
  (`agents-plugin-wsflow/rsrc/`), drift-guarded by
  `TestWsflowRsrcMirrorUpToDate` and regenerated with `WS_REGEN_WSFLOW_RSRC=1`
  (see `ai-docs/ref/wsflow-mirroring.md`). Its distributed skill bodies are
  uniform entry shims, not another procedure corpus.
  {#260513-wsflow-agentless-runtime-mode}
- `playbook.print` / `playbook.render` pass `rsrcRoot` and `worktreeRoot` as explicit call-site parameters, not process-global lookups; argument parsing uses named JSON keys. These seams are now active: `root_override` rebinds both the auto-include resolution root and the child-key binding root; `session_key` triggers render-minted child-key minting for lead callers when the playbook role is delegate-eligible (Phase 2c, implemented). `playbook.print` always passes empty `mintRoot` and ignores `preferMercenary`; only `playbook.render` mints child keys. {#260609-playbook-tools}

## Extension Points & Change Recipes

- **Add a playbook**: create `agents-plugin/rsrc/<name>/<name>.md`, optional `<name>.<harness>.md` harness overlay, optional playbook-local include fragments at `agents-plugin/rsrc/<name>/<include>[.<harness>].md`, and optional shared flat text deps at `agents-plugin/rsrc/<include>.md`; run `wsrsrc.GenerateManifest` to regenerate `manifest.json`; increment `SupportedSchemaVersion` only when the schema shape changes. Set `delegates:true` in frontmatter when the playbook spawns subagents. Set `role:` frontmatter (`implementer`, `reviewer`, `delegate`, or `leaf`) when the playbook is intended for delegate credential injection via `playbook.render`; absent or `lead` role suppresses child-key minting. Declare the tier-derived model-hint var (`RoleModel`) or terminology names (`ExploreAgent`, `SpawnIdiom`, `ContinueIdiom`) in `variables:` frontmatter to activate config-sourced or harness-aware injection; callers cannot override these reserved names via the `context` argument — the tool layer wins on collision. Use implicit `{{.McpNamespace}}` and `{{.SkillNamespace}}` for user-facing namespace notation without adding them to frontmatter.
- **Add an infra doc** (served by `infra.read`): add a flat `agents-plugin/rsrc/<stem>.md` (no frontmatter needed), regenerate `manifest.json`, then read it by bare stem. (The old top-level `infra/<stem>.md` embed location is gone.)
- **Add conditional prompt behavior**: gate it in the caller with an explicit runtime check and append a rendered rsrc prompt to `SystemPromptText`; the registration-time `ConditionalPromptRef` mechanism was removed in 260611 Phase 6b. Do not use the retired API-doc cargo-brief path as a live template.
- **Change delegate orientation**: edit `agents-plugin/rsrc/delegate-orientation.md` (regenerate manifest); review all public named-agent workflows and internal suppressions.
- **Add an override marker to a shipped playbook**: wrap the tunable section with `<!-- ws:override:<pointId> desc="..." --> ... <!-- ws:/override:<pointId> -->`, then regenerate `manifest.json` and the wsflow rsrc mirror (`WS_REGEN_WSFLOW_RSRC=1`). The pointId becomes the user-visible config key prefix (`prompt.<pointId>.<harness>`); choose it deliberately — it is public and stable once shipped.

## Common Mistakes

- Refreshing `runtime.json` after editing rsrc text files; rsrc content is decoupled from `runtime.json` entirely — only `manifest.json` needs regeneration (and the wsflow rsrc mirror via `WS_REGEN_WSFLOW_RSRC`).
- Tuning delegation posture by restoring or writing `prompt.DelegationSection.*`; discovery is marker-driven, the shipped marker is gone, and the live bootstrap path is the global `"workflow.prefer_subagent"` preference.
- Treating playbook-local include fragments as standalone playbook variants; `Validate` skips non-variant local fragments, and `Load` resolves them only through the parent playbook's `includes:` list.
- Registering an existing agent after prompt edits and expecting it to update while a call is active; active registrations cannot be reset.
- Forgetting to regenerate `manifest.json` after adding/editing an rsrc file; `wsrsrc.Load` fails loudly on a hash/listing mismatch.

## Technical Debt

- The rsrc `manifest.json` is the authoritative file inventory for the prompt/playbook/infra tree; there is no longer a `runtime.json` prompt-bundle inventory to drift against.
- Root-relative prompt paths are not implemented.
- Codex non-skill rsrc/ cache materialization: `ResolveRoot` defaults to `os.Executable()/../rsrc` in production (with `WS_RSRC_ROOT` dev override), but whether Codex's non-skill plugin mode correctly materializes the `rsrc/` directory at that derived path is an open verification item.
