# Plan: Pi lead bootstrap: system-prompt-injected workflow manual + Pi lead guide, bridge session-key normalization, workflow_manual -> workflow_state mapping — Phase 1: System-prompt bootstrap + key normalization + manual→state mapping

## Relevant Ticket Contract

- §1: `before_agent_start` appends `event.systemPrompt + "\n\n" + <ws block>` (chained, never replaces). Block order: (a) full `workflow_manual` CONTINUE response fetched once at `session_start` via the bridge's own key, prefixed by a fixed "session-start snapshot" marker line; (b) the Pi lead guide (`agents-plugin-pi/pi-lead-guide.md`, added to `package.json`'s `files`). Fetched once per `session_start`; held in extension memory; re-applied unchanged on every turn (no per-turn refresh).
- §2: `normalizeSessionKey(params, { ownKey, sentinel, parentLeadKey? })`, a pure function next to `resolveSessionKey`, runs in front of fill-or-forward. Exactly two rewrite cases: explicit `session_key === "obsidian-latch"` → own key; explicit `session_key === parentLeadKey` (fork-only, env-delivered) → own key. Every other explicit key passes through untouched (regression: an explicit **child** key must still reach ws-mcp unchanged).
- §3: A model-invoked `ws__workflow_manual` call is intercepted (lead/fork only): primary path cuts the static manual body (playbook.print("lead-workflow-manual") snapshot) out of the `workflow_manual` response by exact substring match, leaving `## Session Key`/`## Session State`/repo notes/advisories; fallback (snapshot not found) dispatches `workflow_state` instead, dropping `workflow_manual`-only args (`root`), and notifies **once** per session that per-call advisories are unavailable. Either way prepend the fixed line "Workflow manual is in your system prompt; this is your current session state." `MODEL_CATALOG_ADVISORY` still rides the mapped response, keyed on the *registered* name. Degraded bootstrap (own key unset or no snapshot) disables both the sentinel rewrite and this mapping for the session, notifies once, and lets the sentinel self-heal exactly as today.
- §4: Spawner sets a process-role marker (`WS_PI_SPAWN_ROLE=worker|explore|fork`, plus `WS_PI_PARENT_SESSION_KEY=<lead key>` for `fork`); absent = host lead. `before_agent_start` appends the ws block when role is absent (lead) or `fork`; nothing for `worker`/`explore`.
- §5: headless `--mode rpc` lead (no spawn marker) gets the ws block like the TUI lead — nothing depends on `ctx.ui`.
- Phase note: "One phase by design... suggested landing order inside the phase, each a self-contained commit: normalization → mapping → role marker + gate → system-prompt injection + guide file." Unit tests required for `normalizeSessionKey` (omit/sentinel/parent-key/unrelated explicit key), the mapping (argument drop, prepended line, advisory-append on the mapped response), and Session-State stripping.
- Golden rule / Constraints: `agents-plugin-tool/` (Go) untouched; system prompt append-only; canonical skill text unchanged, manual text never duplicated into the adapter; rewrite cases are exactly the two in §2 (widening rejected).
- Non-goals: no fork spawn implementation (only reserve the role value + parent-key env var); no agenda/todos in the system prompt; no ws-mcp change.

## Implementation Plan

Land as four self-contained commits, per the ticket's suggested order.

**Commit 1 — normalization:**
1. In `agents-plugin-pi/src/bridge.ts`, add `export function normalizeSessionKey(params, opts: { ownKey: string | undefined; sentinel: string; parentLeadKey?: string })` next to `resolveSessionKey` (`bridge.ts#L154-178`): if `params.session_key === opts.sentinel` and `opts.ownKey` is set, rewrite to `opts.ownKey`; else if `opts.parentLeadKey` is set and `params.session_key === opts.parentLeadKey` and `opts.ownKey` is set, rewrite to `opts.ownKey`; else return `params` unchanged (never mutate input; copy-on-write like `resolveSessionKey`). When `opts.ownKey` is unset (degraded bootstrap), always return `params` unchanged (both rewrites disabled, per §3's degraded-path clause, which also governs §2's sentinel case — the ticket ties them together).
2. Add the literal sentinel constant (`const FRESH_BOOTSTRAP_SENTINEL = "obsidian-latch"`) in `bridge.ts`, matching the copied `rsrc/` skill text.
3. Wire `normalizeSessionKey(...)`'s output into the existing `resolveSessionKey(args, defaultKeyRef)` call site inside `execute()` (`bridge.ts#L228`): `resolveSessionKey(normalizeSessionKey(params, {...}), defaultKeyRef)`. `parentLeadKey` comes from `process.env[WS_PI_PARENT_SESSION_KEY_ENV]` (see Commit 3 for the constant's home — forward-reference is fine since the env var is simply unset until a future fork-spawning ticket sets it).
4. Unit tests in `test/bridge.test.ts`: omitted key (unchanged, still handled by `resolveSessionKey`), sentinel → own key, parent key → own key, unrelated explicit (child) key → unchanged, degraded (`ownKey` undefined) → sentinel passes through unchanged.

**Commit 2 — mapping (workflow_manual → workflow_state):**
1. Add pure helpers in `bridge.ts` (or a small new file if `bridge.ts` gets unwieldy — call is implementer's, both are small): `cutStaticBody(response: string, staticBodySnapshot: string): { text: string; found: boolean }` (exact substring removal, first occurrence) and `prependWorkflowStateLine(text: string): string` (prepends the fixed line from §3).
2. Extend `startBridge`/`BridgeHandle` (`bridge.ts#L44-62`, `#L200-267`) to also fetch, once, right after the ferrule bootstrap succeeds and only when `isLeadOrFork(readSpawnRole(process.env))` (see Commit 3): (a) `client.callTool("workflow_manual", { session_key: ownKey })` → the manual-snapshot text; (b) `client.callTool("playbook.print", { name: "lead-workflow-manual", session_key: ownKey })` → the static-body snapshot text. Store both on the returned `BridgeHandle` (or a sibling ref) for `lead-bootstrap.ts` (Commit 4) and for this mapping to consume. On either call failing or returning no text, leave both unset — this is the "no snapshot" degraded case §3 refers to.
3. In `execute()`'s `rawName === "workflow_manual"` branch, when role is lead/fork and a static-body snapshot exists: intercept the call — dispatch `workflow_manual` (already normalized/resolved key) as usual, then `cutStaticBody` the result against the static-body snapshot; if `found`, return `prependWorkflowStateLine(cut text)` (plus `maybeAppendModelCatalogAdvisory`, keyed on the *registered* name per §3, unchanged existing call). If not `found` (renderer drift), dispatch `workflow_state` instead (dropping `root`/other `workflow_manual`-only args), prepend the same fixed line, and notify once (module-level flag) that per-call advisories are unavailable for the session. When role is worker/explore, or no static-body snapshot (degraded), forward the call verbatim exactly as today (no change to existing behavior for those cases).
4. Unit tests in `test/bridge.test.ts`: `cutStaticBody` found/not-found; `prependWorkflowStateLine`; mapping dispatch picks `workflow_state` and drops `root` on cut-miss; advisory still appends on the mapped response; role gate (worker/explore forwards verbatim even with a snapshot present).

New file `agents-plugin-pi/src/process-role.ts`: `export type SpawnRole = "worker" | "explore" | "fork"`, `export const WS_PI_SPAWN_ROLE_ENV = "WS_PI_SPAWN_ROLE"`, `export const WS_PI_PARENT_SESSION_KEY_ENV = "WS_PI_PARENT_SESSION_KEY"`, `export function readSpawnRole(env: NodeJS.ProcessEnv): SpawnRole | undefined` (validates against the 3 literal values, else `undefined`), `export function isLeadOrFork(role: SpawnRole | undefined): boolean` (`role === undefined || role === "fork"`).
