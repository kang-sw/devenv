# Plan: 260909-feat-ws-pi-agent-row-model-and-usage — Phase 1: Add event-backed agent row telemetry

## Relevant Ticket Contract

- Every agent row shows actual resolved model and effort, the latest model call's reported input tokens, and cumulative estimated child-attributable USD. Unknown fields independently show `—`. Never infer billing, invent prices/usage, or use cumulative session tokens as latest input.
- Count child calls once across continuation and dormant resume, excluding inherited fork history. Retain a valid snapshot or show unknown when attribution is genuinely unrecoverable. Collection happens outside rendering; no rendering RPC, disk reads, model requests, or per-frame polling.
- Preserve sorting, waiting rows, cap, count heading, question hints and width bounds. At 40 columns reserve `/answer <id>` before allocating space to identity/telemetry. Wider rows expose more detail without changing priority.
- Cover workers, execute-workers, persistent simple/deep researchers, task forks, discussion respondents, ordinary sidecar revival, and thread-only revival. No model/network calls or owner-history edits in automated verification. Owner-live worker/fork check remains required.

## Out of Scope

- Go source, shared playbooks/resources, new model tools, provider pricing/billing, delegation/settlement semantics, one-shot research leaves absent from the widget registry, and already-landed panel count behavior.
- No session-format writes from the owner process, provider response-ID requirements, timestamp/content fingerprints, or new per-frame telemetry loop.

## Codebase Findings

### Identity and attribution mechanism

- Installed SDK source under `agents-plugin-pi/node_modules/@earendil-works/pi-coding-agent/dist/core/session-manager.js`: `SessionManager.appendMessage` assigns a mandatory unique `entry.id` using `generateId(this.byId)` and appends the finalized message. `getEntries` preserves entries across compaction and reopening. `SessionManager.forkFrom`, the CLI fork mechanism, copies **all non-header entries** without changing their IDs and gives the child a new session header ID plus `parentSession`. Do not substitute `createBranchedSession`'s branch-only behavior when modeling this CLI path.
- `core/agent-session.js` `_handleAgentEvent` emits `message_end` before synchronously appending that message. A parent listener cannot assume an immediate file read already includes it. An awaited `RpcClient.getState()` request on that child provides a subsequent child-event-loop round trip; read after its response. Reconcile again at settlement and after stop, with launch-generation guards. Never add costs directly from event delivery.
- `modes/json-event.js#toJsonEvent` emits cumulative `message_update.usage` snapshots, not deltas. Final assistant messages carry per-call `usage.input` and `usage.cost.total`, but only optional `responseId`. Durable session-entry IDs solve deduplication without provider-specific call identities.
- `core/session-manager.d.ts` defines version-3 session header and entry shapes. Read the child's JSONL directly through a narrow validated reader; do not call `SessionManager.open` on production histories because its load/migration behavior is not a read-only contract. Use SDK SessionManager only in isolated fixtures.
- `core/agent-session.js#getSessionStats` aggregates assistant usage, usage-bearing tool results, and compaction/branch-summary usage over all entries. Reuse this accounting category distinction, not its inherited session total. Compaction usage can aggregate several summary calls: it can contribute reported cost once, but its aggregate input is not proof of the latest individual model call's input.
- SDK `SessionManager._persist` defers a fresh session file until the first assistant message. A known newly allocated worker session can therefore have no file and still have a proven empty inherited prefix. ForkFrom itself writes its child file. A missing file on an arbitrary restored record is not equivalent to a fresh empty session.

### Existing integration seams

- `agents-plugin-pi/src/spawner.ts`: `RpcAgentRecord`, `spawnAgent`, `sendToAgent`, `attachEventListener`, `applyRpcEvent`, `stopAgent`, `clearLiveState`, `captureForkSelection`, `applyModelEffort`, and `verifyResearchSelection` own persistent child lifecycle. `launchGeneration` already distinguishes stale clients. Keep launch-intent `modelBase/modelEffort` separate from observed display fields: requested effort may be clamped, missing, or replaced in actual child state.
- `RpcClient.getState` returns resolved `model.provider`, `model.id`, `thinkingLevel`, `sessionFile`, and `sessionId` without making a model call. The SDK exposes `thinking_level_changed`; model selection itself is an extension `model_select`, not a guaranteed RPC model-change event. Refresh state on spawn/resume, model-call start/end, settlement, and any adapter-issued selection change. Do not wait for an invented RPC `model_changed` event.
- `agents-plugin-pi/src/agent-sidecar.ts`: `PersistedOrphan`, `captureOrphans`, `parseOrphans`, `rehydrateOrphanRecord`, and `reviveOrphans` implement ordinary recovery. `captureOrphans` intentionally excludes `threadBound` records.
- `agents-plugin-pi/src/ask.ts`: `PersistedForkResume`, `captureForkResume`, `rehydrateForkRecord`, `parseThreadRegistry`, `persistThreads`, and `hydrateThreadRegistry` implement the other recovery route. `buildAgentRows` can render a thread that has no live RPC record; its telemetry must come from the validated `forkResume` snapshot. Plain threads without a respondent remain independently unknown.
- `agents-plugin-pi/src/index.ts` shutdown captures sidecar status before `stopAll`, then discards registries. Preserve that status ordering while finalizing telemetry. Shutdown/rehydration are collection boundaries, not render callbacks.
- Fork bootstrap in `index.ts` appends `ws-pi-fork-context` and `ws-pi-fork-keys` entries containing the actual session ID. Inherited markers refer to another session ID. However, the first observed same-session marker may have been introduced on a legacy resume, so it alone is not universal proof of the original inherited boundary. Do not silently turn a legacy fork's older child calls into excluded parent history.
- `agents-plugin-pi/src/agent-widget.ts`: `AgentRow`, `buildAgentRows`, `formatRow`, and `buildWidgetLines` are the pure projection/formatting seams. Current full-line truncation can cut off the trailing answer hint; reserve the hint explicitly.

### Additive adapter contract selected by research

Introduce a shared adapter-only telemetry type/parser in new `src/agent-telemetry.ts`, used by records and both recovery formats. Keep this independent of spawner/ask to avoid cycles. It holds a versioned normalized display snapshot and immutable attribution origin: actual child session ID, session path binding, and either a proven empty prefix or the durable last-entry ID of the complete pre-first-prompt prefix. The latter excludes every entry through that anchor in file order, not just ancestors on the active branch. Keep the origin across every continuation/resume; never reset it at a later launch.

The snapshot records independently optional actual model, effort, latest input, and estimated total; retain the last validated snapshot as an explicitly stale fallback while the child/session is unreadable. Persist only finite nonnegative numbers and coherent provenance; malformed telemetry does not invalidate an otherwise resumable record. No ever-growing per-event ledger is needed: each refresh recomputes from the complete child-attributable entry set, unique by durable entry ID. Repeated event notifications consequently cannot add cost twice.

## Implementation Plan

1. **Implement the contract and reducer in `src/agent-telemetry.ts` (new).** Add normalized types, a shared tolerant snapshot parser, a read-only session reader, and a pure reducer over parsed entries plus attribution origin. Bind origin to header ID and path; validate mandatory IDs, supported header shape, prefix anchor presence, duplicate IDs and numeric usage. Identical repeated entries contribute once; conflicting duplicate IDs or a missing anchor invalidate new attribution. Do not accept a truncated/malformed interior as complete. An incomplete trailing JSON line is a transient read: keep the last valid snapshot and retry at the next event/lifecycle boundary. Never return a partial total labeled complete.

   Sum each attributable assistant call's reported `usage.cost.total` once, plus independently usage-bearing tool-result/compaction/branch-summary entries as SDK statistics do. Missing/invalid cost on a known call makes the complete total unknown, without discarding independently valid latest input. Cache read/write stay separate; input display uses `usage.input` unchanged. Preserve a real reported zero; an empty history has no usage/cost observation and displays `—`, not fabricated zero. For a later summary whose usage may aggregate calls, clear latest input to unknown rather than showing aggregate tokens as one call. Non-model tool results without usage do not erase latest model input. Read model/effort from actual state, never from historical parent messages.

2. **Initialize and refresh in `spawner.ts#spawnAgent` and `#sendToAgent`.** After start/readiness and model/effort application/verification, query actual state for every persistent role. Discover/bind the actual session identity and path. On a fresh spawn, capture the complete pre-prompt prefix anchor (or proven fresh-worker empty prefix) before `promptAgent`. Persist that same origin in memory and later snapshots. A baseline read failure leaves cost unknown; it must not abort otherwise valid delegation or pretend the next turn begins lifetime accounting. On resume, reuse and validate the saved origin, reconcile existing child entries before dispatch, and refresh actual selection. Clear old observed selection at the start of a new launch; a failed/missing state field becomes independently unknown. Preserve launch configuration and existing explore selection verification.

3. **Collect from `spawner.ts#attachEventListener`, outside `#applyRpcEvent` and rendering.** Coalesce serialized refresh requests per record/client/generation. Assistant completion triggers the getState barrier plus JSONL reconciliation; updates are invalidation signals at most, never summed. Also reconcile at compaction/settlement boundaries and refresh actual selection at assistant/agent start and `thinking_level_changed`. Capture all events from attachment through the first prompt. Ignore completed work belonging to a replaced launch, including rejected/late promises. Trigger widget refresh only after a valid snapshot change. Ensure a burst arriving during refresh requests one final follow-on refresh rather than being lost. A failure retains the prior valid usage snapshot or unknown; model changes cannot retain the old selection as current.

4. **Complete all recovery/lifetime seams.** Add optional telemetry to `RpcAgentRecord`, `PersistedOrphan`, and `PersistedForkResume`. Use one parser in sidecar and thread readers; capture/rebuild it through `captureOrphans`, `rehydrateOrphanRecord`, `captureForkResume`, and `rehydrateForkRecord`. Reconcile child files outside rendering on sidecar revival and thread hydration, including thread-only rows before the respondent is relaunched. Refresh `forkResume` when its respondent telemetry changes so an owner-held waiting row remains current; reuse existing thread persistence rather than a parallel registry.

   In `stopAgent`, preserve its synchronous `clearLiveState` race protection. Drain pending telemetry as appropriate and do the final read after abort/stop against captured session identity, committing only if its generation remains current. Do not postpone clearing live state to make telemetry convenient. In `index.ts` shutdown, retain pre-stop orphan status for the roll-call, finalize telemetry after stopping, and write updated telemetry into the same captured orphan set and applicable thread snapshots before dropping registries. Final disk reconciliation catches messages persisted during shutdown; an older snapshot plus unchanged origin remains safely replayable next start.

   Legacy recovery must try what is provable: a coherent non-fork record with a valid header and no parent session has an empty inherited prefix, so recompute its complete usage even without telemetry. For a fork, accept a valid saved origin; missing origin does not justify excluding all currently present history. Parent/inherited marker heuristics are insufficient where original fork provenance is absent. Such a legacy fork's cumulative cost remains unknown. Before its next prompt, capture a separate current-launch observation floor in the valid child file: later entries can prove latest child-call input without claiming a lifetime-cost origin. Keep that floor distinct from the immutable lifetime origin; never promote it into a complete cost baseline. Repeated reconciliation uses entry order and IDs, so replay cannot roll latest input back to an older event. Until a child-only entry is identified, latest input is unknown; inherited parent input is never shown. Actual state still supplies model/effort. Preserve a valid saved display snapshot when the file is absent/unreachable. A changed session ID, missing origin anchor, or conflicting data cannot inherit the previous session's total. Tests must distinguish these genuine unknowns from recoverable ordinary resumes.

5. **Render in `agent-widget.ts#buildAgentRows`, `#formatRow`, and `#buildWidgetLines`.** Project normalized snapshots from live records or thread `forkResume` without I/O. Show `<model> (<effort>)`, latest input, and an explicitly estimated USD amount, with independent `—` fields. Make the formatter width-aware: reserve the full answer cue when it fits, then allocate compact state/identity and telemetry; at 40 columns abbreviate or omit telemetry before sacrificing the answer cue. At 80/120 columns expose all requested fields when their text fits. Use existing display-width utilities, including Unicode. Keep one logical row, existing sorting/cap/count semantics, and waiting-row inclusion.

## Escalations

None. Confidence is high in the source-backed durable-entry identity and immutable-prefix attribution mechanism; offline SDK probing confirmed the critical assumptions. Legacy forks without an original boundary, corrupted histories, and unpersisted calls after a hard crash have genuinely unrecoverable lifetime cost and use the ticket's authorized unknown fallback. Summary usage may provide aggregate cost without an individual latest-call input; that field remains independently unknown. Implementation must verify asynchronous ordering and both recovery routes before claiming completion; owner-live acceptance remains outstanding.
