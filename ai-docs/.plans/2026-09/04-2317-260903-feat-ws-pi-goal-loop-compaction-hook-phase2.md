# Plan: 260903-feat-ws-pi-goal-loop-compaction-hook — Phase 2: Model-driven compaction lever + config knobs

## Relevant Ticket Contract

- `/goal-compact-and-continue <carry-forward-prose>`: prose -> `ctx.compact({ customInstructions })` -> re-enter the next goal turn (non-terminal, unlike `goal-achieved`/`goal-blocked`).
- Surface BOTH `getContextUsage().percent` AND the compression-safety heuristic advisory (phase-boundary/merge-gate = safe; non-phase stop = unsafe) as informational text in the continue/reminder turn — the model decides; the extension never autonomously compacts.
- Config knobs, adapter-owned data-file (extension-constant default + `goal-loop-config.json` override, never-throw, read fresh per use, `model-catalog.json`/Phase-1 precedent): runaway threshold (exists), a compaction advisory point (percent), and a context-window/max-token override.
- `session_before_compact` companion: inject ws state into a compaction; observe `reason: "threshold"`; Pi's own overflow auto-compaction stays the last-resort backstop.
- Resolved design (ticket, "Compaction ownership"): model-driven, not extension-gated. The heuristic is advisory prose the model weighs, not a computed gate.
- Verification boundary (ticket's own Phase 2 section): a live transcript showing (a) `/goal-compact-and-continue` compacts with the carry-forward prose and re-enters the loop, (b) percent surfaces in the continue turn, (c) a config-knob override takes effect on a fresh read.
- Golden rule: `agents-plugin-tool/` (ws-mcp Go source) untouched; goal-loop stays adapter-local; dependency one-directional (adapter -> ws-mcp).

## Out of Scope

- Any spec anchor edits (`ai-docs/spec/pi-adapter-runtime.md`) — spec text lands at the doc pre-pass (`lead-write-spec`), not in this survey/plan.
- Durable goal state across compaction / `/goal-blocked` writing a durable ticket record — ticket's own "Remaining open questions," explicitly deferred past Phase 2.
- `session_before_compact` vetoing or replacing the CONTENT of Pi's own `reason: "threshold"` auto-compaction (i.e. building a full custom `CompactionResult` via `generateSummary`/`compact` to inject ws state into an auto-triggered compaction). The ticket's own resolved design says the heuristic is advisory, "not an extension gate," and lists heuristic-as-veto as an explicitly deferred open question ("whether `session_before_compact` should still veto an unsafe compaction... none blocks the phases"). Pi's `SessionBeforeCompactResult` only supports `cancel` or a full `compaction` override — no partial "add customInstructions" field exists for the auto-triggered path (confirmed by reading `agent-session.js`'s `_runAutoCompaction`, which hardcodes `customInstructions: undefined` in the emitted event and only reads back `cancel`/`compaction` from the handler result). Building the full override is a large undocumented feature beyond "inject state / observe signal" and is not required by the verification boundary. The companion therefore: (1) for `reason: "manual"` — no extra work needed, since `customInstructions` is already forwarded verbatim from our own `ctx.compact()` call (confirmed at `agent-session.js:1495`), so "injecting ws state" is already satisfied by the `/goal-compact-and-continue` tool itself; (2) for `reason: "threshold"` — observe-only (notify), no override, no veto.
- Interaction with subagent RPC children beyond what Phase 1 already settled (lead-session-only) — no new child-facing surface in this phase.
- Reproducing the opencode four-token marker (already a ticket non-goal).

## Codebase Findings

- `agents-plugin-pi/src/goal-loop.ts#L65-L103` — Phase 1's `GoalLoopConfig`/`readGoalLoopConfig`/`resolveRunawayThreshold` never-throw, read-fresh-per-call pattern to extend for the two new knobs (`compaction_advisory_percent`, `context_window_override`).
- `agents-plugin-pi/src/goal-loop.ts#L109-L126` — `buildGoalAnnouncement`/`buildGoalReminder` pure message builders; `buildGoalReminder` currently takes only `goal: string` and must be extended to also render the percent + compression-safety advisory text.
- `agents-plugin-pi/src/goal-loop.ts#L176-L202` — `SettleDecision`'s `"reinject"` variant currently precomputes `reminder: buildGoalReminder(state.goal!)` *inside* the pure `decideOnSettle` reducer. Non-obvious constraint: `decideOnSettle` has no access to `ctx.getContextUsage()` or the config file (those are IO-context-only), so Phase 2 must change the reinject decision to carry only `{ action: "reinject"; goal: string }` and move `buildGoalReminder(...)` construction into the `registerGoalLoop` IO glue (the `agent_settled` handler), right where `ctx.getContextUsage()` and the config read are already available. This breaks the existing `decideOnSettle`/reinject test shape in `agents-plugin-pi/test/goal-loop.test.ts#L171-L210` — those assertions need updating to the new shape as part of this phase, not as an incidental side effect.
- `agents-plugin-pi/src/goal-loop.ts#L220-L265` — `registerGoalLoop`'s `agent_settled` handler is the IO glue call site: reads config once per settle (`readGoalLoopConfig`/`resolveRunawayThreshold`), calls `decideOnSettle`, and `pi.sendUserMessage`s the reminder. Extend the same config read to also resolve `compaction_advisory_percent`/`context_window_override`, and combine with `ctx.getContextUsage()` to build the reminder text right before sending it.
- `agents-plugin-pi/src/goal-loop.ts#L267-L301` — `goal-achieved`/`goal-blocked` `pi.registerTool()` precedent: JSON-schema `parameters` (cast `as never`), `async execute(_toolCallId, params)` returning `{ content: [{ type: "text", text }] }`, and `state = disarmGoal()` for terminal levers. `/goal-compact-and-continue` mirrors this shape but is **non-terminal** (no `disarmGoal()` call) and needs the 5th `execute` arg (`ctx`) to call `ctx.compact(...)`.
- `agents-plugin-pi/src/spawner.ts#L1146-L1189` (esp. `#L1172`) and `#L1305-L1321` — existing precedent for a tool's `execute(_toolCallId, params, _signal, _onUpdate, toolCtx)` 5-arg signature that consumes the `ctx` argument (there typed `toolCtx: unknown` with a narrow inline cast, e.g. `#L1130-L1133`'s `inheritModel`). `ExtensionContext` is directly importable from `@earendil-works/pi-coding-agent` (confirmed in `dist/core/extensions/types.d.ts`), so the new tool can type `ctx: ExtensionContext` directly instead of following the `unknown`-cast style — either is consistent with local precedent; direct typing is simpler here since `ctx.compact`/`ctx.getContextUsage` are used directly (no narrow field access needed).
- `agents-plugin-pi/src/spawner.ts#L57` (`WS_PI_AGENT_CHILD_ENV` export) and `goal-loop.ts#L162-L164` (`isChildProcess`) — reuse for the same lead-session-only guard on the new `session_before_compact` listener.
- `agents-plugin-pi/src/index.ts#L82,124` — `goalLoopConfigPath` construction and `registerGoalLoop(pi, { goalLoopConfigPath })` call site; no change needed here beyond what `registerGoalLoop`'s options already carry (config path is read fresh per use inside goal-loop.ts, not passed as parsed data).
- `agents-plugin-pi/goal-loop-config.json` — currently `{}`; stays a valid "all defaults" file (no required-field addition), matching `readGoalLoopConfig`'s never-throw/optional-everything contract.
- `agents-plugin-pi/node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/types.d.ts#L193-L246` — `ContextUsage { tokens: number | null; contextWindow: number; percent: number | null }`, `CompactOptions { customInstructions?; onComplete?; onError? }`, `ExtensionContext.getContextUsage()`/`compact()`. `percent`/`tokens` are `null` right after a compaction until the next LLM response — the reminder builder must render "unknown" gracefully, not crash or divide by zero.
- `types.d.ts#L441-L476` — `SessionBeforeCompactEvent { preparation, branchEntries, customInstructions?, reason: "manual"|"threshold"|"overflow", willRetry, signal }` and `SessionBeforeCompactResult { cancel?; compaction?: CompactionResult }` — confirms there is no partial "just set customInstructions" result field, only cancel-or-full-override, which is why the plan above scopes the threshold path to observe-only.
- `agent-session.js#L1468-L1507` (manual `compact()`) vs `#L1733-L1779` (`_runAutoCompaction`) — confirms `customInstructions` is forwarded verbatim into the `session_before_compact` event for the manual path (our own `/goal-compact-and-continue` call), but hardcoded `undefined` for the auto/threshold path, and the handler result is read back only as `cancel`/`compaction` in both paths.
- `node_modules/@earendil-works/pi-coding-agent/examples/extensions/trigger-compact.ts` — canonical usage pattern for `ctx.compact({ customInstructions, onComplete, onError })` with `ctx.ui.notify` on complete/error; mirror this for the new tool's `ctx.compact` call.
- Risk signal (non-obvious, verification-relevant, already covered by the ticket's own live-transcript verification boundary — not escalated): `ctx.compact()`'s manual path calls `await this.abort()` first, aborting "the current agent operation." The new `/goal-compact-and-continue` tool's `execute()` runs *during* an in-flight agent turn (it is itself a tool call within that turn), so calling `ctx.compact()` from inside it triggers an abort of the very turn that invoked it. This is expected/intended (matches "then re-enters the next goal turn": the abort+compact sequence naturally produces a fresh `agent_settled`, which the existing Phase-1 armed-settle handler already re-injects a reminder from — no separate manual "continue" call is needed in the tool's `execute()` beyond returning its own tool result and calling `ctx.compact()`). This exact interaction (tool-triggered compaction of the turn containing the tool call) has no existing example in the installed Pi docs/examples, so it is exactly the ticket's own live-transcript verification target, not something to gate on a deeper research pass.
- `agents-plugin-pi/test/goal-loop.test.ts` — existing unit-test file to extend: config reader/resolver tests (mirror `resolveRunawayThreshold`'s never-hard-fail suite for the two new knobs), `buildGoalReminder`'s new percent/advisory rendering, a new `computeContextPercent`-style pure helper, and the updated `decideOnSettle` reinject shape. No unit coverage is expected (or precedented) for `registerGoalLoop`'s new tool/listener IO glue itself — Phase 1 left `registerGoalLoop`'s IO untested by design (per the test file's own header comment), deferring to the live `pi --mode json` gate; Phase 2 follows the same split.

## Implementation Plan

1. `agents-plugin-pi/src/goal-loop.ts` — extend `GoalLoopConfig` with `compaction_advisory_percent?: number` and `context_window_override?: number`; add `DEFAULT_COMPACTION_ADVISORY_PERCENT` (adapter-chosen default, e.g. `70` — no ticket-pinned value, config-tunable) alongside the existing `DEFAULT_RUNAWAY_THRESHOLD`; add `resolveCompactionAdvisoryPercent(config)` (falls back to default unless the value is finite and in `(0, 100]`) and `resolveContextWindowOverride(config)` (returns `undefined` unless the value is a finite positive number) — both follow `resolveRunawayThreshold`'s exact never-hard-fail shape.
2. `agents-plugin-pi/src/goal-loop.ts` — add a pure `computeContextPercent(usage: ContextUsage | undefined, contextWindowOverride?: number): number | null`: if `usage` is undefined, return `null`; if `usage.percent` is a number and no override is set, return it as-is; if `usage.tokens` is a number, compute `(usage.tokens / (contextWindowOverride ?? usage.contextWindow)) * 100` whenever an override is set or `usage.percent` is `null`; otherwise `null`. Import `ContextUsage` as a type from `@earendil-works/pi-coding-agent`.
3. `agents-plugin-pi/src/goal-loop.ts` — extend `buildGoalReminder(goal: string, info: { percent: number | null; advisoryPercent: number })` to append: (a) a context-usage line ("Context usage: N% of window." or "Context usage: unknown." when `percent` is `null`), with a stronger nudge phrase when `percent !== null && percent >= advisoryPercent` versus a neutral phrase otherwise; (b) a fixed compression-safety heuristic advisory sentence (static prose per the ticket's exact framing: phase-boundary/merge-gate stops are generally safe to compact, a non-phase stop is not — the model weighs this, the extension does not decide); (c) name the new `goal-compact-and-continue` lever alongside the existing two. Update the existing call sites/tests for the new signature.
4. `agents-plugin-pi/src/goal-loop.ts` — change `SettleDecision`'s `"reinject"` variant from `{ action: "reinject"; reminder: string }` to `{ action: "reinject"; goal: string }` (drop the precomputed reminder — `decideOnSettle` has no access to `ctx.getContextUsage()`/config); `decideOnSettle` itself no longer calls `buildGoalReminder`.
5. `agents-plugin-pi/src/goal-loop.ts` — in `registerGoalLoop`'s `agent_settled` handler: after resolving the threshold (existing), also resolve `advisoryPercent`/`contextWindowOverride` from the same config read; on a `"reinject"` decision, compute `percent = computeContextPercent(ctx.getContextUsage(), contextWindowOverride)` and call `pi.sendUserMessage(buildGoalReminder(decision.goal, { percent, advisoryPercent }))`.
6. `agents-plugin-pi/src/goal-loop.ts` — add the `goal-compact-and-continue` `pi.registerTool()` (mirrors `goal-achieved`/`goal-blocked`'s shape): `parameters` requires `carry_forward: string` (the prose); `execute(_toolCallId, params, _signal, _onUpdate, ctx: ExtensionContext)` calls `ctx.compact({ customInstructions: params.carry_forward, onComplete: () => ctx.ui.notify("Compaction completed", "info"), onError: (e) => ctx.ui.notify(\`Compaction failed: ${e.message}\`, "error") })` (mirrors `trigger-compact.ts`'s example) and returns a `{ content: [{ type: "text", text: ... }] }` tool result; **non-terminal** — does not call `disarmGoal()`, and does not itself send a follow-up message (the compaction-triggered settle re-arms the existing reminder path). Import `ExtensionContext` as a type alongside `ExtensionAPI`.
7. `agents-plugin-pi/src/goal-loop.ts` — add the `session_before_compact` listener in `registerGoalLoop`: guarded by `isChildProcess(process.env)` (return early, matching the `agent_settled` guard) and by `state.active` (no-op outside goal mode); when active, `ctx.ui.notify` a short observational message naming the active goal and `event.reason` — always returns `undefined`/no result (no `cancel`, no `compaction` override — non-vetoing, matching the resolved "not an extension gate" design). Extract the message text into a small pure builder (e.g. `buildCompactionObservation(goal: string, reason: "manual"|"threshold"|"overflow")`) for unit coverage, keeping the listener itself thin IO glue per the file's established pure/IO split.
8. `agents-plugin-pi/goal-loop-config.json` — no structural change required (`{}` already satisfies "all knobs unset -> defaults"); optionally leave a comment-equivalent note only if the executor judges it helpful (JSON has no comments — skip unless a sibling doc needs updating).
9. `agents-plugin-pi/src/index.ts` — no change expected: `registerGoalLoop(pi, { goalLoopConfigPath })`'s existing call site and options shape already cover the new knobs (same file, read fresh per use); update only the file's top-of-file doc comment block if it enumerates Phase 1 specifics that now read as stale (optional, low-risk doc-comment touch-up).
10. `agents-plugin-pi/test/goal-loop.test.ts` — add/extend unit coverage: `resolveCompactionAdvisoryPercent`/`resolveContextWindowOverride` (undefined/empty/valid/zero/negative/non-numeric/NaN/Infinity, mirroring the existing `resolveRunawayThreshold` suite), `computeContextPercent` (undefined usage, null percent+null tokens, null percent+known tokens+override, known percent+no override, known percent+override present), the updated `buildGoalReminder` (percent below/at/above advisory point, `null` percent, new lever name present), the updated `decideOnSettle` reinject shape (`{ action: "reinject", goal }` without an embedded reminder), and `buildCompactionObservation` (per-reason wording). Update the existing tests at `#L171-L210` that currently assert the old embedded-reminder shape.
