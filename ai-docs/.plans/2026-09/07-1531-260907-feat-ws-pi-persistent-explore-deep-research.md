# Plan: 260907-feat-ws-pi-persistent-explore-deep-research — Phase 1

## Relevant Ticket Contract

Authority: `ai-docs/tickets/ready/260907-feat-ws-pi-persistent-explore-deep-research.md`, Decisions, Constraints, Spec Impact, and Phase 1; owner clarification permits extending the shared resolver with cause information and caller-specific policy without further design approval.

- Lead/fork public interface: `explore({ query, deep_research? })`; omitted/false means simple. Return exactly `{ agent_id, alias }` after initial RPC prompt acceptance, not after completion. No public model, tier, effort, or arbitrary tools selector; `ws-agent-spawn` schema is unchanged.
- Simple uses configured authenticated `small` and exactly `read,grep,find,ls`. Deep captures the dispatching lead/fork's actual model and effort together, not configured `large`, and uses those read tools plus blocking `explore`. Direct reading remains available; delegation is optional.
- Deep collection uses authenticated `small`, its resolved effort, no bash, and no recursive delegation. Allowed tree: lead/fork → deep researcher → ephemeral blocking collection. Existing worker/execute-worker blocking, self-reaping exploration is not converted into orchestration.
- Simple creation and collection requests fail explicitly on unset/unknown/no-auth/empty-catalog/transport/parse failures before process, prompt/session allocation, registry mutation, capacity eviction or alias reservation. Deep parent creation does not resolve or require `small`; a refused collection returns an error to its parent without launching an inherited replacement.
- Researchers are ordinary persistent RPC records: repeated answers through settle `last_message`, sends, park, stop/resume, failure transitions, transcripts, aliases/titles, widget/fan-in and sidecar restoration. Identity, mode, permissions and effective model/effort survive continuation/restart. Later parent retuning does not retune existing children.
- Adapter implementation only in `agents-plugin-pi/`; update `ai-docs/spec/pi-adapter-runtime.md`, adapter descriptions and lead guidance in the same slice. Preserve predecessor's frozen Result. Automated coverage is necessary but does not replace owner-run live dogfood.

## Out of Scope

- ws-mcp Go changes, shared `rsrc` semantic changes or hand-editing the Pi `rsrc` mirror, runtime-pin changes, new public spawn/config/tool-list APIs, model catalog subprocess probes, and another agent lifecycle runtime.
- Sibling tier ticket's backend-expansion/refusal rollout for unrelated spawns, warning removal and advisory deduplication. Preserve whichever ordinary policy is present when this slice lands; its transport/parse fallback and omitted-tier no-parent-effort behavior must remain unchanged.

Here “unchanged worker leaves” preserves that actual source behavior; the new deep collection uses the different, genuinely no-bash `read-only` profile. Do not relabel `recon` as capability-enforced read-only.

### Internal cross-module contracts selected here

These are implementation mechanics, not new user-facing configuration:

1. Extend `TierResolution` additively with required `source: tier|inherit` and optional `failure` carrying `kind: transport|parse|unset|unknown|no-auth`, with available resolved-from/raw/checked-model detail. Accepted tier has no failure/rejected; omitted alias has source inherit and neither. Every other outcome has source inherit, inherited model, no tier effort, and failure detail. Keep existing `rejected` details and meanings for existing callers; unknown/no-auth may appear in both diagnostic views but are constructed once in the shared resolver. When sibling adds unset rejection, retain it and mirror its cause without changing source. Empty catalog is unknown with catalog-empty detail, not inheritance success.
2. Transport = thrown MCP call or MCP `isError`; parse = missing text, invalid JSON, non-object payload, missing/invalid required discriminator/model fields or non-string effort when supplied. A well-formed non-Pi answer is unset, not parse. The resolver performs no registry/filesystem/UI effects. Preserve sibling backend expansion if present; do not add a preset-local normalization map.
3. `RpcSpawnCtx` gains an exploration-only require-tier policy. `spawnAgent` resolves exactly once, then applies caller policy before guards. The persistent preset uses an already-packaged fixed guide path, so it needs neither external preflight nor a prepared-model override: there is no prompt-render allocation before the common resolver. The blocking handler uses that same resolver before entering `exploreLeaf` and its render/allocation path.
4. Persist optional `exploreMode: simple|deep` on `RpcAgentRecord` and `PersistedOrphan`; pair it with record/process role explore. Add internal `WS_PI_EXPLORE_MODE` in `src/process-role.ts`, read only together with role explore. Missing/invalid mode never enables collection. Set it explicitly on researcher launch/resume and clear it on every non-research launch, especially a blocking leaf. No public environment tuning surface is introduced.
5. Add internal `read-only-explore` to `ToolGroup`, containing `READ_ONLY_BUILTINS` plus literal explore, with no bridge names. New records store exact mode/group and modelBase/modelEffort. Do not add a second persisted tool list for research; use existing group machinery and reject contradictory explicitTools on research restoration.
6. Generated aliases use an internal prefix request on `RpcSpawnCtx` (explore uses `explore`), with common `spawnAgent` scanning current aliases immediately before guards/insertion. Pick the first free positive suffix, including dormant/restored holders. Explicit public alias transfer semantics remain unchanged.
