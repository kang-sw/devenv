### Existing mechanisms and API seams

- `agents-plugin-pi/package.json` and `package-lock.json` currently have no Agent SDK dependency. Pin **0.3.263** during implementation, the exact package inspected and probed, instead of resolving a moving SDK version. Source-backed API reference: [Anthropic TypeScript Agent SDK reference](https://code.claude.com/docs/en/agent-sdk/typescript). The inspected package's `sdk.d.ts` is the version-specific authority: `query` returns `Query extends AsyncGenerator<SDKMessage, void>`; `Query.close()` is synchronous; `Options.abortController` and `Options.spawnClaudeCodeProcess` expose cancellation/process ownership. `SpawnOptions.signal` is forwarded after SDK graceful shutdown, not the immediate caller signal. `SpawnedProcess` is satisfied by Node `ChildProcess`.
- The property is **`settingSources`**, not `settingsSources`. `Options.env` replaces inheritance; `tools` sets the actual built-in inventory, whereas `allowedTools` alone is not a closed inventory. `strictMcpConfig` closes ambient MCP discovery; empty settings alone did not close account connectors in the earlier provider spike. Managed policy settings may still apply.
- `SDKResultSuccess` can have `is_error: true`: success requires both success subtype and false `is_error`. `SDKResultError` supplies error subtypes/errors. Terminal `modelUsage` is cumulative per query; never sum snapshots, and never treat `total_cost_usd` as an actual bill. A stream ending without a valid result is an item error.
- `agents-plugin-pi/src/index.ts` owns adapter registration, `session_start`, and `session_shutdown`. Register the leaf through `src/tool-result-render.ts::registerWsTool` and the existing late-filled `ToolPreviewTuiRef`; do not duplicate renderers or call ws-mcp for the new tool.
- `src/lead-bootstrap.ts::computeSessionBootstrap` preserves a fork's captured active-tool list verbatim, and `src/execute-gateway.ts::computeLeadActiveTools` retains existing non-removed tools. Preserve those contracts. A separate declaration must not accidentally add this leaf to worker/explore profiles or re-add tools to a fork.
- `src/spawner.ts::registerAgentTools`, its RPC lifecycle, alias reservation, and UUID handles implement a different persistent agent contract. Keep them untouched. Search found no reusable Pi-local three-word allocator; a small leaf-local allocator is appropriate without importing Go internals or adding an agent framework.
- `test/native-tool-registration.test.ts` captures actual definitions and exercises shared rendering without models. Package tests run through `npm test` (`node --test` with Pi role env unset). Inject SDK query/process/clock dependencies for lifecycle tests; keep real model/network calls out of that suite.

### Settled public encoding and configuration decisions

The installed Pi `ToolDefinition` accepts `TSchema`, but its nested `@earendil-works/pi-ai/dist/api/anthropic-messages.js::convertTools` rebuilds `input_schema` with `type: "object"`, `properties`, and `required`. A top-level array loses its item schema there. The lead adjudicated the ticket example as conceptual batch notation: the **physical Pi arguments are `{items: [...]}`**, the core consumes the array, and output is **JSON text containing the aligned result array, plus `details.items` with that same array**. This is the necessary provider-compatible encoding; do not register an unsupported root-array schema or introduce single-item overloads. The lead will clarify the physical schema in the ticket/spec pass.

Other lead-accepted implementation policy: **three active children total per session controller**, shared across overlapping tool invocations; **120,000 ms per running item from slot acquisition through SDK result**, plus **at most 2,000 ms cleanup**. No caller-controlled timeout/concurrency fields or new global config/env surface. Queued items wait fairly behind finite work, do not consume execution timeout, and cancel immediately with their own invocation. No immediate schema/architecture ambiguity remains after these adjudications.

## Implementation Plan

1. **Define the Phase 1 public contract in proposed `agents-plugin-pi/src/claude-delegate.ts::ClaudeDelegateItem`, `ClaudeDelegateResult`, and `registerClaudeDelegate`.** Register `ws-claude` with an object schema requiring non-empty `items`; each item has required `preset` (`audit` or `consult`) and nonblank `request`, optional string-array `paths`, and optional nonblank `model`. Close additional properties and reject `edit-targets`, `resume`, unknown presets, empty requests, and malformed values before starting their item. The Pi schema validates structure; retain runtime validation for direct/fake calls. Schema-level invalid batch shape is a tool error with zero children. Semantic item errors return in their own slots. Results always contain `id`, `status` (`success`/`error`), `output` (possibly empty), and `usage` (terminal SDK usage projection or null); errors additionally contain `{code, message}`. Use stable codes `invalid_item`, `timeout`, `cancelled`, `sdk_error`, `missing_result`, `profile_violation`, and `cleanup_failed`. Preserve SDK error subtype in the safe diagnostic when useful. Omit `changed` and raw Claude session ids. Serialize exactly the core result array into text and `details.items`.

2. **Add proposed `src/claude-delegate-prompts.ts::buildClaudeTaskFrame` and `buildClaudeRequest`.** Author small, self-contained embedded frames per `ai-docs/manuals/skill-authoring.md`: audit evaluates the requested artifact and returns severity/evidence/actionable findings; consult answers the posed assumption question with reasoning, uncertainty, and a direct recommendation. Keep task-specific request and optional paths in the user prompt, not the system append. Paths are read targets, not edit authorization or additional-directory grants; relative paths resolve from the captured worktree cwd. Report missing artifact context instead of inventing a complete judgment. Supply neither parent context nor ws render output. Audit each constraints line for the manual's six invariants; avoid schema restatement and broad inherited workflow instructions.

3. **Add proposed `src/claude-sdk.ts::runClaudeItem` and `buildClaudeOptions`; pin the SDK in package manifests.** Use a lazy/injected import of SDK `query`, with a new query per item and the explicitly resolved installed `claude` executable; missing executable/import fails clearly per item rather than changing auth or falling back to a Pi provider. Capture cwd from the current Pi execution context. Reuse the probe's preset/options/env separation, changing only the task frame/request, allowing optional Claude model, and setting both `tools` and `allowedTools` to the five read tools. Set `permissionMode: "dontAsk"`, `strictMcpConfig: true`, `mcpServers: {}`, `settingSources: []`; grant only those exact read-tool names in `canUseTool`, denying everything else. No `bypassPermissions`, plugins, agents, extra directories, resume, or hooks are attached. Use `persistSession: false` for this non-resuming phase and a finite `maxTurns: 20` as an additional per-item cap; the wall timeout remains authoritative. On init, verify inventory is a subset of the exact five read tools and MCP servers are empty; a violation aborts with an item error. Do not claim this inspection is a general sandbox. Retain only final output and terminal usage/modelUsage/cost-estimate fields; exceptions/stderr become bounded diagnostics without dumping env, prompts, session ids, or account data.

4. **Implement proposed `src/claude-delegate.ts::createClaudeDelegateController`, `executeClaudeBatch`, and `allocateClaudeHandle`.** Own one FIFO semaphore with three permits for the session, not a separate three-child pool per invocation. Allocate/reserve a three-lowercase-word stem for every result slot before scheduling, using small explicit word lists with a bounded collision search and a session-local used set; never reuse a stem while that controller exists and fail cleanly on exhaustion. Keep a handle stable across queued/running/settled outcomes. Use `Promise.allSettled` over item jobs, then normalize each outcome into its original index. Each invocation owns its abort listeners and queued jobs; its cancellation cannot abort another invocation. Controller shutdown stops admission, cancels all queues, and awaits active cleanup. No SDK process is parked or stored in the Pi RPC registry.

5. **Implement proposed `src/claude-sdk.ts::disposeClaudeChild` and the controller timeout boundary.** Start the 120-second timer at slot acquisition, covering lazy SDK setup and iteration. Race the consumer against timeout/cancellation so a never-settling fake iterator cannot hang the join. Own a separate AbortController and process handle per item through `spawnClaudeCodeProcess`; pass the SDK's forwarded spawn signal to Node and handle spawn errors. On every terminal path, clear execution timers, abort and close once, detach the caller listener, and observe the consumer's late rejection without mutating an already-settled result. Cleanup has its own at-most-two-second budget: close input/ask for graceful stop first, escalate only that owned child to termination and then SIGKILL before the deadline, wait for exit/stream closure, and release the permit only after confirmed exit. Destroy owned streams and remove owned listeners/timers. If termination cannot be confirmed, report `cleanup_failed` and quarantine that capacity/stop new launches rather than claiming cleanup or oversubscribing. Never await `iterator.return()` or `query.interrupt()` indefinitely, and never kill by executable name or another invocation's PID. Final result settlement includes cleanup, so every item is bounded by execution policy plus cleanup even when SDK cooperation fails.

6. **Wire proposed `registerClaudeDelegate` into `src/index.ts` session lifecycle without changing native spawning.** Construct a session-owned controller/registration using the shared preview ref and current context. Register for the true lead; a fork only gets the definition if its captured active-tool surface already includes it, preserving `computeSessionBootstrap`'s no-reprofile invariant. Worker/explore roles do not acquire it. No subprocess starts at extension factory/registration time. Refresh context and stop any previous controller during session replacement; await controller shutdown in `session_shutdown`. Do not pass bridge handles/session keys/effectivePromptRef to the SDK layer. Add focused integration coverage for actual registration and role/active-tool behavior.

7. **Implement proposed `test/claude-delegate.test.ts`, `test/claude-sdk.test.ts`, and registration coverage using injected fakes, then run package verification.** Cover the scenarios below without live Claude calls. Review source diff for Phase 2/3 drift. The subsequent doc pass records the physical envelope, finite policy, supported presets, handles, and remaining manual acceptance under `ai-docs/spec/pi-adapter-runtime.md`; this research itself edits no spec or ticket.
