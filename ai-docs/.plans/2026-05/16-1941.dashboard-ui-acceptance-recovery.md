Scope: `ws-dashboard/` frontend terminal/explorer/workbench code, daemon-served

## Existing Patterns

- Terminal pane rendering (the bug): `ws-dashboard/frontend/src/App.tsx#L1361-L1398` `TerminalPaneBody`
  dumps PTY output into `<pre className="terminal-output"><code>{pane.output}</code></pre>` and takes
  input from a line-buffered `<input>` + Send button. This is **not** an emulator — ANSI renders raw.
  Phase 3 replaces this body.
- Terminal output polling: `App.tsx#L866-L902` — `window.setInterval` 500ms `fetchTerminalOutput` by
  cursor, appended via `appendTerminalOutput` (`terminals.ts#L180-L189`). Keep the cursor poll; route
  each output delta into `terminal.write(...)` instead of string concat.
- Placeholder/mock terminal surface: `App.tsx#L1190-L1197` static `persistent-terminal` pane is added
  unconditionally to group `primary` with no `body` (`detail: "...command surface reserved."`). This is
  the "mock terminal visible after opening a workRoot". `App.tsx#L1177-L1187` `main-agent` is a sibling
  static placeholder (agent, out of brief scope). Phase 2 removes the terminal placeholder.
- Real terminal panes: `App.tsx#L1309-L1359` `terminalWorkbenchPanesByGroup` / `terminalWorkbenchPane`
  build live panes; `App.tsx#L940-L983` `createTerminalPane` / `sendTerminalDraft` / `closeTerminalPane`.

- New Terminal affordance already exists: `App.tsx#L1089-L1099` toolbar `New terminal` button
  (`data-command-id="terminal.create"`).
- File explorer: `App.tsx#L492-L688` `WorkRootFileExplorer` + `App.tsx#L690-L764` `FileExplorerRow`

## Constraints

- No browser/visual test tooling exists today: `frontend/package.json` test scripts are all
  `tsc` + `node` pure-function runs (`test:routes`, `test:terminals`, `test:workbench`, etc.); both
  prior dogfood artifacts explicitly recorded "no interactive browser or screenshot automation".
  Phase 1 adds the first real browser gate (`playwright` is not installed; `npx` is available).
- The gate cannot use `frontend-dev` (Vite) — it must run against `./dev.sh run` daemon-served
  `frontend/dist`; the ticket rejects Vite-only checks.
- Browser auth is cookie-only via `/pair`; the one-time pairing token is consumed on first use, so a
  gate must pair once per daemon launch and reuse the cookie.
- Daemon delivers PTY bytes as `String::from_utf8_lossy` over 4096-byte reads
  (`terminal.rs#L445-L460`); ANSI escapes are ASCII-safe, but a multibyte UTF-8 character split across
  a read boundary can corrupt — pre-existing, note but do not expand scope to fix it.
- Output transport is HTTP cursor polling (no WebSocket); 500ms `setInterval` poll stays — emulator
  wiring changes the sink (`terminal.write`), not the transport.
- `decideSurfaceOpen` places `persistentTerminal` (pinned) in the focused-then-first group; terminal
  panes and the static placeholder both land in group `primary` as `pinned` — removing the
  placeholder must not disturb `placeTerminalSessions` ordering (`App.tsx#L1261-L1307`).
- Workbench is a hand-rolled React tab model (`WorkbenchEditorGroup`), not Dockview, despite the
  `dockview` dependency and `workbench/dockviewBridge.ts`; terminal-fill CSS work targets the custom
  `.workbench-pane`/`.terminal-pane` tree, not Dockview panels.
- Close-as-terminate must be preserved: `closeTerminalPane` → `closeTerminal` DELETE →
  `terminal.rs#L252-L261` terminates+reaps; the close button is labeled `Terminate`.
- `data-command-id` attributes must be preserved on explorer refresh/expand/select and terminal
  create/input/close controls (command-layer contract).

## Opinion

- Phase 2's tab-selection bug is not obviously a logic defect: `WorkbenchTabLane` wires
  `onClick → onSelectPane → setActivePaneByGroup` uniformly for every tab. The likely real cause is
  re-render churn — `workbenchModel`/`editorGroups` are rebuilt unmemoized on every 500ms output poll
  (`App.tsx#L823-L848`, `#L866-L902`), and `activeTerminalPaneRequest`'s effect (`App.tsx#L925-L938`)
  re-selects on each `editorGroups` identity change, which can fight a user click. Fail-first
  evidence should pin the exact reproduction before editing; budget for it.
- The static `persistent-terminal` placeholder pane (`App.tsx#L1190-L1197`) is the single clearest
  defect: it is unconditional, bodyless, and indistinguishable from a real terminal tab. Removing it
  plus a real empty-workbench state is a small, well-bounded Phase 2 change.
- Phase 3 is the largest slice: it adds `@xterm/xterm` + a fit addon, a new React terminal component
  owning a `Terminal` instance + `ResizeObserver`, output sink rewrite, `onData` input wiring, and
  CSS so the emulator fills `.workbench-pane-body` (currently padded + `overflow:auto`, which fights
  a full-bleed terminal). Consider a terminal-kind CSS branch off the existing `data-surface-kind`
  hook rather than restructuring `.workbench-pane`.
- Brief vs. reality: the brief assumes a runnable `npm run test:browser`/`test:e2e`; none exists and
  Playwright is not installed. Phase 1 genuinely creates this from scratch (new dep, new script, new
  spec file) — not a wiring task. If the execution environment again lacks a browser, the ticket's
  fallback (recorded manual evidence + explicit blocker) is the documented path, consistent with both
  prior dogfood artifacts.
- The file explorer is functional but unconventional: row-click only selects, while expansion needs a
  separate `Expand` button and the directory glyph is non-standard (`·` for files). Phase 4 should
  make the row itself toggle directories and use conventional disclosure affordances; the underlying
  `workRootFiles.ts` pure logic needs no change.
