# Activity Console dogfood Phase 2 survey

Ticket: `260523-bug-ws-dashboard-activity-console-dogfood-usability`
Phase: Phase 2 - Improve compact transcript summaries

## Findings

- `transcriptBlockView` currently chooses `block.title` before text or data, so
  normalized tool blocks rendered by the Codex adapter collapse to generic
  labels even when safe detail exists in `text` and `data`.
- Existing Codex parser output already includes safe fields:
  - tool calls: `data.name`, `data.argumentsBytes`, text `Called <name>`
  - tool results: `data.outputBytes`, text `Tool output captured`
  - unsupported degraded records: category-like title plus bounded safe text/data
- `ActivityTranscriptBlock` renders `view.summary` in a single-line span, so
  Phase 2 can stay inside the view-model helper without changing CSS density.
- Backend parser coverage remains intentionally narrow for Phase 3. Phase 2
  should improve the display of already-normalized data and degraded entries,
  not infer new private native fields on the frontend.

## Implementation Plan

1. Add summary helper functions in `workRootActivity.ts` that safely classify
   generic titles and derive one-line compact text from known safe data fields.
2. Keep terminal and expanded block behavior unchanged.
3. Add focused tests in `workRootActivity.test.ts` for:
   - tool calls showing tool name and argument-byte hint
   - tool results showing output byte hint
   - status blocks showing meaningful text when the title is generic
   - degraded unsupported-like blocks avoiding the generic unsupported title

## Risks

- Frontend must not stringify arbitrary `data` into the one-line summary if that
  could surface backend-native private material. Only known safe scalar fields
  should be summarized.
- Summary selection must avoid turning assistant/output markdown into compact
  blocks or changing exec terminal rendering.
