# Activity Console dogfood Phase 3 survey

Ticket: `260523-bug-ws-dashboard-activity-console-dogfood-usability`
Phase: Phase 3 - Expand Codex prompt and interruption transcript coverage

## Findings

- The current adapter supports only `event_msg/task_started`,
  `event_msg/task_complete`, `event_msg/agent_message`,
  `response_item/function_call`, and `response_item/function_call_output`.
- A key/type-only survey of recent local Codex session JSONL records, with no
  payload content retained, showed frequent unsupported shapes:
  - `event_msg/user_message`
  - `response_item/message`
  - `response_item/custom_tool_call`
  - `response_item/custom_tool_call_output`
  - `event_msg/mcp_tool_call_end`
  - `event_msg/exec_command_end`
  - `event_msg/patch_apply_end`
  - `event_msg/turn_aborted`
  - low-value telemetry/context records such as `token_count`, `session_meta`,
    and `turn_context`
- The public browser contract is already source-neutral. Phase 3 can stay in
  the daemon adapter by mapping these records to `user`, `assistant`,
  `toolCall`, `toolResult`, and `status` blocks with bounded safe metadata.

## Implementation Plan

1. Introduce a parser result that can distinguish supported blocks, deliberately
   skipped low-value telemetry, and unsupported degraded records.
2. Normalize prompt/message records:
   - `event_msg/user_message` -> bounded `user` block.
   - `response_item/message` -> bounded `assistant`/`user` block from known
     content text fields.
3. Normalize activity records without exposing payloads:
   - tool/custom-tool calls -> `toolCall` with safe name and input/argument
     byte count.
   - tool/custom-tool outputs -> `toolResult` with output byte count only.
   - MCP/exec/patch/apply/end/abort records -> compact status/tool result
     blocks with status/duration/exit/success/change-count hints only.
4. Improve unsupported degraded blocks so they include safe event/payload
   category and field counts rather than content-free `unsupported` markers.

## Risks

- Codex native text can contain host paths or session-like tokens. Any visible
  prompt/message text must pass the existing bounded native text redactor.
- Command, MCP, and patch records often contain raw command strings, cwd,
  stdout/stderr, result payloads, or path-bearing change lists. The compact block
  must summarize counts/status only.
