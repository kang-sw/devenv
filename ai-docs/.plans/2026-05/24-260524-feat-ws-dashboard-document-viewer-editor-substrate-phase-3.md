- `ws-dashboard/crates/daemon/src/work_root_files.rs#L224-L236` and `ws-dashboard/frontend/src/workRootFiles.ts#L21-L31` — Possible contract risk: current read response shape lacks `contentHash`; adding write conflict behavior without updating read/front-end types would force implicit or frontend-local base hashes.
- `ws-dashboard/frontend/src/documentViewer.tsx#L326-L333` and `ws-dashboard/frontend/e2e/dashboard-acceptance.spec.ts#L1624-L1629` — Possible test/UI risk: the viewer currently owns a disabled edit segment and the browser gate asserts it is disabled; Phase 3 needs same-pane editing, so this assertion and possibly the control ownership must change together.
- `ws-dashboard/frontend/src/App.tsx#L4274-L4332` and `ws-dashboard/frontend/src/documentViewer.tsx#L46-L52` — Possible stale-overlay risk: translation state is pane-local React state while overlays are keyed by content hash; save fan-out or re-read must invalidate overlay state when content hash changes, not only when translation toggle changes.
- `ws-dashboard/frontend/src/workRootFiles.ts#L207-L228` and `ws-dashboard/frontend/src/workRootFiles.test.ts#L114-L164` — Possible persistence risk: restore intentionally records descriptors only; adding draft/save state could accidentally persist content or dirty state unless tests remain explicit.
- `ws-dashboard/crates/daemon/src/router.rs#L48-L127` — Possible auth risk: the new write/events routes must be added under the protected router; placing them outside the protected nest would bypass the existing owner-auth boundary.
- `ws-dashboard/frontend/src/commands.ts#L24-L58` and `ws-dashboard/frontend/src/commands.test.ts#L50-L125` — Possible command-coverage risk: visible edit/save/revert controls need stable command ids, but current command tests do not include the existing document translation toggle builder; new document commands may need explicit migration-test coverage.
- `ws-dashboard/frontend/src/App.tsx#L2100-L2250` and `ws-dashboard/crates/daemon/src/work_root_activity.rs#L238-L263` — Possible reuse risk: Activity streaming is source-specific and feed/transcript shaped; document events can reuse SSE lifecycle patterns, but not Activity event payload semantics or transcript-specific fallback behavior.
- `ws-dashboard/frontend/src/App.tsx#L429-L551` and `ws-dashboard/frontend/src/App.tsx#L498-L519` — Possible fan-out risk: file-open logic deletes preview panes when pinning and stale fetch guards compare open requests; source-keyed save fan-out must not accidentally update a replaced preview or miss a pinned pane for the same `workRootId + path`.
- `ws-dashboard/crates/daemon/src/work_root_files.rs#L377-L429` — Possible write-safety risk: read canonicalizes an existing target before checking containment; a write route for new or changed bytes may need containment validation that does not rely on a target already existing, especially while create-file is out of scope.
