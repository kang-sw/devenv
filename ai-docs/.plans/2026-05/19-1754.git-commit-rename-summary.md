# Survey: 260515-bug-git-commit-rename-status-summary

## Reusable Components
- `agents-plugin-tool/internal/wsgit/git.go#L422-L430` — `TicketChange`: existing structured ticket-change result already has `path`, `old_path`, `from_status`, `to_status`, and result-heading fields needed by the brief.
- `agents-plugin-tool/internal/wsgit/git.go#L707-L734` — `detectTicketChanges`: central summary-layer merger of cached `--name-status` ticket changes with cached result/edition heading detection.
- `agents-plugin-tool/internal/wsgit/git.go#L736-L766` — `parseTicketNameStatus`: existing parser for cached ticket name-status records and native `R...` rename preservation.
- `agents-plugin-tool/internal/wsgit/git.go#L768-L792` — `parseTicketResultAdditions` / `isAddedTicketResultHeading`: existing narrow `+### Result` and `+#### Edition` detection keyed from ticket diff paths.
- `agents-plugin-tool/internal/wsgit/git.go#L794-L824` — `ticketChangeForPath` / `ticketStatusStem`: recognized ticket-status and stem parser for `ai-docs/tickets/{idea,todo,ready,wip,.done,.dropped}/*.md`.
- `agents-plugin-tool/internal/wsgit/git.go#L826-L846` — `ticketChangeKey` / `ticketChangeSummaries`: stem-keyed merge and commit-message summary rendering already produce `moved from -> to` once statuses are populated.

## Existing Patterns
- Native rename parsing: see `agents-plugin-tool/internal/wsgit/git.go#L746-L763` and `agents-plugin-tool/internal/wsgit/git_test.go#L433-L453` — `R100` records use old path status as `FromStatus` and destination path status as `ToStatus`.
- Result/Edition tests are parser-level and compact: see `agents-plugin-tool/internal/wsgit/git_test.go#L455-L467` — direct parser tests cover heading extraction without full Git repos.
- Full commit flow uses runner output sequencing: see `agents-plugin-tool/internal/wsgit/git_test.go#L222-L264` and `agents-plugin-tool/internal/wsgit/git_test.go#L469-L492` — `sequenceRunner` can exercise `detectTicketChanges` integration through `Commit` without shelling out.
- Ticket move staging already matches same-stem add/delete worktree shape before commit: see `agents-plugin-tool/internal/wsgit/git.go#L609-L640` and `agents-plugin-tool/internal/wsgit/git_test.go#L334-L386` — this is staging expansion, separate from cached summary reconstruction.
- MCP text rendering consumes `TicketChange` fields directly: see `agents-plugin-tool/internal/mcp/server.go#L1130-L1158` — no schema change appears needed if core `TicketChanges` are corrected.

## Relevant Interfaces
- `agents-plugin-tool/internal/wsgit/git.go#L404-L419` — `CommitOptions` / `CommitResult`: `git.commit` returns `TicketChanges` and auto-fills `UpdatedTickets` when caller omits them.
- `agents-plugin-tool/internal/wsgit/git.go#L432-L469` — `Client.Commit`: calls `detectTicketChanges` after staging validation and before commit-message construction.
- `agents-plugin-tool/internal/mcp/server.go#L1818-L1835` — `git.commit` MCP schema: `updated_tickets` remains optional; detected ticket moves and Result/Edition headings are documented in the property help text.
- `agents-plugin-tool/internal/mcp/server_test.go#L1180-L1229` — existing MCP `git.commit` smoke test: JSON and text response assertions are available if end-to-end coverage becomes necessary.

## Constraints
- `ai-docs/spec/mcp-tools.md#L218-L227` — planned contract is conservative: reconstruct only unambiguous same-stem ticket add/delete status moves; ambiguous sets remain non-move changes.
- `ai-docs/mental-model/git-workflow-tools.md#L20-L24` — `git.commit` stages explicit paths, expands ticket moves by stem, rejects unrelated staged paths, detects Result/Edition additions from cached diffs, then builds a structured message.
- `ai-docs/mental-model/git-workflow-tools.md#L39-L41` — ticket move expansion depends on `ai-docs/tickets/{ready,todo,idea,.done,.dropped}` with legacy `wip` accepted for old-path detection.
- `agents-plugin-tool/internal/wsgit/git.go#L589-L606` — commit validation rejects unrelated staged paths and empty staged commits before ticket summary detection.
- `agents-plugin-tool/internal/wsgit/git.go#L826-L831` — current merge key is only stem when present, so multiple add/delete records with the same stem can overwrite each other unless ambiguity is handled before map insertion.

## Opinion
- The implementation surface is narrow and likely belongs entirely in `internal/wsgit`; MCP/CLI surfaces should naturally inherit corrected `TicketChange` data.
- Main risk is the current stem-only `changes` map in `detectTicketChanges`, which can lose evidence before ambiguity checks if raw add/delete records are inserted one by one.
- `ws/mental_models.find` for git commit ticket Result/Edition move summary returned no extra entries beyond the explicit `git-workflow-tools` reference.
