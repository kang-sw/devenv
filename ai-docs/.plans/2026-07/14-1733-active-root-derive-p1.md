# Plan: 260714-refactor-dashboard-active-root-atomic-select-pure-derivation — Phase 1: Pure deriveWorkbenchView seam + mount-by-construction + delete active-root refs

## Relevant Ticket Contract
- D1: `openWorkRootInstances` is derived from the render-time union of persisted `openWorkRootKeys` and the selected root's key via `withOpenWorkRootKey(openWorkRootKeys, selectedRootKey)` — append-if-absent, position-preserving. Never filter-then-append. The selected entry's `{rootId, serverRoute}` comes from `selection.root` (freshly resolved), not the lagging `openWorkRootRefs`.
- D2: the union's selected-root entry resolves through `resolveActiveResources` (the same fallback-bearing path as `activeResources`), not raw `resourcesByServer[serverRoute]`. Keep-alive (non-selected) instances keep resolving via the raw per-server map.
- D3: `effectiveActiveRootKey` becomes pure — the selected root's key when selection resolves, else `null`. Delete `lastActiveRootKeyRef`, `lastActiveRootServerIdRef`, their advance block, their close-time reset, and the fallback branches of `resolveEffectiveActiveRootKey`.
- D5: `lastNonNullResourcesByServer` (ref-backed) stays exactly as-is in Phase 1; do not conflate it with the refs being deleted.
- D6: test oracle is `tsc` + node pure-logic only (no jsdom/RTL/Playwright). `deriveWorkbenchView(committedState)` takes the exact single-render committed-state slice `{ resourcesByServer, lastNonNullResourcesByServer, selectedServerId, selectedId, openWorkRootKeys, openWorkRootRefs }` and returns `{ activeResources, selectedRootKey, openInstanceKeys, effectiveActiveRootKey }`. Include the cross-render position-preserving-prefix proxy unit.
- Phase 1 body: add D7's `resolveRootLayout(rootKey, workbenchGroupsByRoot, paneOrderByRoot, activePaneByRoot, restoreSnapshot)` and route `buildEditorGroupsForRoot`'s reads (App.tsx:4269-4270) and the per-instance `effectiveActivePaneByGroup` read (App.tsx:5988) through it. Leave the stateful seeding effects (App.tsx:815-826, 3826-3835) in place.
- Ordering constraint (Migration risk section): the union and the ref-deletion MUST land in one reviewable commit — splitting them transiently reopens failure modes #1-#4.
- Constraints: scope-bounded to `App.tsx` selection handlers + `WorkbenchShell` active-root derivation, `workbench/openRootLookup.ts`, and the pure helpers in `resourceModel.ts`. Do not rewrite Dockview integration/pane lifecycle/resource-fetch layer. Do not touch the `server.off` teardown contract beyond removing the ref reset block.
- Verification boundary (Phase 1): `npm run build`, `test:workbench`, `test:resource-model`, `test:commands`, `test:open-work-root` all pass; live dogfooding is the final gate for reconciliation/paint-timing properties the pure oracle cannot see (explicitly out of this phase's automated scope).
