# Plan: Left-nav work-root rows — two-line layout with open-surface counts, and open-vs-closed de-emphasis — Phase 1: Two-line work-root row with open-surface counts and open-state de-emphasis

## Relevant Ticket Contract

- Two changes land together in the same component (`ResourceRow`/`WorkspaceGroup` in `App.tsx`) and the same CSS block: (1) a reserved second line under the row title showing open-terminal/open-document counts for that root, (2) an `isOpenWorkRoot`-driven de-emphasis of not-open rows via reduced saturation and slight brightness drop.
- Ship terminal and document counts only. Agent counts are explicitly deferred (`## Deferred scope`) — do not invent a data source for `SurfaceKind: "agent"`/`"agentChat"`, and do not consume the row's only free overlay affordance (`background`), which a future phase needs for an attention-flash pseudo-element.
- Counts come from real per-root sources, not `paneOrderByRoot` (its own in-source CONTRACT excludes terminal/readonly-file panes).
- Prefer `isOpenWorkRoot` as a `data-*` attribute (CSS-only, matches the four existing `data-resource-*` attributes, gives the browser suite a selector) over a class-string branch.
- Prefer token-level `color-mix` on the row's own background/foreground over `filter: saturate()` (filter affects every descendant and creates a stacking context that can interact with `.resource-row-drag-over`'s inset box-shadow).
- Express 65:35 proportion via type scale + existing grid `gap`, not `grid-template-rows` percentages.
- Reserve the secondary line's height uniformly across open/closed states of the *same* presentation (no visible row-height jump on open/close).
- Row must stay drag-reorderable; the new line must not create a drag dead-zone or swallow `resource.select`.
- Verification boundary: the dashboard browser acceptance gate (`npm run test:browser`) is the closing gate; `frontend/e2e/dashboard-acceptance.spec.ts` runs `test.describe.configure({ mode: "serial" })`.

## Out of Scope

- Agent/`agentChat` surface counts and the split working/ready sub-count UI (deferred; owned by a later phase once `260725-research-ws-dashboard-pty-agent-pivot` settles surface identity).
- The Windows-11-style attention-flash overlay (future phase; Phase 1 must only avoid blocking it).
- Folding `.nav-secondary-context` ("N pinned main surface(s)") into the new line — ticket default is to keep them separate in this phase.
- Any change to `workspace`-presentation rows beyond leaving them at current behavior (see Decision 4 below).
- Non-CSS-only saturation trickery (`filter`), per the ticket's explicit preference.
