# Plan: 260525-feat-ws-dashboard-server-scoped-operation-forwarding — Phase 5: Remote Activity, Git, workspace, and WorkRoot mutations

## Relevant Ticket Contract
- Forward WorkRoot Activity snapshots, transcript reads, Activity event SSE, activation changes, workspace removal, Git toolbar operations, and Git worktree-add operations through Server Route-scoped routes.
- Activity stream keys and transcript lookups must include `serverRoute`. Git and workspace mutation responses that include resources must be rewritten to the linked Server Route. Git worktree path previews and error messages are remote host paths and should be presented as such.
- Deferred scope: agent control actions (interrupt, cancel, erase, retry, terminate). This phase covers existing read/activity and practical WorkRoot/Git operations only.
- Naming/validation: land already reading as `serverRoute`/`server_route` with dot-free validation in place (draft source predates the rename and uses `server_id`; apply the rename inside each cherry-pick, per phase, not as a separate pass).
- Reuse draft source commits `6f9fc757`, `15ff7df0`, `c3ef069a` (oldest first) from the phase-7 reference worktree (`/home/swkang/devenv/.worktree/dashboard-server-scoped-forwarding-phase-7`, branch `implement/dashboard-server-scoped-forwarding-phase-7`) rather than reimplementing; re-author docs/spec/closeout against current docs.
- Backend forwarding must stay allowlisted: register explicit server-scoped routes only. Do not add a wildcard proxy.
- Mutating remote operations (Git branch changes, fetch/push/pull, activation changes, workspace removal, Git worktree add) must preserve owner-auth gating at the local gateway and bearer auth to the linked daemon.
- Activity event SSE requires proxying stream semantics (same mechanism class as Phase 4's document-event SSE), not one-shot fetch forwarding.
- Frontend: Server Route-scoped operations must avoid bare-id collisions — pane keys, Git toolbar state, Activity stream keys, and any persisted UI state must include `serverRoute` where the same `workRootId`/`workspaceId`/`activityId` could exist on more than one server. Existing local-only frontend helpers should accept `serverRoute` rather than doing ad hoc URL construction in components.

## Out of Scope
- Terminal HTTP lifecycle and terminal WebSocket forwarding — Phase 6/7.
- Agent control actions (interrupt/cancel/erase/retry/terminate).
- Document translation provider forwarding (already deferred, Phase 4 note applies unchanged).
- Recursive/multi-hop federation.
