# Plan: 260525-feat-ws-dashboard-server-scoped-operation-forwarding — Phase 6: Remote terminal HTTP lifecycle

## Relevant Ticket Contract
- Forward terminal creation, list, output polling, input, resize, and close through Server Route-scoped terminal routes before adding the live WebSocket gateway (Phase 7).
- Terminal panes must carry Server Route identity, and gateway terminal routing must prevent terminal id collisions across linked servers (terminal ids remain daemon-local opaque ids; do not synthesize gateway-side ids — carry `serverRoute` alongside the id in frontend/pane state instead).
- HTTP terminal routes use the same linked-server auth, refusal, and bounded-error behavior as other forwarded operations (reuse Phase 2's resolver/forwarding helper).
- Closing a remote terminal through the local gateway must close the upstream terminal; local terminal behavior must remain unchanged.
- Deferred scope: WebSocket live transport (Phase 7), larger terminal UX redesign, native-Windows control-key polish.
- Naming/validation: land already reading as `serverRoute`/`server_route` with dot-free validation in place.
- Reuse draft source commits `fd51c06d`, `a2af58b1`, `c4231ea5` (oldest first) from `/home/swkang/devenv/.worktree/dashboard-server-scoped-forwarding-phase-7` (branch `implement/dashboard-server-scoped-forwarding-phase-7`) as a design reference; re-implement onto the current tree rather than mechanically cherry-picking (naming/structure has diverged since Phases 1-5 landed).
- Backend forwarding must stay allowlisted; the terminal *socket* route must remain unregistered/deferred this phase (Phase 7's job).

## Out of Scope
- Terminal WebSocket upgrade/live transport — Phase 7 only.
- Agent control actions, document translation, multi-hop federation.
- Terminal UX redesign, control-key polish.
