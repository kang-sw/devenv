# Plan: 260701-feat-write-ticket-lever-b-mcp-tools — Phase 2: Sage gate-resolve and record MCP tools

## Relevant Ticket Contract
- Two tools, drawn so both decision logic AND write-side output artifacts leave the playbook:
  - `ws/tickets.sage_gate(stem, landing) -> { action, ask_prompt?, reviewers?, mode? }`, `action ∈ skip | stop_blocked | ask | run`. Owns posture resolution, legacy `sage-review:` → dual-field migration, `config.show` fallback, the category×stage matrix, and standalone/combined mode selection. Does not spawn.
  - `ws/tickets.sage_record(stem, stage, verdicts)` — aggregates verdicts (incl. `resolution: missing` escalation), writes the resolved frontmatter posture, renders any Blocked section from a Go-owned template, commits, and returns the applied posture + commit ref. Mirrors `enter.implement`'s `raw`/`next_instruction` verbatim-follow contract.
- Reviewer spawning stays lead-owned (an MCP tool cannot spawn subagents), collapsed to one parameterized `On: Reviewer Spawn` block.

- Constraint: this phase edits `agents-plugin/rsrc/lead-write-ticket/lead-write-ticket.md` directly — wires the new tools in AND deletes the superseded ~235-line sage block + three templates in the same phase.
- Constraint: spec addressing is closeout-style (contract-first: no) — document the built contract in `ai-docs/spec/mcp-tools.md` after implementation, not before.
- Verification (from ticket): exercise sage review across all posture values, the category×stage matrix, and both aggregation paths against the new tools; confirm frontmatter, Blocked-section text, and commit output match today's behavior exactly before deleting the corresponding prose.
