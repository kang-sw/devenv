# Plan: 260525-feat-ws-dashboard-server-scoped-operation-forwarding — Phase 1: Frontend Server Route identity and endpoint helpers

## Relevant Ticket Contract
- Introduce frontend route helper APIs for every canonical Server Route-scoped dashboard operation the ticket will forward; callers pass a `serverRoute` or a full `ResourcePath`, and components stop constructing server-sensitive API URLs inline. Canonical shapes: `/api/dashboard/servers/{serverRoute}/root-picker[/directories|/pins]`, `/work-roots/open`, `/workspaces/{workspaceId}/...`, `/work-roots/{workRootId}/...`, `/terminals/{terminalId}/...`.
- Define collision-safe frontend identities for workbench panes, file pane source keys, file explorer snapshots, document event subscriptions, Activity streams, Git state, terminal panes, terminal restore intents, command payloads, and persisted UI records: the same `workRootId`/`workspaceId`/`activityId`/`terminalId` on two servers must produce distinct UI state. Existing local-only persisted records may be migrated to `server-local` or dropped with a bounded compatibility decision.
- Reuse the already-written Phase 1 source commits (oldest first) `2954a622`, `9c169d1c`, `bfab8b7b` from `implement/dashboard-server-scoped-forwarding-phase-7` rather than reimplementing (Implementation Strategy). Do not replay that branch's docs/plan/closeout commits.
- Naming + dot-free validation land incrementally *inside* this phase's cherry-pick, not as a separate pass: the landed diff must already read as `serverRoute`/`server_route` with dot-free route-segment validation. Source commits predate this and use `serverId`/`server_id` with no dot rejection (Decisions; Implementation Strategy).
- `serverRoute` is the canonical browser-visible daemon routing identity. Existing JSON/resource fields named `serverId` (e.g. `ResourcePath.serverId`) are compatibility field names that carry the selected Server Route — do NOT rename the wire field (Decisions).
- Direct linked-server route segments must be dot-free (`[A-Za-z0-9_-]+`); dot is reserved as a future hop separator. Reject new linked-server requests whose requested Server Route contains a dot; do not silently rewrite existing persisted dotted values (Decisions/Constraints).
- Completion also requires drafting the `ai-docs/spec/ws-web-dashboard/index.md` contract entry for the canonical route shapes and `serverRoute` naming (Spec Impact) so Phase 2 forwards against a written contract.

## Out of Scope
- Backend remote forwarding, one-shot JSON forwarding helper, `server-local` in-process aliasing, and resource-view rewriting (Phase 2).
- SSE proxying (document/Activity events) and terminal WebSocket gatewaying (Phases 4/5/7). Phase 1 may add route-construction and identity tests only.
- Authoritative backend rejection of dotted linked-server route requests (the request hits `/api/dashboard/servers/link`, a backend route — Phase 2+). Phase 1 covers only frontend-side dot-free guarding on route construction and the add form.
- Router/terminal backend files called out as conflict-prone in the ticket (`daemon/src/router.rs`, `daemon/src/terminal.rs`) are backend and not touched by Phase 1 commits.
