# Plan: 260726-refactor-ws-dashboard-long-uptime-leak-hardening — Phase 1: Kill the handshake-failure orphan, unpark exited sessions on their own grace, backstop with a periodic sweep

## Relevant Ticket Contract

- Sub-fix 1: on `connect_and_handshake` returning `None` in `TerminalSession::spawn`, read the just-written `<id>.json` for pid+start_time, `terminal_platform::kill_verified` it, remove the stale `.sock`/`.json`, then return `Err` — no scanner needed for this case.
- Sub-fix 2: bound how long the helper's `serve_connections` accept loop waits for the first successful handshake before self-exiting, independent of the daemon (covers daemon-crashes-before-connect).
- Sub-fix 3: a periodic backstop sweep must, once `admits_attach()` goes false for a session (never before): (a) actually close the IPC connection — abort/signal the reader task and shut down `write_half`, not just drop the session out of the map; (b) confirm the shell child is `wait()`ed on Unix (Windows already correct). The sweep also re-scans the registry dir for orphaned `<id>.json`/`.sock` with no live session, excluding entries younger than the connect/handshake timeout, and never adopts (kill-only).
- Any daemon-initiated kill of a registry entry MUST route through `terminal_platform::kill_verified` (never a bare pid kill).
- The 30s attach-grace contract (`terminal.rs:41-45`, `admits_attach()`) is authoritative for when an `Exited` session may be evicted — neither the lazy `retain(is_live)` path nor the new sweep may drop/disconnect a session before `admits_attach()` goes false.
- Interval and shutdown safety: must pick and state a concrete sweep interval; the sweep task must be cancelled as part of (or strictly before) the daemon's shutdown path (`server.rs:145`).
- Verification boundary (ticket-stated): no orphaned helper process/fd/`.json`/`.sock` survives past the connect timeout (sub-fix 1) or past the helper's own no-handshake timeout (sub-fix 2) even with the daemon down; a terminal whose shell exits keeps its attach grace for the full 30s, then is reaped (connection closed, no zombie, fd released) within one sweep interval after grace expires, without a new `create_terminal`; open/mid-creation terminals are unaffected by the sweep.

## Out of Scope

- Phase 2 (git `GIT_TERMINAL_PROMPT=0`, process-group containment, unkillable-child detection) and Phase 3 (`DocumentWriteLocks` eviction, WS heartbeat, reqwest timeout) — separate phases, not touched here.
- `boot_reconcile`'s adopt path and its 6-row table — the sweep must never call it or reuse its adopt branches; only its `identity_status`/`kill_verified` building blocks are candidates for reuse.
- Windows-specific zombie reaping — already correct per the ticket; no Unix-only fix should be gated in a way that regresses Windows, but no new Windows work is required.
- The already-struck single-flight item and the already-shipped `git_exec::capture` bounded-timeout work (both explicitly out of Phase 1).

## Codebase Findings

- `ws-dashboard/crates/daemon/src/terminal.rs#L874-881` — `TerminalSession::spawn`: on `connect_and_handshake(...).ok_or(...)?` returning `None`, nothing kills the just-spawned helper. `id` and `registry_dir` are already in scope at this point (sub-fix 1's exact call site).
- `ws-dashboard/crates/daemon/src/terminal.rs#L221-270` (`reconcile_entry`) — existing pattern to mirror for sub-fix 1's kill: `ReconcileRow::KillVerified` branch does `tokio::task::spawn_blocking(move || crate::terminal_platform::kill_verified(pid, start_time)).await` then `delete_registry_entry(&self.registry_dir, &entry.terminal_id)`. Reuse this exact shape (or extract it into a shared `pub(crate) async fn kill_verified_and_delete_entry(registry_dir, terminal_id, pid, start_time)` helper on `TerminalRegistry`/free fn, since sub-fix 1 and the sweep's registry-dir backstop both need the identical kill+delete sequence).
- `ws-dashboard/crates/daemon/src/terminal_registry_file.rs#L29-71` — `registry_entry_path`, `delete_registry_entry` (already prunes both `.json` and `.sock`, see its own CONTRACT comment) are ready to reuse. There is **no existing single-entry read function** — only `scan_registry_dir` (whole-directory scan). Sub-fix 1 needs to read exactly one `<id>.json`; add a small `pub fn read_registry_entry(registry_dir: &Path, terminal_id: &str) -> Option<TerminalRegistryEntry>` here (mirrors `scan_registry_dir`'s per-file parse logic, minus the directory iteration) rather than duplicating JSON-read logic inline in `terminal.rs`.
- `ws-dashboard/crates/daemon/src/terminal_helper_process.rs#L220-252` (`serve_connections`) — the accept loop's `wait` is `IDLE_ACCEPT_POLL` (2s) whenever `shared.exited_at()` is `None`, looping forever with no bound. `shared.shell_started` (`AtomicBool`, flipped exactly once on receiving `HandshakeAck`, `:316-321`) already doubles as "has a handshake ever completed" — no new state needed. Sub-fix 2: track an `Instant` captured at `serve_connections` entry (helper process start), and when `shell_started` is still `false`, bound `wait` by a new `NO_HANDSHAKE_TIMEOUT` constant (propose `Duration::from_secs(10)` — comfortably above the daemon's own `DEFAULT_CONNECT_TIMEOUT` of 3s at `terminal.rs:46`, giving margin for retry/backoff — flag as an executor-adjustable constant, not a hard ticket number). On elapsed, `break` the loop the same way the existing `GRACE_WINDOW` exhaustion path already does (`:229`), which flows into the same `kill_shell_if_running()` + `delete_registry_entry` + socket cleanup already at `run_terminal_helper`'s `:214-217`.
- `ws-dashboard/crates/daemon/src/terminal_helper_process.rs#L150-160` (`SharedState::transition`) — on a `Running -> non-Running` transition it already tears down `master`/`writer_tx` but never touches `self.child` — no `wait()`. This is the Unix-EOF-path zombie finding (sub-fix 3b): `spawn_reader_thread`'s `Ok(0)` branch (`:590`) calls `shared.transition(TerminalHelperStatus::Exited)` without reaping. Fix: inside `transition()`'s existing `if ring.status == Running` guard, also `self.child.lock()...take()` and `.wait()` it (skip `.kill()` — the child already exited on its own; mirrors `kill_shell_if_running`'s take-then-wait shape at `:134-137` minus the kill). Centralizing in `transition()` (not just the reader thread) covers every self-detected-exit path uniformly, including the Windows reaper (`:624-629`), which the ticket already says is correct today — an extra idempotent `wait()` there is harmless.
- `ws-dashboard/crates/daemon/src/terminal.rs#L1120-1156` (`spawn_ipc_reader_task`) — fire-and-forget `tokio::spawn`, return type `()`. No handle is retained anywhere, so nothing can ever cancel this task from outside — this is the exact mechanism the ticket's "closing the connection... daemon already has this Arc clone alive" finding refers to. Needs to return the `JoinHandle` so the caller can store it.
- `ws-dashboard/crates/daemon/src/terminal.rs#L442-453` (`TerminalSession` struct) — `write_half: Arc<AsyncMutex<IpcWriteHalf>>` already exists and is reachable for a shutdown call; no field currently holds the reader task's `JoinHandle`. Add `reader_task: Mutex<Option<tokio::task::JoinHandle<()>>>`, populated in `from_connection` (`:895-928`) right after `spawn_ipc_reader_task` is called.
- `ws-dashboard/crates/daemon/src/terminal_ipc_transport.rs#L26-27` — `IpcReadHalf`/`IpcWriteHalf` are `tokio::io::split()` halves (generic `ReadHalf`/`WriteHalf<BoxedIpcStream>`, not a socket-specific split). These share the underlying stream via internal shared state, so **dropping only one half does not close the underlying socket** — both the reader task's `IpcReadHalf` (via abort) and `write_half`'s `.shutdown()` (via `tokio::io::AsyncWriteExt`, not currently imported in `terminal.rs`) must both happen, exactly as the ticket's sub-fix 3(a) phrasing ("abort... AND shut down write_half") states. A `write_half.shutdown()` half-closes the Unix socket, which is what makes the helper's `reader.read_message()` observe EOF (`None => return Ok(true)` at `terminal_helper_process.rs:315`) and fall through to the already-existing `if shared.exited_at().is_some() { break; }` check (`:243-245`) — no new helper-side logic needed for the daemon-initiated-disconnect path; it already self-exits once disconnected post-exit.
- `ws-dashboard/crates/daemon/src/terminal.rs#L290-301` (`insert`) and `#L330-362` (`remove_for_work_roots`, `drain_all`) — existing precedent for the registry's "remove-and-return-for-caller-to-kill" contract the sweep's eviction step should follow (`retain` + collect removed `Arc<TerminalSession>`, same shape as `remove_for_work_roots#L339-346`).
- `ws-dashboard/crates/daemon/src/terminal.rs#L364-370` (`identity_status`) and `#L386-440` (`connect_and_handshake`) — both private free functions in `terminal.rs`, reusable in-module by the sweep's registry-dir backstop without visibility changes, provided the sweep's driver logic also lives in `terminal.rs` (as an `impl TerminalRegistry` method) rather than a fully separate module needing these as `pub(crate)`.
- `ws-dashboard/crates/daemon/src/terminal_reconcile.rs` (whole file) — established precedent for splitting *pure* decision logic from the async driver (`classify`, unit-tested with no I/O). The sweep's own decision ("this registry-dir entry has no live session, is older than `connect_timeout`, and identity verifies-ours → kill-only") is structurally the same shape as this table's `KillVerified`/`DropNoSuchProcess`/`DropPidReused` rows minus the `Adopt*` rows (a sweep never adopts). Consider whether to extend `terminal_reconcile.rs` with a narrower "sweep row" classifier reusing `IdentityStatus`, or keep it inline in the new sweep code — either is compact; do not duplicate the identity-status enum.
- `ws-dashboard/crates/daemon/src/server.rs#L94-104` — `TerminalRegistry::boot_reconcile(...)` construction site; the periodic sweep task should be spawned immediately after this, using the constructed `terminals` (clone before it moves into `AppState` at `:122-143`, since `TerminalRegistry` is `#[derive(Clone)]` at `terminal.rs:151`).
- `ws-dashboard/crates/daemon/src/server.rs#L144-169` — existing `shutdown_task` spawn + `.abort()` pattern at both `tokio::select!` branches (`:159` on normal server completion, `:164` on forced-grace-period shutdown) is the exact idiom to mirror for the new sweep task's `JoinHandle`: store it, `.abort()` it at both of the same two call sites. No `tokio-util::CancellationToken` is used anywhere in this crate (confirmed via search) — plain `JoinHandle::abort()` matches existing style, don't introduce a new dependency for this.
- `ws-dashboard/crates/daemon/tests/terminal_lifetime.rs` — real-process integration harness (`spawn_real_daemon`, `create_terminal`, `poll_output_until_contains`, a `delayed_exit_marker_command` helper for inducing a shell exit after a delay, and a Unix `proc_start_time` helper at `:650` for asserting a pid is actually gone). This is the right test shape/location for Phase 1's verification (induce a handshake failure or an exited-shell-plus-grace-expiry scenario against the real spawned daemon binary), not a new harness.
- **Risk signal (module placement):** `terminal.rs` is already ~1970 lines with many split-out `terminal_*` sibling modules (`terminal_reconcile.rs`, `terminal_registry_file.rs`, `terminal_platform.rs`, `terminal_helper_process.rs`, `terminal_ipc_transport.rs`, `terminal_helper_protocol.rs`, `terminal_helper_ipc.rs`). A new `terminal_reaper.rs` module (owning only the `tokio::time::interval` loop + spawn/abort glue, calling a `TerminalRegistry::sweep_once()` method whose body stays in `terminal.rs` next to the private fns it needs) fits this established split better than growing `terminal.rs` further or inventing a differently-shaped module. Flagging as a design choice, not a hard requirement — the executor may keep it in `terminal.rs` if that stays simpler in practice.
- **Risk signal (backstop scope):** the ticket's phrasing "must exclude an entry younger than the handshake timeout" and "a runtime sweep only kills, it never adopts" together imply the sweep's registry-dir backstop should skip `connect_and_handshake` entirely (unlike `boot_reconcile`'s `reconcile_entry`, which does attempt a connect) — it only needs `identity_status` + age-check before a kill. Getting this backwards (attempting a full handshake) would silently reintroduce an adopt-shaped code path the ticket explicitly forbids for the sweep.

## Implementation Plan

1. `ws-dashboard/crates/daemon/src/terminal_registry_file.rs` — add `pub fn read_registry_entry(registry_dir: &Path, terminal_id: &str) -> Option<TerminalRegistryEntry>`, factored out of `scan_registry_dir`'s per-file read+parse (`:98-101`).
2. `ws-dashboard/crates/daemon/src/terminal.rs` (`TerminalSession::spawn`, `:874-881`) — sub-fix 1: on `connect_and_handshake` returning `None`, before returning `Err`: `spawn_blocking` a `read_registry_entry(registry_dir, &id)` read; if `Some(entry)`, `spawn_blocking` a `terminal_platform::kill_verified(entry.pid, entry.start_time)` call (mirror `reconcile_entry`'s `KillVerified` branch shape, `:257-264`), then `delete_registry_entry(registry_dir, &id)` regardless of whether an entry was found (covers the "never even wrote the file" edge too). Consider extracting the kill+delete pair into one shared helper reused by both this call site and item 5 below.
3. `ws-dashboard/crates/daemon/src/terminal_helper_process.rs` — sub-fix 2: add `const NO_HANDSHAKE_TIMEOUT: Duration = Duration::from_secs(10);` near `GRACE_WINDOW`/`IDLE_ACCEPT_POLL` (`:32-33`). In `serve_connections` (`:220-252`), capture `let started_at = Instant::now();` once at function entry, and extend the `wait` match's `None` arm (currently unconditionally `IDLE_ACCEPT_POLL`, `:231`) to check `shared.shell_started.load(Ordering::SeqCst)`: if `false`, use `NO_HANDSHAKE_TIMEOUT.checked_sub(started_at.elapsed())`, `break`ing the loop when it returns `None` (same `break` shape already used for grace exhaustion at `:229-230`); if `true` (handshake already happened at least once, shell may still be running with no current connection), keep the existing `IDLE_ACCEPT_POLL` behavior unchanged.
4. `ws-dashboard/crates/daemon/src/terminal_helper_process.rs` (`SharedState::transition`, `:150-160`) — sub-fix 3b: inside the existing `if ring.status == Running` guard, add `if let Some(mut child) = self.child.lock().expect("child lock poisoned").take() { let _ = child.wait(); }` (take-then-wait, no kill, since the transition already means the child exited on its own) alongside the existing `master`/`writer_tx` teardown.
5. `ws-dashboard/crates/daemon/src/terminal.rs` — sub-fix 3a groundwork:
   - Change `spawn_ipc_reader_task` (`:1120-1156`) to return `tokio::task::JoinHandle<()>` (drop the `tokio::spawn(...)` statement's trailing `;`, return the handle).
   - Add `reader_task: Mutex<Option<tokio::task::JoinHandle<()>>>` to `TerminalSession` (`:442-453`); in `from_connection` (`:895-928`), store the handle returned by `spawn_ipc_reader_task` into this field right after the existing call.
   - Add `use tokio::io::AsyncWriteExt;` to the top imports.
   - Add `async fn close_ipc_connection(&self)` on `TerminalSession`: `.take()` + `.abort()` the `reader_task` handle if present, then lock `write_half` and call `.shutdown().await` on it (discard the result — an already-broken pipe is expected/harmless, matching the existing `let _ = write_ndjson(...)` discard style used elsewhere in this file).
6. `ws-dashboard/crates/daemon/src/terminal.rs` — sub-fix 3, eviction step: add `pub(crate) fn sweep_evict_expired(&self) -> Vec<Arc<TerminalSession>>` on `TerminalRegistry`, mirroring `remove_for_work_roots`'s retain-and-collect shape (`:330-348`) but keyed on `!session.admits_attach()` instead of work-root membership — this is the only correct gate per the ticket's grace-authority decision (never `!is_live()` alone, which would evict before grace expires).
7. `ws-dashboard/crates/daemon/src/terminal.rs` — sub-fix 3, registry-dir backstop: add `pub(crate) async fn sweep_registry_backstop(&self)` on `TerminalRegistry`: `spawn_blocking` a `scan_registry_dir(&self.registry_dir)`, then for each entry whose `terminal_id` is **not** a live key in `self.sessions` (snapshot the current key set under the read lock first) **and** `now_ms().saturating_sub(entry.created_at_ms) > self.connect_timeout.as_millis() as u64`: compute `identity_status(entry.pid, entry.start_time)` (reuse as-is, no `connect_and_handshake` attempt per the "never adopts" constraint); if `VerifiedOurs`, kill+delete via the same helper as item 2; otherwise (`NoSuchProcess`/`PidReused`) `delete_registry_entry` only, never kill (mirrors `reconcile_entry`'s three-line invariant, `:221-230`).
8. `ws-dashboard/crates/daemon/src/terminal.rs`, combine into one entry point: `pub(crate) async fn sweep_once(&self)` calling, in order: `sweep_evict_expired()` then `close_ipc_connection().await` on each returned session (also confirm/await any Unix zombie-reap is already covered by item 4's helper-side fix — no daemon-side `wait()` needed, the daemon never owns the shell PID directly), then `sweep_registry_backstop().await`.
9. New file `ws-dashboard/crates/daemon/src/terminal_reaper.rs` (registered in `main.rs`/module tree the same way sibling `terminal_*` modules are) — `pub fn spawn(registry: TerminalRegistry, interval: Duration) -> tokio::task::JoinHandle<()>`: a `tokio::spawn` running `let mut ticker = tokio::time::interval(interval); loop { ticker.tick().await; registry.sweep_once().await; }`. Propose `interval = Duration::from_secs(10)` as the concrete sweep interval (well under the 30s grace window, so worst-case post-grace teardown latency stays a fraction of the grace period itself); state this explicitly as the chosen value in the commit/PR description since the ticket requires a stated number.
10. `ws-dashboard/crates/daemon/src/server.rs` — wire it in: after `terminals = TerminalRegistry::boot_reconcile(...)` (`:99-104`), add `let reaper_task = crate::terminal_reaper::spawn(terminals.clone(), REAPER_INTERVAL);` before `terminals` moves into `AppState` at `:133`. Add `reaper_task.abort();` next to both existing `shutdown_task.abort();` calls (`:159`, `:164`).
