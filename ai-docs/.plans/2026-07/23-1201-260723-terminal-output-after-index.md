# Plan: 260723-bug-dashboard-terminal-output-after-oN-backfill-scan — Phase 1: Replace O(N) output_after scan with index arithmetic and drop the redundant status rescan

## Relevant Ticket Contract
- **Change 1 (`output_after`, `terminal.rs` ~607-620):** replace `.iter().filter(|c| c.sequence > after).cloned().collect()` with index arithmetic: `front_seq = inner.output.front().map(|c| c.sequence)` (no front -> nothing retained); `skip = after.saturating_add(1).saturating_sub(front_seq).min(len) as usize` (0 when no front); `inner.output.iter().skip(skip).cloned().collect()`. This relies on the gapless-contiguous-sequence + front-only-eviction invariant (`append_output` increments `next_sequence` exactly once per push; eviction only ever `pop_front`s) and must be byte-identical to the old filter for every `after`. Add a CONTRACT comment on `output_after` recording this dependency.
- **Change 2 (`send_terminal_socket_status`, `terminal.rs` ~893-916):** add a small private accessor `status_and_next_sequence(&self) -> (TerminalStatus, u64)` that locks `inner` once, reads only `status` and `next_sequence`, and never touches `inner.output`. Call it at line ~899 instead of `output_after(u64::MAX)`.
- **Constraints:** no public signature/struct-field changes; other call sites (`terminal_output` ~432, `plan_output_backfill` ~863, `is_range_truncated` ~628) stay unchanged; use saturating arithmetic throughout, clamp `skip` to `len` (deque length) so it can never index past it — clamp must happen in `u64` *before* the `as usize` cast; fully behavior-preserving (identical bytes/order/JSON shape/resume-by-cursor/truncation semantics); Spec Impact: None.
- **Verification boundary:** unit test proving new skip-based `output_after` == old `filter(seq > after)` semantics across representative `after` values on a deque pushed past `MAX_OUTPUT_CHUNKS` (eviction forced): before-window, at-boundary, mid-window, at-next_sequence(-1)/at-next_sequence, near-`u64::MAX` — identical in-order `Vec` for each case; existing `is_range_truncated_*` and `plan_output_backfill_*` tests keep passing unmodified; `cargo build --workspace` and `cargo test -p ws-dashboard-daemon` both green.

## Implementation Plan
1. In `ws-dashboard/crates/daemon/src/terminal.rs`, replace the `output_after` body (L607-620) with the index-arithmetic form: keep the lock/struct-literal shape, replace only the `chunks:` computation. Compute `let front_seq = inner.output.front().map(|c| c.sequence);` then `let skip = match front_seq { Some(front_seq) => after.saturating_add(1).saturating_sub(front_seq).min(inner.output.len() as u64) as usize, None => 0, };` then `chunks: inner.output.iter().skip(skip).cloned().collect()`. Ensure the `.min(inner.output.len() as u64)` clamp happens in `u64` before the final `as usize` cast (per ticket constraint) — i.e. clamp, then cast, not cast-then-clamp. Add a `// CONTRACT: ...` comment directly above `fn output_after` stating the optimization depends on gapless-contiguous `sequence` + front-only eviction (per `append_output`, L700-719) and must be revisited if either invariant changes.
2. In the same file, add a new private method on `TerminalSession` (placed near `output_after`/`is_range_truncated`, e.g. directly after `output_after`): `fn status_and_next_sequence(&self) -> (TerminalStatus, u64) { let inner = self.inner.lock().expect("terminal session lock poisoned"); (inner.status, inner.next_sequence) }`. Must not reference `inner.output`.
3. In `send_terminal_socket_status` (~L893-916), replace line 899 `let output = session.output_after(u64::MAX);` with `let (status, next_sequence) = session.status_and_next_sequence();`, then replace `output.status` -> `status` and `output.next_sequence` -> `next_sequence` in both the `Exit` and `Status` message-construction arms (L901-913).
4. Leave `terminal_output` (L432), `plan_output_backfill` (L861-872), and `is_range_truncated` (L628-631) untouched — no edits to these bodies.
