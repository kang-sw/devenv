## Relevant Ticket Contract

- Scope is diagnostic `tracing` instrumentation only — NO control-flow or
  teardown-semantics change to the relay or connect path.
- `terminal_websocket_relay` (`servers.rs:1617-1655`): at each loop-exit
  `else { break; }` (browser leg `servers.rs:1624`, upstream leg
  `servers.rs:1638`), emit a `tracing` event recording, per direction, whether
  the loop exited via `None` (clean EOF/stream end) or `Some(Err(e))`; for the
  error case, log the full `tungstenite::Error` value (its Debug/Display and
  variant, not a boolean). Include a stable target/identifier for the

  blanket `_ => TerminalWebSocketForwardError::Unavailable` map_err arm

  `tracing::warn` before it collapses to `Unavailable`.

  `Some(Err(<variant>))`.

## Codebase Findings

- `ws-dashboard/crates/daemon/src/servers.rs:1617-1655` — `terminal_websocket_relay(browser: WebSocket, upstream: UpstreamTerminalSocket)`. Both `select!` arms use `let Some(Ok(message)) = <recv> else { break; };`, collapsing `None` and `Some(Err(_))` into one untraced `break`. Function currently takes no session identifier.
- `ws-dashboard/crates/daemon/src/servers.rs:1499-1502` — the only call site: `Ok(upstream) => upgrade.on_upgrade(move |browser| terminal_websocket_relay(browser, upstream)).into_response()`, inside `server_scoped_terminal_websocket`, which has `terminal_id: String` (owned, from `AxumPath`) in scope and unused after this point — safe to move into the closure as the stable per-session identifier the ticket asks for, with zero behavior change.
- `ws-dashboard/crates/daemon/src/servers.rs:1562-1588` — `connect_remote_terminal_websocket(endpoint: &str, token: &BearerAuthToken, terminal_id: &str, query: &TerminalWebSocketQuery)` already receives `terminal_id: &str` as a parameter — no signature change needed here to get the identifier.
- `ws-dashboard/crates/daemon/src/servers.rs:1582-1587` — target map_err arm: `_ => TerminalWebSocketForwardError::Unavailable` inside `match error { TungsteniteError::Http(response) => ..., _ => ... }`. Renaming the catch-all pattern (e.g. `_` -> `other`) to bind the swallowed value is a no-op for behavior/output type.
- `ws-dashboard/crates/daemon/src/server.rs:151`, `ws-dashboard/crates/daemon/src/root_picker.rs:170,204,274,313,361`, `ws-dashboard/crates/daemon/src/git_worktree.rs:271` — existing crate-wide tracing convention: fully-qualified `tracing::warn!(%error, "message")`, no `use tracing::...` import needed, no spans used anywhere in this crate. Follow this exact shape (flat event, `%error` Display interpolation) rather than introducing a span-based approach — Phase 1 should look like the rest of the crate.
- `~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/tungstenite-0.29.0/src/error.rs:14-75` — `Error` derives `thiserror::Error` with a distinct `#[error("...")]` message per variant (e.g. `"IO error: {0}"`, `"WebSocket protocol error: {0}"`, `"Write buffer is full"`, `"TLS error: {0}"`). Its `Display` impl therefore already names the variant class, so `%error` interpolation alone satisfies the ticket's "variant, not a boolean" requirement — Debug is not required, matching the crate's existing `%error`-only convention.
- `ws-dashboard/crates/daemon/src/cli.rs:11-12` / `ws-dashboard/crates/daemon/src/main.rs:17` — default `--log-filter` is `"info"`. Use `tracing::warn!` (not `debug!`/`info!`) for all new events so they are captured at the daemon's default filter level during a reproduction run without requiring the owner to also pass a non-default `--log-filter`.
- `ws-dashboard/crates/daemon/src/logging.rs:16-88` — durable rolling-file sink already wraps `tracing_subscriber::registry()` with a stderr layer + file layer at the same filter; confirms events emitted here will land in `<state_dir>/logs/daemon.log.<date>` per the ticket's acceptance criterion, no sink changes needed.
- `ws-dashboard/crates/daemon/src/servers.rs:2544-2568` — the file's only `#[cfg(test)] mod tests` covers `parse_remote_startup_metadata`, unrelated to the relay/connect functions; no existing test references `terminal_websocket_relay` or `connect_remote_terminal_websocket`, so the signature addition (one new `terminal_id: String` parameter) has no test-call-site fallout.

## Implementation Plan

1. `servers.rs:1617` — add a `terminal_id: String` parameter to `terminal_websocket_relay`'s signature: `async fn terminal_websocket_relay(browser: WebSocket, upstream: UpstreamTerminalSocket, terminal_id: String)`.
2. `servers.rs:1501` — update the only call site to pass the identifier: `.on_upgrade(move |browser| terminal_websocket_relay(browser, upstream, terminal_id))` (the enclosing `server_scoped_terminal_websocket`'s `terminal_id: String` is unused after this line, so moving it in is a plain ownership handoff, no clone needed).
3. `servers.rs:1623-1636` (browser leg) — replace `let Some(Ok(message)) = browser_message else { break; };` with an explicit `match browser_message { Some(Ok(message)) => message, Some(Err(error)) => { tracing::warn!(terminal_id = %terminal_id, leg = "browser", %error, "linked terminal relay: browser leg read errored, tearing down relay"); break; } None => { tracing::warn!(terminal_id = %terminal_id, leg = "browser", "linked terminal relay: browser leg ended, tearing down relay"); break; } };` binding `message` for the existing `Ok` case exactly as before. Net effect on control flow is identical to today (`break` on `None` or `Err`, fall through to existing `is_close`/send logic on `Ok`) — only the two new `tracing::warn!` calls are added.
4. `servers.rs:1637-1649` (upstream leg) — mirror step 3 for `upstream_message`, using `leg = "upstream"` in both new events, same message-shape convention ("...tearing down relay").
5. `servers.rs:1582-1587` — rename the catch-all match arm from `_` to a bound identifier (e.g. `other`) and add one `tracing::warn!` call before returning `Unavailable`: `other => { tracing::warn!(terminal_id = %terminal_id, %other, "linked terminal websocket connect failed"); TerminalWebSocketForwardError::Unavailable }`. `terminal_id: &str` is already a parameter of `connect_remote_terminal_websocket`, no signature change needed here.
6. No new `use tracing::...` import needed anywhere — call fully-qualified `tracing::warn!(...)`, matching `server.rs`/`root_picker.rs`/`git_worktree.rs`.
7. Do not touch the post-loop `Close`-send lines (`servers.rs:1653-1654`), `remote_terminal_websocket_url`, `axum_to_tungstenite_message`/`tungstenite_to_axum_message`, or any `Cargo.toml` dependency feature list — all out of scope per Phase 1/2 split.
