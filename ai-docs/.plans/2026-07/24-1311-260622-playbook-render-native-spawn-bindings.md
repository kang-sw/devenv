# Plan: 260622-feat-playbook-render-tier-label — Phase 1: Render and teach native spawn bindings

## Relevant Ticket Contract

- Extend `playbook.render` (and `playbook.print`) output with resolved
  `recommended-model` and optional `recommended-reasoning-effort` lines,
  additive after the existing `recommended-tier: <tier>` line, which stays
  verbatim.
- Resolve model/effort through the existing harness-aware
  `wsconfig.ResolveAgentForHarnessConfig` seam already shared by `RoleModel`
  and the fixed-tier `{{.*TierModel}}` vars (`resolveTierModel` in
  `playbook_tools.go`) — reuse, do not parallel-implement.
- Empty effort omits the effort line (no override, not an error). A
  model-resolution failure omits the model line too but leaves the stable
  `recommended-tier` line intact — never emit an empty value.
- Add Codex-specialized workflow-manual guidance mapping `recommended-model` →
  native `spawn_agent.model` and `recommended-reasoning-effort` →
  `spawn_agent.reasoning_effort` (not `effort` — confirmed-rejected spelling),
  and describe the honest-rejection fallback (report the binding was
  unavailable; mercenary path is the explicit exact-binding fallback).
- Remove the delegate-body `Alias model for this role: {{.RoleModel}}.` echo
  line from every shipped delegate playbook now that render output is the
  single pre-spawn binding source.
- Shared playbook text stays host-neutral; literal native parameter names
  belong only in Codex-specialized rendered guidance.
- Update `ai-docs/spec/mcp-tools.md` (`#260609-playbook-tools`) and
  `ai-docs/spec/workflow-skills.md` (`#260507-mcp-centric-workflow-language`)
  on contact.
- Keep `agents-plugin/rsrc/` (canonical) and the generated
  `agents-plugin-wsflow/rsrc/` mirror synchronized via the documented regen
  commands — never hand-edit the wsflow copy.

## Out of Scope

- Any phase beyond Phase 1 (ticket has only one phase; treat as complete
  scope).
- `lead-implement.md`'s "do not include `recommended-tier` in worker-facing
  task text" guidance — that governs prose the lead writes into a worker
  task, not the `playbook.render` return payload, and the ticket's guidance
  target is explicitly the Codex workflow-manual, not `lead-implement`.
  Leave it untouched unless review finds a real coupling.
- `mercenary.register`'s `tier` pass-through and its tool description text
  (`server.go:3907-3914`) — mercenary registration takes no model/effort
  fields; only the native-spawn path binds those. Not touched.
- Reworking `RoleModel` / `resolveRoleModelVar` itself — only the body
  echo sites that render it are removed; the var and its resolution stay.
- Any change to `agents-plugin-wsflow/rsrc/*` file contents by hand — that
  tree is a generated byte-identical copy; edit only the canonical
  `agents-plugin/rsrc/*` sources and regenerate.

## Codebase Findings

- `agents-plugin-tool/internal/mcp/playbook_tools.go#L86-99` — `resolveTierModel(harness, tier, configOpts)`
  already calls `wsconfig.ResolveAgentForHarnessConfig(configOpts, tier, "", "", harness)`
  and discards the returned `effort` (3rd return value, `_`). This is the
  single seam to extend, not replace: refactor to a shared
  `resolveTierModelAndEffort(harness, tier string, configOpts wsconfig.Options) (model, effort string)`
  that makes the one `ResolveAgentForHarnessConfig` call, and have
  `resolveTierModel` become a thin wrapper (`model, _ := resolveTierModelAndEffort(...)`)
  so `resolveRoleModelVar` and `resolveTierModelVars` are unaffected.
- `agents-plugin-tool/internal/wsconfig/config.go#L213-256` — confirmed
  `ResolveAgentForHarnessConfig` signature: `(backend, model, effort string, err error)`.
  Effort comes from `mapping.Effort` (config-resolved) and is already
  `strings.TrimSpace`-safe; empty effort is a legitimate "no override" value,
  matching the ticket's empty-effort constraint directly.
- `agents-plugin-tool/internal/mcp/playbook_tools.go#L292-302` — `withRecommendedTier(payload, tier)`
  appends `\nrecommended-tier: <tier>` and is a 2-line pure function with its
  own unit test (`mercenary_surface_test.go:638-650`) asserting the exact
  string. Preserve it unchanged; add a new wrapper (e.g.
  `withRecommendedBindings(payload, tier, harness string, configOpts wsconfig.Options) string`)
  that calls `withRecommendedTier` first, then appends
  `recommended-model`/`recommended-reasoning-effort` lines only when
  non-empty, so the existing test and the "preserve existing line verbatim"
  constraint both hold with zero risk.
- `agents-plugin-tool/internal/mcp/server.go#L1298` and `#L1357` — the two
  `withRecommendedTier(body, recommendedTier)` / `withRecommendedTier(path, recommendedTier)`
  call sites (inside `playbook.print` / `playbook.render` cases of
  `func (s *Server) callTool`). Both already have `s` (for `s.currentHarness()`)
  and pass `wsconfig.Options{}` to `printPlaybook`/`renderPlaybook` a few
  lines above — swap in the same `wsconfig.Options{}` literal for the new
  wrapper call. No signature change needed on `printPlaybook`/`renderPlaybook`/
  `renderPlaybookBody` (they keep returning `(string, string, error)`); the
  model/effort resolution happens only at the two `toolTextResponse` call
  sites, which is the minimal-surface-area option (avoids threading two new
  return values through 3 internal functions and their ~6 test call sites).
- `agents-plugin-tool/internal/mcp/server.go#L2924-2934` — `toolTextResponse`
  discards `text` when `err != nil`, so calling the new wrapper unconditionally
  (even when `err != nil`) is safe and matches existing `withRecommendedTier`
  call-site behavior.

## Implementation Plan

1. `agents-plugin-tool/internal/mcp/playbook_tools.go`: refactor
   `resolveTierModel` (L93-99) into a new `resolveTierModelAndEffort(harness, tier string, configOpts wsconfig.Options) (model, effort string)`
   that makes the single `wsconfig.ResolveAgentForHarnessConfig` call and
   returns `("", "")` on error; make `resolveTierModel` a one-line wrapper
   over it so `resolveRoleModelVar` (L111-113) and `resolveTierModelVars`
   (L148-158) are unchanged.
2. `agents-plugin-tool/internal/mcp/playbook_tools.go`: add
   `withRecommendedBindings(payload, tier, harness string, configOpts wsconfig.Options) string`
   near `withRecommendedTier` (after L302). It calls `withRecommendedTier`
   first (preserves the exact existing line/behavior and its test), returns
   early when `tier` is empty, otherwise calls `resolveTierModelAndEffort`
   and appends `\nrecommended-model: <model>` when `model != ""` and
   `\nrecommended-reasoning-effort: <effort>` when `effort != ""` (after
   `strings.TrimSpace`) — no line is ever emitted with an empty value.
3. `agents-plugin-tool/internal/mcp/server.go`: at the two call sites
   (L1298 `playbook.print`, L1357 `playbook.render`), replace
   `withRecommendedTier(body, recommendedTier)` /
   `withRecommendedTier(path, recommendedTier)` with
   `withRecommendedBindings(body, recommendedTier, s.currentHarness(), wsconfig.Options{})`
   / the `path` equivalent.
4. Add a new Codex-specific idiom key to `playbookTerminologyTable` in
   `playbook_tools.go` (e.g. `SpawnBindingGuidance`), with Codex text naming
   `spawn_agent.model` / `spawn_agent.reasoning_effort` (never `effort`) and
   the honest-rejection-fallback instruction, and host-neutral/Claude values
   that avoid literal native field names (a generic sentence about honoring
   the rendered binding via the host's native model-selection surface, or
   empty, per Codex-specialized author doctrine already established for this
   table). Register the new var name in `reservedToolVarNames` (mirrors the
   pattern at L59-74).
5. `agents-plugin/rsrc/lead-workflow-manual/lead-workflow-manual.md`:

   extending the existing `recommended-tier`/mercenary sentence with the
   native-binding guidance and the "report exact binding unavailable, don't
   claim success" fallback per the ticket's Decisions.
6. Remove `Alias model for this role: {{.RoleModel}}.` (body line) and the
   now-unused `- RoleModel` frontmatter declaration from each of the 12
   canonical files listed in Codebase Findings.
7. Regenerate the manifest and wsflow mirror per the two-step command
   sequence in Codebase Findings (do not hand-edit
