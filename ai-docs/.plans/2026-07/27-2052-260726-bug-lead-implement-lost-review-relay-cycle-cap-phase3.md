## Relevant Ticket Contract

- New delegate `implementer-elevated`: `tier: large` in its own front-matter (no render-time tier override exists; a declared tier is the only way to satisfy `#260612-reviewer-allocation-tier-default`'s "declared tier is authoritative" clause).
- `role: implementer`, not `delegate` — `childRoleForPlaybookRole` accepts `implementer`/`reviewer`/`delegate`/`leaf`, but the *second* consumer at `playbook_tools.go:763-769` appends the `prefer_mercenary` guidance block only for `role in {implementer, reviewer}`; a `role: delegate` copy would silently lose that guidance on the same dispatch path `implementer-relay` uses.
- The prompt must differ from `implementer-relay` in **inputs** (add prior cycles' fix commits and dispositions), **posture** (question whether prior fixes addressed a symptom vs. cause; licensed to propose a different in-plan approach or escalate for a plan update), and **output** (state what was attempted and why it failed, even on continued failure) — not only tier.
- Every added input must appear in the new playbook's `variables:`; `renderPlaybook` returns `ErrUndeclaredVar` on an undeclared key.
- **Capacity condition** (partitioned:/fallback Instruction only): a finding the implementer reported `[fixed]` **once** that the next review still reports non-clean routes the *next* relay to `implementer-elevated` instead of `implementer-relay`. Excludes findings with a settled disposition (`[won't fix]`, `[deferred]`, `[out-of-scope]`, open `[escalate]`) — those are decisions, not failed attempts. Fires after exactly one failed relay (not two): a 3-cycle budget affords 2 relays, so a "relayed-twice-and-still-failing" state is only observable at the terminal cycle-3 review, after which no relay follows — firing then would make the elevated delegate permanently unreachable.
- **Root-cause condition** (same two branches): a **newly surfaced** finding whose root cause matches an already-relayed finding routes to `implementer-elevated`, independent of the cycle count. Must be worded on *newly surfaced* findings, not recurrences — recurrence of the *same* finding is already the capacity condition, and the motivating run (three distinct findings, one shared root cause) would not have tripped a recurrence-worded detector.
- **Precedence**: when an adjudicator override and a capacity/root-cause signal coincide on one relay, dispatch `implementer-elevated` carrying the override list; never dispatch two relays for one cycle.
- **Structural signal, not prose inference**: the Re-review prompt template in `lead-implement.md` must gain a symmetric ask — for each `[fixed]` item, respond `[resolved]` or `[unresolved: <short reason>]` — mirroring the existing `[accepted]`/`[maintained: <reason>]` ask for `[won't fix]` items, so the capacity condition reads a token instead of the lead diffing prose against its own disposition record.
- **Wording fix**: the live "Use Review relay and Re-review prompts only for genuinely new non-clean Critical/Important findings" phrasing (currently at `session_state.go:582` and `:587`) must be restated so a finding reported `[fixed]` and returned `[unresolved]` is relayable — the phrase targets reviewer-invented churn, not unresolved carryover.
- **Three dispatch-surface edits**, all in `agents-plugin/rsrc/lead-implement/lead-implement.md`: the **Review relay dispatch** template, the **Task input mapping** (Delegate dispatch step 6), and the **Re-review prompt** template — each with a pinned assertion in `playbook_tools_test.go`. The Re-review prompt currently has *no* pinned assertion at all (verified: no hit for its literal lines in `playbook_tools_test.go`), which is why the ticket names it explicitly — nothing would fail today if it were skipped.
- Spec: amend `{#260612-reviewer-allocation-tier-default}` for the new delegate and its dispatch condition.
- Verification is by **dispatching**, not by reading Instruction text: `playbook.render(name: "implementer-elevated")` must actually return `recommended-tier: large`, mint a child key proving `role:` is in the accepted set, and (under `prefer_mercenary`) carry the same guidance block as `implementer-relay` — a named tier no dispatch path honors is exactly how the original cap was lost.
