# Plan: 260725-bug-dashboard-terminal-platform-macos-unsupported — Phase 1: Make the daemon build and verify identity correctly on macOS

## Relevant Ticket Contract

- Exit criterion: green native `cargo build` + `cargo test -p ws-dashboard-daemon` on aarch64-apple-darwin, plus named evidence Linux did not regress (`cargo check --target x86_64-unknown-linux-gnu` after `rustup target add`, a container run, or an explicit recorded deferral naming the gap).
- Decision (binding): macOS start-time source is `proc_pidinfo(pid, PROC_PIDTBSDINFO, 0, &mut buf, size)` → `proc_bsdinfo.pbi_start_tvsec`/`pbi_start_tvusec`, packed into the existing opaque `u64` registry field. Do not use `sysctl`/`kinfo_proc` (libc 0.2.186 has no `kinfo_proc`/`extern_proc`/`p_starttime` on apple targets — verified below).
- Decision (binding): macOS `kill_verified` is verify → `kill(pid, SIGKILL)` → best-effort post-kill re-read distinguishing: pid gone (success, no log), identity readable with the **same** start-time (success, no log — includes the legitimate unreaped-zombie case a direct-child test observes), identity readable with a **different** start-time (pid-reuse signal — log only this case). Return type stays `io::Result<bool>`; report via `tracing::warn!`, not the return value (both call sites already discard the `Result`).
- Constraint: registry `start_time` field stays an opaque `u64`; no schema change.
- Constraint: do not widen `#[cfg(unix)]` into a runtime branch — keep syscall leaves in cfg-gated submodules behind cfg-independent re-exported names; the re-export block must stay exhaustive with an explicit `compile_error!` arm for unsupported unix targets.
- Constraint: `terminal_helper_process.rs:174`'s `process_start_time(pid).unwrap_or(0)` must become a loud `Err` returned from `run_terminal_helper` **before** `write_registry_entry` — never a recorded sentinel `0`. Do not add a 4th `IdentityStatus` variant (`terminal_reconcile.rs:51`, exactly 3 variants; a 4th would ripple into the 6-row reconcile table, which is out of this phase's spec budget).
- Constraint: `spawn_detached` (`setsid()` + double fork) is already portable POSIX and expected to work unchanged on macOS — not part of the port beyond verification.
- Spec Impact (binding, lands with Phase 1 closeout): amend three anchors in `ai-docs/spec/ws-web-dashboard/index.md` — the fallback-kill guarantee sentence (`#260516-ws-web-dashboard-workroot-io-restore-model`) becomes platform-tiered (Linux/Windows: structurally closed; macOS: verified-then-signal with best-effort, non-guaranteed post-kill detection — do not overclaim macOS mis-kill detection); the identity sentence (`#260516-ws-web-dashboard-terminal-registry-pty-spawn`) gets a note that the start-time *source* is platform-specific while the recorded value stays opaque; the evidence anchor (`#260516-ws-web-dashboard-terminal-cross-platform-evidence`) records macOS build/unit-test coverage from this phase, with full live-lifecycle evidence stated as an explicit gap deferred to Phase 2 (do not claim runtime coverage Phase 1 does not have).
- Note: this crate has never been type-checked on macOS; treat any newly surfaced macOS-only compile/test failure beyond the two named ones as in-scope for this phase, not deferred.

## Implementation Plan

1. In `ws-dashboard/crates/daemon/src/terminal_platform.rs`, restructure the `unix` module (`#[cfg(unix)]`, L21-L112) to keep only `spawn_detached` (unchanged — shared portable POSIX). Move `process_start_time`, `verify_process_identity`, `kill_verified` out into a new `#[cfg(target_os = "linux")] pub mod linux { ... }` submodule with their current bodies unchanged (still `/proc` + `SYS_pidfd_open`/`SYS_pidfd_send_signal`).
2. Add a new `#[cfg(target_os = "macos")] pub mod macos { ... }` submodule implementing:
   - A private helper `fn read_bsdinfo(pid: u32) -> Option<libc::proc_bsdinfo>` that zero-inits a `libc::proc_bsdinfo`, calls `libc::proc_pidinfo(pid as libc::c_int, libc::PROC_PIDTBSDINFO, 0, &mut info as *mut _ as *mut libc::c_void, size_of::<proc_bsdinfo>() as libc::c_int)`, and returns `Some(info)` only when the return value equals the struct size, else `None`.
   - A private helper `fn pack_start_time(info: &libc::proc_bsdinfo) -> u64` implementing `(pbi_start_tvsec << 20) | (pbi_start_tvusec & 0xF_FFFF)` (see Codebase Findings packing note).
   - `pub fn process_start_time(pid: u32) -> Option<u64>` = `read_bsdinfo(pid).map(|info| pack_start_time(&info))`.
   - `pub fn verify_process_identity(pid: u32, expected_start_time: u64) -> bool` = `process_start_time(pid) == Some(expected_start_time)` (same shape as the other two platform modules).
   - `pub fn kill_verified(pid: u32, expected_start_time: u64) -> io::Result<bool>`: read identity via `read_bsdinfo`; if absent or `pack_start_time(&info) != expected_start_time`, return `Ok(false)` (nothing verified, nothing killed — mirrors the Linux/Windows "not verified" early return). Otherwise call `libc::kill(pid as libc::pid_t, libc::SIGKILL)`; if it returns nonzero, return `Ok(false)`. Otherwise perform the best-effort post-kill re-read via `read_bsdinfo(pid)` again: `None` → normal success (no log); `Some(after)` with `pack_start_time(&after) == expected_start_time` → normal success (no log — covers both the zombie case per `libc::SZOMB`/`after.pbi_status` and any other same-identity readback, per the Decisions text); `Some(after)` with a different packed start-time → `tracing::warn!(pid, ...)` a pid-reuse signal, still return `Ok(true)` (the `kill(2)` call itself succeeded). Return `Ok(true)` for the two "no log" cases.
3. Update the re-export block (`terminal_platform.rs:354-357`) to:
   ```
   #[cfg(unix)]
   pub use unix::spawn_detached;
   #[cfg(target_os = "linux")]
   pub use linux::{kill_verified, process_start_time, verify_process_identity};
   #[cfg(target_os = "macos")]
   pub use macos::{kill_verified, process_start_time, verify_process_identity};
   #[cfg(windows)]
   pub use windows::{kill_verified, process_start_time, spawn_detached, verify_process_identity};
   #[cfg(not(any(target_os = "linux", target_os = "macos", windows)))]
   compile_error!("ws-dashboard-daemon terminal_platform: unsupported target (only linux, macos, windows are implemented)");
   ```
   Keep `windows` module/re-export exactly as-is (untouched by this ticket).
4. Re-gate `#[cfg(all(test, unix))] mod unix_tests` (L359-429) to `#[cfg(all(test, any(target_os = "linux", target_os = "macos")))] mod platform_identity_tests`, and change `use super::unix::*;` to `use super::{kill_verified, process_start_time, verify_process_identity};` (the cfg-independent top-level re-exports) plus `use std::process::Command;`. Test bodies stay otherwise unchanged — they already only call the cfg-independent function signatures.
5. In `ws-dashboard/crates/daemon/src/terminal_helper_process.rs:174`, change
   `let start_time = crate::terminal_platform::process_start_time(pid).unwrap_or(0);`
   to an early, loud failure, e.g.:

   ```
       .ok_or_else(|| anyhow::anyhow!("failed to read own process start time for identity registration (pid {pid})"))?;
   ```
   placed before the `entry`/`write_registry_entry` call that already immediately follows — this is a same-line semantic change, no reordering needed since the code already computes `start_time` right before use.
6. Amend `ai-docs/spec/ws-web-dashboard/index.md`:
