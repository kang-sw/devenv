# Plan: 260814-refactor-config-collapse-tuning-knobs-to-list-tune — Phase 2: Swap the surface — add config.list + config.tune, remove the ten

## Relevant Ticket Contract

- Add `config.list` (read; subsumes `config.show` + `config.tuning`) and
  `config.tune("<key>", <value>, scope, harness)` (write; subsumes the eight
  writers). Remove all ten per-knob tools outright — no aliases (Decision 7).
- `config.list` must return the full per-key schema (value domain,
  required/optional fields, allowed/default scope, harness applicability),
  preserve `config.tuning`'s `format:"json"` stable shape (spec
  `{#260625-tuning-catalog}`) AND `config.show`'s resolved-from-scope
  reporting (spec `{#260619-layered-config-scope-model}`), and preserve the
  no-agent full-ws-only filter (today: only `workflow.prefer_mercenary` is
  hidden) (Decisions 3, 4).
- `config.tune`'s `scope` argument is schema-optional with `default_scope`
  backstop; the precise per-key contract is a caller obligation surfaced by
  `config.list`, not a hard schema requirement (Decisions 2, 8).
- `harness` is load-bearing for prompt-override keys AND `agents.tier`;
  warning-only (not an error) for keys that ignore it (alarms, `prefer_*`)
  (Decision 5).
- `agents.tier` is a compound writer: `tier` moves **inside** the value
  object alongside `backend`/`model`/`effort`; `harness` stays the outer
  selector arg — `config.tune("agents.tier", {tier, backend, model, effort},
  scope, harness)` (Decision 9). Do not redesign the tier/effort enum
  taxonomy (260611's scope).
- Authority gate preserved: `config.*` stays lead-only via the prefix gate
  (unchanged, prefix-based); global-only keys additionally require
  lead-key authority, driven per-key by the registry (Decision 6).
- Sweep every consumer in one atomic landing (Decision 7 / Constraints):
  `server.go` dispatch + `tools()` schema literals + 3 gating tables;
  `runtime.json` in both `agents-plugin/` and `agents-plugin-wsflow/`
  (`tools` + `commands` blocks); `cmd/ws-mcp/main.go`'s
  `runtimeCapabilityCommandNames`/`filterNoAgentCommands` + CLI mirror;
  the Go tests; `agents-plugin-wsflow/tests/test_wsflow_runtime_contract.py`;
  `ws:lead-tune` + `lead-workflow-manual` prose (canonical `agents-plugin/rsrc/`
  tree only — the wsflow copy is a generated byte-identical mirror, never
  hand-edited); `ai-docs/spec/mcp-tools.md` (anchors `{#260625-tuning-catalog}`,
  `{#260620-config-prompt-override-tuning-tools}`,
  `{#260619-layered-config-scope-model}`), `ai-docs/mental-model/mcp-runtime.md`,
  and `ai-docs/spec/workflow-skills.md`'s `lead-tune` reference.
- Checkpoint ordering given in the ticket (informal dev-sequence, not
  necessarily separate commits — Decision 7 wants one atomic landing): (a) add
  the two tools alongside the existing ten, green; (b) repoint CLI mirror,
  `runtime.json`, capability-command lists; (c) rewrite Go + Python tests;
  (d) rewrite shipped prose + mental-model/spec docs; (e) remove the ten tools
  and gating-table entries last.
- Verification bar: full Go + Python contract suites green; `tools/list`
  shows exactly `config.list` + `config.tune` with the ten gone; wsflow
  catalog still omits full-ws-only knobs; an `agents.tier` write with
  explicit `harness` still targets the correct per-harness alias slot;
  `ws:lead-tune` dogfood round-trips a read and a write.
- Phase 1 (landed, d722e864) forward note: Phase 2 builds on the registry's
  currently-inert `GlobalOnly()`/`DefaultScope()` methods and must wire scope
  routing through them; the `agents.tier` adapter (`ResolverBacked:false`)
  must stay a compound writer, not be flattened.

## Codebase Findings

### Registry (Phase 1 output, consumed and extended here)

- `agents-plugin-tool/internal/mcp/config_registry.go` — the per-key
  registry. 5 static entries (`workflow.prefer_subagent`,
  `workflow.prefer_mercenary`, `bootstrap_alarm`, `doc_coverage_alarm`,
  `agents.tier`) plus `promptKnobEntry(pointID)` factory for the dynamic
  `prompt.*` family. Already exposes `GlobalOnly()`/`DefaultScope()` methods
  delegating to `wsconfig.GlobalOnly`/`wsconfig.DefaultScope` (project-fixed
  for `agents.tier`), `configKeyEntryForTool(toolName)` (keyed by
  **tool name**, used by 3 gating tables), `enumContains`/`validateEnumValue`
  helpers.
- **Registry entry must change for Decision 9.** Today (`config_registry.go:157-183`)
  `agents.tier`'s `tier` field lives in `SelectorFields` (alongside
  `harness`), matching today's `config.agents_tier(tier, backend, model,
  harness, effort)` shape. Decision 9 requires `tier` to move **into**
  `ValueFields` (required) alongside `backend`/`model`/`effort`, leaving
  `SelectorFields` = `harness` only. This is a genuine Phase 2 registry edit,
  not just consumption — `buildTuningCatalog`'s agents.tier append
  (`server.go:2239-2247`) reads `agentsTierEntry.SelectorFields`/`.ValueFields`
  directly, so the catalog's projected shape updates automatically once the
  registry entry is edited.
- `configKeyEntryForTool` is keyed by **tool name** (`WriterTool`/`ResetTool`
  match). It cannot resolve `config.tune`'s runtime `key` **argument** (e.g.
  `"workflow.prefer_subagent"`, `"agents.tier"`, `"prompt.UserPreferenceSection"`)
  — a new lookup keyed by config **key** is needed for the generic writer.
  Add `resolveConfigEntryForKey(key string) (configKeyEntry, bool)`: loop
  `configRegistry` matching `entry.Key == key`; if no match and
  `strings.HasPrefix(key, "prompt.")`, return
  `promptKnobEntry(strings.TrimPrefix(key, "prompt."))`, true.
- **Session-key requirement varies per key and is not a registry field
  today.** Lead-authority keys (4 static entries where
  `RequiresLeadAuthority`) need `s.requireLeadSessionKey` (lead-scoped key,
  matching `server.go:691,731,751,791`). The `prompt.*` family needs a
  **non-empty** `session_key` but NOT lead-scope (matching
  `server.go:837-838,903-904` — plain presence check, no
  `requireLeadSessionKey` call). `agents.tier` needs **no** session_key at
  all (confirmed: `server.go:673-688` has zero session_key handling).
  Derive this without a new struct field: a key needs session_key iff
  `entry.RequiresLeadAuthority || strings.HasPrefix(entry.Key, "prompt.")`.
- **Reset/unset is already registry-encoded via `ResetTool != ""`.** 3 of 4
  static entries have `ResetTool` set (`workflow_prefer_subagent`,
  `bootstrap_alarm`, `doc_coverage_alarm`); `workflow_prefer_mercenary` has
  none (confirmed: no `reset` handling in its dispatch case,
  `server.go:730-748`, and no `reset` schema property, `server.go:3903-3912`).
  `promptKnobEntry` already sets `ResetTool: "config.prompt.unset"`.
  `agents.tier` has none. `config.tune`'s generic `reset: true` handling can
  therefore branch uniformly on `entry.ResetTool != ""` without new fields.

  resolver-backed and has no `allowed_scopes` list to lean on (Phase 1
  finding: fixed to `wsconfig.ScopeProject`) — reject any explicit `scope`
  argument other than empty/`"project"`.
- **No-agent gating for `config.tune` cannot live at the tool-name level.**
  Today `noAgentHiddenTool` (`server.go:4873-4891`) hides
  `config.workflow_prefer_mercenary` as a whole TOOL, checked once at
  `callTool`'s outer gate (`server.go:494-496`) before dispatch. Once
  `config.tune` is one generic tool name, that outer per-tool gate cannot see
  which `key` argument a wsflow caller passed — `configKeyEntryForTool` will
  return `ok=false` for `"config.tune"`/`"config.list"` (they are not
  `WriterTool`/`ResetTool` values in the registry), so `noAgentHiddenTool`'s
  `config.*` branch falls through to `return false` (never hidden) — correct
  for the tool itself, but a wsflow caller could still call
  `config.tune("workflow.prefer_mercenary", "on")`. `config.list` already
  handles this correctly at the catalog-content level via
  `buildTuningCatalog`'s `appendKnob` (`server.go:2165-2170`, driven by
  `NoAgentVisible`). `config.tune`'s dispatch must add an equivalent runtime
  check: after resolving the entry, if `NoAgentMode() && !entry.NoAgentVisible`,
  reject with the same message shape the outer gate uses
  (`"%s agentless mode disables agent-backed tool: %s"`,
  `server.go:495`).
- `internal/mcp/format.go:9-11` `FormatConfigView` — CLI-exported wrapper
  around `formatConfigView`; CLI's `config list` command reuses this (plus a
  new export for the tuning-catalog text formatter if the CLI needs it — see

### Gating tables

- `agents-plugin-tool/internal/mcp/server.go:74-81` `isLeadOnlyTool`/
  `workflowPreferenceWriterTool` — already registry-driven
  (`configKeyEntryForTool(name).RequiresLeadAuthority`), keyed by **tool
  name**. `config.tune` cannot be marked lead-only at this level (it serves
  both lead-only and non-lead-only keys) — authority is enforced **inside**
  the `config.tune` dispatch case per resolved key, exactly matching how
  `config.prompt.set`/`unset` are lead-only in spirit today without being in
  this table (they're gated by the `config.*` prefix in `roleAllowsTool`
  only). No change needed to `isLeadOnlyTool` itself.
- `agents-plugin-tool/internal/mcp/server.go:4628-4647`
  `toolSchemaRequiresSessionKey` — the default branch's
  `configKeyEntryForTool(name)` lookup (by tool name) goes stale once the ten
  names are removed (nothing will match). Since `config.tune`'s session_key
  requirement varies by the runtime `key` argument (not statically knowable
  at schema-build time), do **not** add `config.tune`/`config.list` to this
  function's always-required set. This means `config.tune`'s JSON schema
  will not force `session_key` into `required` for any key — the *runtime*
  dispatch check (see Dispatch section) still enforces it identically to
  today for lead-authority and prompt.* keys; only the upfront
  schema-validation layer is relaxed. This is an intentional, low-risk
  simplification given the single generic tool shape — flag it in the PR
  description / commit body since it is a caller-visible (if minor) schema
  contract change.
- `agents-plugin-tool/internal/mcp/server.go:4873-4891` `noAgentHiddenTool`
  — the `config.*` branch (`4885-4888`) still works unmodified for any
  remaining `config.*`-prefixed tool name lookup; `config.list`/`config.tune`
  simply fall through to `return false` (never tool-hidden), which is
  correct for `config.list` and only a *partial* answer for `config.tune`
  (see Dispatch section's runtime no-agent check).
- `agents-plugin-tool/internal/mcp/server.go:4752-4766` `roleAllowsTool` —
  prefix-based (`!strings.HasPrefix(name, "config.")` for delegate/leaf).
  Needs **zero** changes; `config.list`/`config.tune` are already covered.

   return map[string]any{"description": description} }`, since

   - Trim `key`; error `"config.tune: key is required"` if empty.
   - `entry, ok := resolveConfigEntryForKey(key)`; error
     `"config.tune: unknown config key %q; call config.list for supported

     `key` since the tool itself, `config.tune`, is never hidden).

     s.requireLeadSessionKey("config.tune", params.Arguments); err != nil {
     return err } } else if strings.HasPrefix(entry.Key, "prompt.") { trim
     session_key; error "config.tune: session_key is required" if empty }`
     (agents.tier: no check, matching today).
   - Harness: `if entry.HarnessApplicable { if harness == "" { harness =
     s.currentHarness() } ; validate against entry.SelectorFields' harness
     enum when non-empty (enumContains) } ` — else (alarms/prefer_subagent/
     prefer_mercenary) a non-empty `harness` argument is accepted without
