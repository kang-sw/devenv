# Plan: 260626-feat-session-key-format-and-retention — Phase 2: Touch active session records and prune stale records

## Relevant Ticket Contract

- Successful MCP calls that resolve/require a known `session_key` must refresh the record's key-file mtime, via a central session-store helper — covering root-aware calls, lead-only keyed tools, and session-state tools (agenda/todo/note), including the read-only seams that call `readRecord` directly and bypass `lookup` (`getOverride`/`listOverrideKeys`/`children`).
- Touch is throttled: skip `Chtimes` when the record's mtime is already within the last ~1h (touch-refresh guard).
- `ws.ferrule` scans `<cache-root>/keys/` for pruning at most ~once/24h, gated by a prune marker or equivalent bookkeeping.
- Prune deletes key record files whose mtime is older than ~30 days. Malformed files must not crash pruning; current/newly minted records must not be pruned.
- Pick concrete constants now (no "about" left in code): the plan below uses 24h scan cadence, 30-day retention, 1h touch guard — implementer may adjust with rationale, but tests must assert the exact constants that land.
- Tests must cover: no-scan-on-every-ferrule, mtime refresh on successful keyed lookup (including read-only session-state seams), stale-key deletion, retention of recently touched records.
- Update `ai-docs/spec/mcp-tools.md` and `ai-docs/mental-model/mcp-runtime.md` from "no automatic eviction" to the new touch/prune lifecycle.
- Decisions to preserve: keys stay opaque (no format parsing beyond the existing broad `sessionKeyFilenamePattern`); no shelling out to platform `touch` — use Go `os` APIs (`os.Stat` + `os.Chtimes`) only; record writes already refresh mtime via `writeRecordAtomic`'s temp+rename, so writes need no extra touch call.

## Out of Scope

- Phase 1 (three-word key mint format) — already landed (`fd84f0a4`), not touched here.
- `wskey.Generate()` / `internal/wskey` — format is settled, no changes needed for Phase 2.
- The unrelated `internal/wsstore` SQLite-backed artifact/agent-instance retention system (`agents-plugin-tool/internal/wsstore/store.go`) — a different subsystem (per-worktree SQLite state) with its own TTL/prune machinery; do not conflate or reuse its schema for the flat `keys/*.json` store, which stays a plain filesystem mtime scan.

## Codebase Findings

This is the natural touch point for the root-aware/lead-only paths, but must not be the *only* touch point (see next finding).
- `agents-plugin-tool/internal/mcp/session_state.go#L763-773` — `readState(sessionKey)` reads via `readRecord` directly (holds `s.mu`), bypassing `lookup`. This is the read-only session-state seam (used by `ws.todo.list`, `ws.todo.read`, agenda reads, `workflow_manual.go`'s bootstrap-adjacent reads at `workflow_manual.go#L184` and `#L225`, and `server.go#L986`). Must get its own touch call.
- `agents-plugin-tool/internal/mcp/session_auth.go#L296-312` (`getOverride`) and `#L317-333` (`listOverrideKeys`) — both call `readRecord` directly under `s.mu`, invoked from `internal/mcp/session_config_adapter.go#L16` and `#L34` (the `wsconfig.Resolver` override-lookup path). Explicitly named by the ticket as a bypass seam; needs its own touch call.
- `agents-plugin-tool/internal/mcp/session_auth.go#L193-272` (`children`) — iterates every `*.json` file in `keys/`, reading each via `readRecord` to build the adjacency map; the queried key is `parentKey`. Touch must apply **only** to `parentKey`'s own record (right after the `records[parentKey]` presence check at `#L224-226`), not to every record scanned in the directory walk — touching every visited record would be wrong (it's a read of *other* sessions' state, not activity on them).
- `agents-plugin-tool/internal/mcp/session_auth.go#L399-423` (`writeRecordAtomic`) — every write already goes through temp-file-create + `os.Rename`, which gives the replaced file a fresh mtime. Confirms the ticket's decision that write paths (`mutateRecord`, `setOverride`, `deleteOverride`, `setNote`, `enterMode`, `mutateTodos*`) need no additional touch call.
- `agents-plugin-tool/internal/mcp/session_auth.go#L381-394` (`readRecord`) — the shared low-level reader, validates the key against `sessionKeyFilenamePattern` before touching disk. A dedicated `touch(dir, key)` helper should reuse this same path-safety guard (or rely on the fact all call sites already validated the key via a prior `readRecord` success) rather than re-deriving it.
- `agents-plugin-tool/internal/mcp/server.go#L1689-1740` (`handleLeadLogin`, the `ferrule` bootstrap handler, dispatched at `server.go#L577-578`) — the natural call site for the once-per-24h prune scan; runs on every `ferrule` call, root-independent (the `keys/` store is a single flat directory shared across all worktrees), so the prune call belongs near the top of this handler, best-effort (must not fail bootstrap on a prune error).
- `agents-plugin-tool/internal/mcp/session_auth.go#L98-111` (`keysDir`) — resolves/creates `<cache-root>/keys` via `wsstate.CacheRoot`; both the touch helper and the prune scan should reuse this instead of re-deriving the cache root.
- `agents-plugin-tool/internal/mcp/session_auth.go#L207-220` — `children`'s directory walk already filters entries to `filepath.Ext(entry.Name()) != ".json"` (skips non-JSON files). A prune marker file placed directly inside `keys/` with a non-`.json` name (e.g. `.prune-marker`) is automatically excluded from this walk and from `mint`'s `O_EXCL` key namespace — no extra filtering needed elsewhere.
- `agents-plugin-tool/internal/mcp/session_auth_test.go#L91` (and similar `t.Setenv("WS_CACHE_HOME", filepath.Join(t.TempDir(), "cache"))` lines throughout) — existing test isolation pattern; new tests should follow it and manipulate file mtimes directly via `os.Chtimes` (no injectable clock exists on `sessionStore` today, so simulate "stale" by backdating file mtimes, not by mocking time).
- `agents-plugin-tool/internal/mcp/session_auth_test.go#L19-38` — `callLogin`/`callToolOnce` helpers issue MCP `tools/call` requests through `Server.ServeStdio`; reuse for prune/touch integration tests (e.g., two `ferrule` calls close together to assert no-double-scan; a `todo.list` call after backdating a record's mtime to assert refresh).

If touch is embedded only in `lookup()`, this incidental double-lookup would already touch session-state calls too — but relying on that as the *sole* mechanism is fragile (it's an authorization side effect, not a designed touch point, and could be refactored away). Per the ticket's explicit instruction, implement the touch helper at the low-level `readRecord`-adjacent seams (`lookup`, `readState`, `getOverride`, `listOverrideKeys`, `children`) rather than depending on this pre-dispatch coincidence.

- `ai-docs/spec/mcp-tools.md#L169-171` — "...There is still no logout and no automatic eviction, though deleting a key file is now a physically possible removal path (deferred)." — needs rewrite; eviction is no longer deferred/hypothetical.

## Implementation Plan

1. In `agents-plugin-tool/internal/mcp/session_auth.go`, add constants near `sessionRecordSchemaVersion` (`#L68`): `touchGuardWindow = time.Hour`, `pruneScanCadence = 24 * time.Hour`, `keyRetentionAge = 30 * 24 * time.Hour`, `pruneMarkerName = ".prune-marker"`. Add `"time"` to the import block (`#L3-16`).
2. Add a private helper `func (s *sessionStore) touch(dir, key string)` in `session_auth.go` next to `readRecord`: `os.Stat` the key's path (`s.keyPath(dir, key)`); if `time.Since(info.ModTime()) < touchGuardWindow`, return; else `os.Chtimes(path, now, now)`, ignoring errors (best-effort, matches existing non-fatal style of `lookup`'s error handling).
3. Call `s.touch(dir, key)` at the end of `lookup` (`#L172-186`, after `readRecord` returns `ok`), `readState` (`session_state.go#L763-773`, after `readRecord` succeeds, while `s.mu` is still held), `getOverride` (`session_auth.go#L296-312`, after the record is found, regardless of whether the specific `itemKey` is present), and `listOverrideKeys` (`#L317-333`, same condition).
4. In `children` (`session_auth.go#L193-272`), after the `if _, ok := records[parentKey]; !ok { return []sessionChild{}, nil }` check (`#L224-226`) confirms `parentKey` resolved, call `s.touch(dir, parentKey)` once — not inside the per-entry loop that builds `records`/`adjacency`.
5. Add `func (s *sessionStore) maybePrune()` in `session_auth.go` (or a new `session_prune.go` file in the same package, whichever keeps `session_auth.go` from growing unwieldy — prefer a new file since prune is a distinct concern from the record CRUD helpers): resolve `dir` via `s.keysDir()`; stat `filepath.Join(dir, pruneMarkerName)`; if it exists and `time.Since(modTime) < pruneScanCadence`, return; otherwise create/touch the marker first (claim the scan so concurrent `ferrule` calls don't double-scan — an `O_CREATE|O_TRUNC` write + close is sufficient, no need for `O_EXCL` since a duplicate scan is harmless, just wasteful), then scan: `os.ReadDir(dir)`, for each entry with `.json` suffix, `os.Stat` it and `os.Remove` if `time.Since(modTime) > keyRetentionAge`. Do not JSON-parse file contents for the prune decision (mtime-only pruning sidesteps the "malformed files must not crash pruning" requirement entirely — a malformed record still has a valid mtime and is prunable/keepable on that basis alone, no `readRecord` call needed). Hold `s.mu` for the scan/delete loop to serialize against concurrent writes.
6. In `server.go`, call `s.sessions.maybePrune()` near the top of `handleLeadLogin` (`#L1692`, before or right after the `root` validation — best-effort, ignore any error so a prune hiccup never fails a bootstrap call).
7. Add/extend tests in `agents-plugin-tool/internal/mcp/session_auth_test.go` (or a new `session_prune_test.go`): (a) touch-guard — call a keyed read (e.g. `lookup` or a `todo.list` MCP call) after backdating the record file's mtime beyond `touchGuardWindow` and assert the mtime advances; call again immediately and assert it does *not* advance again; (b) read-only session-state seam — repeat via `ws.todo.list`/`ws.agenda.list` (exercises `readState`) and via a `session_config` override read path if one is reachable through MCP (exercises `getOverride`/`listOverrideKeys`), not just direct `lookup`; (c) prune cadence — call `ferrule` twice with a manually-old marker between calls to prove no-scan-inside-cadence, then backdate the marker beyond `pruneScanCadence` and confirm a scan occurs; (d) stale-key deletion — backdate a key file's mtime beyond `keyRetentionAge`, call `ferrule` (with a backdated/absent marker to force a scan), and assert the file is gone; (e) retention of recently touched records — a record freshly touched (or newly minted) must survive a forced prune scan even if its *creation* time would otherwise be old (only mtime governs); (f) malformed-file resilience — drop a non-JSON-parseable `.json` file into `keys/`, force a prune scan, and assert it does not crash and is pruned/kept purely by mtime like any other file.
8. Update `ai-docs/spec/mcp-tools.md#L133-135` and `#L169-171` to describe: touched mtime on successful keyed resolution (with the 1h guard), `ferrule`-driven prune scan (≤ once per 24h) removing key records whose mtime exceeds 30 days, and that this replaces the old "no logout and no eviction" language.
9. Update `ai-docs/mental-model/mcp-runtime.md#L45` with the equivalent same-paragraph rewrite (this doc is a single dense paragraph per bullet — keep the edit surgical, replacing only the "no logout and no automatic eviction..." clause).
