# Brief: 260609-feat-ws-playbook-surface-mvp (Phase 2)

## Intent

Wire the two caller-visible playbook MCP tools onto the Phase-1 `internal/wsrsrc`
`Load` seam: `playbook.print` (returns procedure text inline) and
`playbook.render` (writes a context-injected, harness-rendered prompt to a
worktree-scoped tmp file and returns the path). Add harness-aware content
selection (claude+codex terminology shipped as data, model aliases from config,
unknown-harness host-neutral fallback) and a delegation tip fragment for
`delegates: true` playbooks. `playbook.render` is the full-ws promotion of
wsflow's `prompt.render`, generalized beyond its fixed five-stem allowlist.

## Scope Boundary

- IN: `playbook.print` / `playbook.render` MCP tool schemas + dispatch; harness
  detection → terminology/overlay selection; config-backed model-alias
  substitution; delegation-tip injection for `delegates: true`; `runtime.json`
  refresh if a tool-surface bump is required; golden-render + inline-return
  tests; any sample-tree fixtures needed to test (a `delegates: true` playbook
  and a plain playbook).
- OUT (hard boundaries):
  - **No session_key minting.** Ship `render(name, context?)` / `print(name,
    context?)`. Session-auth (`session_key`, `ws/lead.login`, key roles,
    in-memory session→root map) does not exist until M3. Implementing the full
    keyed signature now is rejected — render cannot mint a child key before the
    session model exists.
  - **No skill-body migration** (M2). Do not convert any skill text to
    playbooks. The sample/fixture playbooks are test material, not production
    skill conversion.
  - **No spawn-machinery changes** (M3). Do not touch `agents.*`, the actor
    model, or runner backends.
  - Do not remove or alter wsflow `prompt.render`; it stays during migration.

## Caller-Visible Contract

- `playbook.print(name, context?)` → returns the auto-included, variable-
  substituted, harness-rendered procedure text **inline** in the MCP tool result
  (compact readable text, per the MCP-runtime text-output rule).
- `playbook.render(name, context?)` → writes the same rendered content to a
  **worktree-scoped tmp file** and returns the **path** (not the content). This
  keeps full delegate prompts out of the lead's context window. Mirror wsflow
  `prompt.render`'s worktree-tmp behavior.
- `name` is a playbook name resolvable by `wsrsrc.Load` against the rsrc tree
  (or `WS_RSRC_ROOT`). `context?` is an optional map of caller-injected
  substitution variables, subject to `wsrsrc`'s declared-only substitution
  (undeclared → `ErrUndeclaredVar`; declared-but-used-and-unprovided →
  `ErrUnprovidedVar`).
- Failures are loud and typed: a missing/incompatible manifest, missing file,
  hash mismatch, or undeclared/unprovided variable surfaces as an `isError`
  tool result with the typed-error reason. No embedded fallback text.
- Harness selection: the detected session harness (claude/codex) selects the
  terminology values and any `<name>.<harness>.md` overlay; unknown harness ⇒
  host-neutral base text with no harness-specific terminology substitution.
- Delegation tip: for `delegates: true` playbooks, inject the standard
  continuity tip fragment at render/print time. Tip is harness-aware (its
  continuation idiom comes from the terminology table, e.g. claude:
  `SendMessage(to: <agentId>)`). agentId continuity is tip-only — no MCP
  registry, no mandated memory-file recording.

## Contract Instructions

- Source tree: `agents-plugin-tool/`, primarily `internal/mcp/server.go`
  (schemas in `tools()`, dispatch in `callTool`, visibility/gating in the
  product-mode/profile points) and the harness/config seams it already owns.
- Add the MCP tools via the standard recipe: schema in `tools()`, dispatch case
  in `callTool`, `runtime.json` refresh if the advertised tool surface changes,
  and visibility tests. Both `tools()` and `callTool` must be updated together
  (a schema without dispatch is a visible broken tool; dispatch without schema
  is unreachable).
- **Build on the existing `wsrsrc.Load` seam** — do NOT add a parallel loader,
  do NOT route through `wsprompt` (the two loaders are deliberately
  non-overlapping). The render/print layer assembles the final `vars` map and
  the harness selector, then calls `wsrsrc.Load`.
- **Harness terminology vs structural divergence** (settled split):
  - Small terminology substitution (`explore_agent`, `spawn_idiom`,
    `continue_idiom`, etc.) flows through `wsrsrc`'s existing declared-variable
    substitution: the playbook declares them in `variables:` frontmatter, and
    the render/print layer resolves their values from the bundled
    **terminology table** (claude+codex) and passes them in `vars`.
  - Whole-procedure structural divergence uses the `<name>.<harness>.md`
    **overlay** mechanism that `wsrsrc.Load` already applies. Do not encode
    structural divergence as terminology vars.
- **Terminology table ships as data, not prose, not config**: a bundled
  claude+codex table (Go-level table or bundled rsrc data file — implementation
  choice) holds the non-model idioms. Do NOT bake these idioms into each
  playbook's prose, and do NOT make them user-config.
- **Model aliases come from config, never the bundle**: resolve concrete
  per-provider model names through the existing `config.agents_tier` /
  model-alias config surface (`wsconfig`), harness-aware. The rsrc text and the
  binary must never bake concrete model names. If a playbook references a model
  alias, resolve it from config at render time and pass it as a `vars` value.
- **Harness detection**: reuse the existing session-harness signal the server
  already records from MCP payloads (`initialize.params` Claude/Codex identity,
  Codex `tools/call._meta.x-codex-turn-metadata`). Do not invent a new detection
  path. Unknown/unrecorded harness ⇒ host-neutral fallback.
- **Caller `context` vs tool-injected vars**: the tool merges caller `context`
  vars with tool-resolved harness/model vars into the single `vars` map handed
  to `Load`. Keep harness/model var names distinct from caller-context var names
  so there is no silent collision; if a collision is structurally possible,
  define and document precedence (tool-injected harness/model values win for
  reserved names).
- **Tool gating**: `playbook.print`/`playbook.render` are full-ws tools (not
  wsflow-only, unlike `prompt.render`). They are not agent-backed, so they are
  not hidden by the no-agent gate. Apply whatever the spec
  (`260609-playbook-tools`) and existing gate patterns dictate; if a gate
  predicate is added, apply it at all three points (`callTool`, `toolAllowed`,
  `LeadToolNames`) per the mcp-runtime recipe. Do not reclassify `prompt.render`.

### Forbidden wiring

- No temporary/mock terminology or model values baked in source to "make tests
  pass." Tests must exercise the real terminology-table + config resolution.
- No embedded fallback playbook text on load failure.
- No `runtime.json` refresh for rsrc *text* edits (rsrc content is decoupled
  from the bundle hash); only a *tool-surface* change refreshes `runtime.json`.

## Integration Test Instructions

- Boundary: MCP tool layer over `wsrsrc.Load`. Add Go tests in the
  `internal/mcp` test surface (and `internal/wsrsrc` if a loader-level seam is
  added), plus fixtures under `agents-plugin/rsrc/` if a `delegates: true` and a
  plain playbook are needed (regenerate `manifest.json` via
  `wsrsrc.GenerateManifest`; `TestValidateRealTree` must stay green).
- Pass criteria:
  - `print` returns rendered text **inline** with includes applied and declared
    vars substituted.
  - `render` returns a **tmp path** whose file contents match the rendered
    expectation (read the file and assert).
  - **Golden-render** for claude / codex / unknown-harness on a `delegates:
    true` playbook and a plain playbook: harness terminology substituted for
    claude+codex; host-neutral fallback for unknown; delegation tip present only
    for `delegates: true`.
  - Config-driven model-alias substitution verified with **no baked model
    names** (assert the resolved value came from config, e.g. by varying the
    config table).
  - Loud-failure path: missing/incompatible manifest, undeclared var, or
    dangling include surfaces as an `isError` result with the typed reason.
- Run: `cd agents-plugin-tool && go test ./...` (the existing workflow runs this;
  read full output before claiming pass).

## Implementation Strategy Decisions (settled — do not reopen)

- Two-command split, no unification (`print` inline vs `render` to tmp path).
- Plain-text rsrc loaded at call time via `wsrsrc.Load`; not `go:embed`, not a
  new loader.
- Manifest schema-version compatibility (not hash equality); loud typed-error
  failure, no embedded fallback.
- Harness set is claude + codex only; Gemini excluded; unknown ⇒ host-neutral.
- Harness differences ship as data (terminology table); model names live in
  config; structural divergence via overlay files only.
- Frontmatter-declared auto-includes (atomicity); flag-based include selection
  rejected.
- Delegation tip is a compact fragment for `delegates: true` only; agentId
  continuity is tip-only.

## Forward-Compatibility Guardrail (M3 keyed render signature)

The settled *final* signature is
`playbook.render(session_key, name, context?, root_override?)` — keyed like
every ws call; when `session_key.role == lead` it mints+injects a fresh child
key; `root_override` rebinds both the auto-include root and the child-key root
for worktree children. Phase 2 does NOT implement this (session-auth is M3), but
must leave the seam:

- Do not bake `name` in as an immovable first positional, and do not preclude
  prepending a `session_key` argument later (e.g. keep the dispatch arg-parsing
  tolerant/extensible rather than positional-rigid).
- Keep root resolution a **call-site-overridable seam**: the
  `WS_RSRC_ROOT`/auto-include root must be parameterizable from the call site
  (anticipating `root_override`), not hard-wired to a single process-global
  resolution.

## Rejected Alternatives

- Single tool with output-kind metadata (loses flexibility; risks full delegate
  prompts landing in the lead's context). → two-command split.
- Implementing the full keyed render signature in Phase 2 (impossible before M3
  session-auth exists). → ship `render(name, context?)` with the seam.
- A new/parallel playbook loader or routing through `wsprompt`. → reuse
  `wsrsrc.Load`.
- Baking model names into the bundle or terminology into playbook prose. →
  model names from config, terminology from the bundled data table.

## Approach

1. Add `playbook.print` / `playbook.render` schemas to `tools()` and dispatch to
   `callTool`; resolve the worktree root for `render`'s tmp file via the
   standard resolver (call-site-overridable seam).
2. Build a harness selector from the recorded session harness; resolve
   terminology values (bundled table) + model aliases (config) into the `vars`
   map; merge with caller `context`.
3. Call `wsrsrc.Load(name, harness, vars, root)`; for `delegates: true`, append
   the harness-aware tip fragment.
4. `print` returns the body inline; `render` writes worktree-scoped tmp and
   returns the path.
5. Refresh `runtime.json` if the tool surface changed; add fixtures + golden
   tests.

## Constraints

- MCP tool output is LLM-facing: compact readable text; tool results are text
  content even when structured.
- `wsrsrc` substitution is declared-only and single-pass; respect its typed
  errors and do not re-expand replacement values.
- rsrc includes are flat (root-level text deps); do not write nested includes.
- Do not refresh `runtime.json` for rsrc text edits; regenerate `manifest.json`.

## Out of scope

- session_key/auth, root_override implementation (M3).
- skill-body → playbook conversion (M2).
- spawn machinery / actor model / runner backends (M3).
- removing or changing wsflow `prompt.render`.
- Gemini harness support.

## Details

- Loader seam: `wsrsrc.Load` (prompt-bundle.md#260609-rsrc-playbook-distribution)
  — manifest schema-version gate, per-file hash integrity, harness overlay, flat
  includes, declared-only single-pass substitution, typed errors
  (`ErrManifestMissing`, `ErrSchemaMismatch`, `ErrHashMismatch`, `ErrFileMissing`,
  `ErrUndeclaredVar`, `ErrUnprovidedVar`).
- MCP recipe (mcp-runtime.md): schema in `tools()`, dispatch in `callTool`,
  gating at `callTool`/`toolAllowed`/`LeadToolNames` if a gate is added,
  `runtime.json` for tool-surface changes.
- Config model aliases: `config.agents_tier` / model-alias config
  (named-agent-runtime.md; mcp-tools.md#260508-model-alias-config-tools).
- Harness detection: session harness from MCP payloads
  (mcp-tools.md#260508-mcp-payload-harness-detection).

## Verification Contract

- `go test ./...` from `agents-plugin-tool/` green, including the new MCP-layer
  golden/inline/loud-failure tests and `TestValidateRealTree`.
- No baked model names (test proves config-sourced resolution).
- `render` tmp-path contents asserted by reading the file.
