## Existing Patterns

- **MCP tool add recipe**: schema entry in `tools()` (starts ~L2450, ends L2933), dispatch `case` in `callTool` (starts L361), `wsflowOnlyTool()` / `noAgentHiddenTool()` gating functions at L3118-L3140; `LeadToolNames()` at L2935 iterates `tools()` with the same gates. Since `playbook.print`/`playbook.render` are neither wsflow-only nor agent-backed, they require **no new gate predicate** — they simply appear in `tools()` and dispatch, and pass all existing gates as full-ws tools.
- **`toolAllowed()` role filtering**: L3039-L3056 — `delegate` role allows any tool not in `agents.*`, `config.*`, or `session.*`; both new tools clear this automatically. `leaf` role excludes `api.*`, `agents.*`, `config.*`, `session.*`, `subquery`, `git.commit`; playbook tools clear this too.
- **`isError` text response pattern**: `toolErrorTextResponse(req.ID, text)` at call sites (e.g., L738); `toolTextResponse(req.ID, "", err)` wraps any `error` as `isError`. Use these for loud typed failures from `wsrsrc.Load`.
- **Root resolver pattern**: `s.resolveToolRoot(params.Arguments, params.Meta)` called as first step in most tools (e.g., L400, L459); returns the worktree root for `GeneratePaths`. `playbook.render` needs this for the tmp-file step; `playbook.print` may not need root unless it also uses GeneratePaths.
- **Context map argument extraction**: `stringMapArgument(params.Arguments["context"])` already exists (e.g., L466) and returns `map[string]string`. Re-use this for the `context` argument on both new tools.
- **wsflow `prompt.render` dispatch at L853-860**: exact model for `playbook.render` — resolve root, extract `stem`/`name`, call render function, return path as text.
- **`prompt.render` schema at L2774-2785**: model for `playbook.render`/`playbook.print` schemas — `name` (required), `context` (optional object with string values), `root` (optional).
- **Harness-aware arg in `config.agents_tier` dispatch L543-545**: `s.currentHarness()` called inline at dispatch; same pattern for resolving harness in new tool handlers.

## Constraints

- **`wsrsrc` not imported in `server.go`**: grep over the file confirms zero `wsrsrc` imports. The import `"github.com/kang-sw/devenv/internal/wsrsrc"` must be added; no existing pattern to follow — new import block entry.
- **`ResolveRoot()` is a stub**: returns error if `WS_RSRC_ROOT` is unset. Phase 2 must implement the `os.Executable()` fallback or tests will require `WS_RSRC_ROOT` set. The comment in `loader.go#L26-30` gives the exact derivation: `filepath.Join(filepath.Dir(os.Executable()), "..", "rsrc")`. This matters for production; tests can use `t.Setenv(envRsrcRoot, ...)`.
- **Single `vars` map, declared-only substitution**: `wsrsrc.Load()` uses declared-only, single-pass substitution. The caller merges tool-injected vars (harness terminology, model aliases) with caller-supplied `context` vars into one `vars` map. If a caller-supplied key collides with a reserved tool-injected key, the brief says tool-injected values win for reserved names — this precedence must be implemented at merge time by overwriting caller values with tool-injected values after the merge, not before.
- **No terminology-table code exists yet**: the bundled claude+codex terminology table (e.g., `explore_agent`, `spawn_idiom`, `continue_idiom`) is new code — no Go-level table or bundled data file for it exists in `wsrsrc` or `mcp`. The implementer creates it.
- **No delegation tip text exists**: the harness-aware continuation tip is new copy. Not in any existing Go source.
- **`agents-plugin/rsrc/` has no `delegates: true` fixture**: only `sample-playbook/sample-playbook.md` with `delegates: false` (confirmed by reading the file). A new fixture playbook with `delegates: true` must be added and `manifest.json` must be regenerated (`WSRSRC_REGEN=1`). `TestValidateRealTree` will fail until regenerated.
- **`runtime.json` update**: `agents-plugin/runtime.json` must have `playbook.print` and `playbook.render` added to the `tools` dict. `agents-plugin-wsflow/runtime.json` does NOT get them (they are full-ws, not wsflow tools). The current `prompt.render` absence from the main runtime.json and presence in wsflow runtime.json is the correct asymmetric pattern to follow.
- **Namespace substitution is NOT applied to playbook content**: `prompt.render` applies `wsNamespaceRef.ReplaceAllString` to body text; `playbook.render`/`playbook.print` must NOT apply this regex — their substitution is declared-var only via `wsrsrc.Load(vars)`. Accidental reuse of the regex would mangle playbook content for non-wsflow callers.
- **`wsflowOnlyTool()` must NOT include `playbook.*`**: the new tools are full-ws, so they must not be added to the `wsflowOnlyTool()` switch at L3133-3140. They also must not be in `noAgentHiddenTool()` at L3118-3131.
- **`GeneratePaths` "prompt" kind already exists**: L70 in `generated_paths.go`; no extension needed.
- **`generatedPathTarget` at L66-L75**: only supports `"review"` and `"prompt"` — no changes needed.

## Risk Signals

- `agents-plugin-tool/internal/wsrsrc/loader.go#L25-L31` — Possible **reuse risk**: `ResolveRoot()` is an explicit Phase-2 stub returning an error when `WS_RSRC_ROOT` is not set. The brief assumes Phase 2 completes this; if the implementer skips the `os.Executable()` fallback, all production invocations without `WS_RSRC_ROOT` fail. The stub comment names the exact pattern. Lead/planner should confirm whether the executable-path fallback is in scope or deferred to a sub-phase.

- `agents-plugin-tool/internal/mcp/server.go#L3133-L3140` (`wsflowOnlyTool`) + `L2943` (`LeadToolNames`) — Possible **contract risk**: brief says `playbook.print`/`playbook.render` are NOT wsflow-only and are not agent-backed. The three-point gating requirement (`callTool` / `toolAllowed` / `LeadToolNames`) only applies when a new gate predicate is added. No new gate is required here, but the implementer must verify these tools do not accidentally appear in `wsflowOnlyTool()` (which would make them invisible in full ws) or `noAgentHiddenTool()` (which would hide them in wsflow no-agent mode). Current pattern makes this easy to violate by analogy with `prompt.render`.

- `agents-plugin-tool/internal/wsrsrc/wsrsrc.go#L80-L94` (`ErrUndeclaredVar`) — Possible **test risk**: if the terminology table injects vars not declared in the playbook frontmatter, `wsrsrc.Load()` returns `ErrUndeclaredVar`. Every variable the tool layer injects must be declared in the playbook's `variables:` list. The new fixture playbooks must declare all tool-injected reserved names. `TestValidateRealTree` validates declared vs. used vars for the real tree (L665 in `wsrsrc_test.go`), so this would surface during CI.

- `agents-plugin/rsrc/manifest.json` — Possible **shortcut risk**: adding new playbook fixtures without running `WSRSRC_REGEN=1` leaves `TestValidateRealTree` (L665) red. The regen command is `cd agents-plugin-tool && WSRSRC_REGEN=1 go test ./internal/wsrsrc/... -run TestGenerateRealManifest -v`. The brief explicitly requires this; missing it is a common mistake documented in the mental model.

- `agents-plugin-tool/internal/wsconfig/config.go#L156-L199` — Possible **reuse risk**: model-alias resolution returns `(backend, model, effort, error)`. The playbook tool layer only needs `model` for substitution into vars. The `opts Options{CacheHome: ...}` requires `WS_CACHE_HOME` to be set, or it falls back to OS cache dirs. Tests that exercise config-sourced model names must set `t.TempDir()` as `WS_CACHE_HOME` (pattern established in `config_test.go`). If tests omit this, they may resolve real user config values and fail the "no baked model names" assertion.

- `agents-plugin/runtime.json` + `agents-plugin-wsflow/runtime.json` — Possible **contract risk**: `playbook.print`/`playbook.render` must appear in `agents-plugin/runtime.json` only, NOT in `agents-plugin-wsflow/runtime.json`. The current version range is `">=0.30.0-dev <0.31.0"`. Adding new tool names to the same range is sufficient unless the brief requires a version bump. The brief says "runtime.json refresh if a tool-surface bump is required" — it does, since new tools are visible.

- `agents-plugin-tool/internal/mcp/server.go#L3161-L3196` (`renderPrompt`) — Possible **reuse confusion**: `renderPrompt` is the wsflow `prompt.render` function. `playbook.render` should NOT call `renderPrompt`. It shares the `GeneratePaths(root, "prompt", ...)` + `os.WriteFile` pattern but must call `wsrsrc.Load()` instead of `wsprompt.RenderSource()`, and must not apply `wsNamespaceRef` substitution. The visual similarity of the two functions is a copy-paste trap.

## Opinion

- The seam surface is clean and well-tested; Phase 1 (`wsrsrc`) is feature-complete. The main new code is: (a) the bundled terminology table (new Go data), (b) the delegation tip text (new copy), (c) the `ResolveRoot()` `os.Executable()` fallback, and (d) the two MCP tool handlers in `server.go` that wire these together.
- The single most load-bearing decision not visible in the code is the **terminology variable names**: what names the playbook `variables:` frontmatter declares for harness-specific idioms (e.g., is it `ExploreAgent`, `SpawnIdiom`, `ContinueIdiom`?). Whatever the implementer chooses, all fixture playbooks and the terminology table must use the same names consistently; `TestValidateRealTree` will catch mismatches.
- `ResolveRoot()` Phase-2 stub is the only seam with a non-trivial completion task; the rest of the implementation is mechanical wiring of existing primitives.
