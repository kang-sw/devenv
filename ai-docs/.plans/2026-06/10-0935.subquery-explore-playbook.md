# Survey: subquery-explore-playbook

## Reusable Components

- `agents-plugin-tool/internal/wsrsrc/manifest.go#L41-L72` — `wsrsrc.GenerateManifest(root string)`:
  walks the rsrc tree, sha256-hashes every file (CRLF-normalised), skips `manifest.json`
  itself, returns `Manifest{SchemaVersion: SupportedSchemaVersion, Files: map[string]string}`.
  Deterministic: `filepath.Walk` is lexical order, `json.Marshal` sorts map keys.

- `agents-plugin-tool/internal/wsrsrc/manifest.go#L76-L83` — `wsrsrc.WriteManifest(root, m)`:
  serialises to indented JSON + trailing newline, writes `root/manifest.json` (mode 0644).

- `agents-plugin-tool/internal/mcp/playbook_tools_test.go#L24-L44` — `buildTestRsrcTree(t, map[string]string)`:
  test helper that writes arbitrary playbook files to a `t.TempDir()`, calls
  `wsrsrc.GenerateManifest` + `wsrsrc.WriteManifest`, returns the root path.
  This is the standard per-test fixture harness; new explore tests should use it for
  fixture-based cases.

- `agents-plugin-tool/internal/mcp/playbook_tools_test.go#L47-L54` — `newTestServerWithHarness(t, harness)`:
  creates a `*Server` bound to a temp root; pass `"claude"`, `"codex"`, or `""` (neutral).

- `agents-plugin-tool/internal/mcp/playbook_tools.go#L226-L236` — `printPlaybook(s, rsrcRoot, name, callerContext, configOpts)`:
  renders the playbook body text inline; zero-logic wrapper over `renderPlaybookBody`.
  Used by all golden-render tests.

- `agents-plugin-tool/internal/mcp/playbook_tools.go#L153-L165` — `delegationTip(harness)`:
  returns the `\n\n---\n**Continuity tip:** …` fragment appended when `meta.Delegates == true`.
  Full fragment text:
  > `**Continuity tip:** This playbook delegates to a subagent. When the subagent returns an agent id, use \`` + ContinueIdiom + `\` to send follow-up messages to the same agent rather than spawning a new one. The playbook surface keeps no agent registry; record the agent id in your workflow state if you need it across turns.`

## Existing Patterns

- **Real-rsrc golden test pattern** — `playbook_tools_test.go#L639-L711`:
  Uses `rsrcRoot := filepath.Join("..", "..", "..", "agents-plugin", "rsrc")` (relative from
  `agents-plugin-tool/internal/mcp/`). New `explore` golden tests must use this same path.
  Three functions cover claude/codex/neutral; each checks:
  1. Derived check: `terminologyForHarness(h)[varName]` present in body for all three vars.
  2. Anti-tautology hardcoded check: literal string values (e.g. `"the Explore agent"`,
     `"SendMessage(to: <agentId>)"`) asserted directly so a wrong table cannot produce
     a false-positive derived pass.
  3. Delegation tip: `strings.Contains(body, "Continuity tip")`.

- **Fixture-based harness test pattern** — `playbook_tools_test.go#L158-L226`:
  Uses `buildTestRsrcTree` + `delegatePlaybookContent` fixture (see below). New
  `explore` playbook golden tests are real-rsrc (like lines 639-711), not fixture-based.
  Fixture-based pattern is still available for isolated unit cases.

- **Manifest regen recipe** — `wsrsrc_test.go#L676-L689` (`TestGenerateRealManifest`):
  `WSRSRC_REGEN=1 go test ./internal/wsrsrc/... -run TestGenerateRealManifest -v`
  run from `agents-plugin-tool/`. Skip guard on line 679: skips unless `WSRSRC_REGEN` env set.

- **CI tree-sync gate** — `wsrsrc_test.go#L665-L670` (`TestValidateRealTree`):
  `Validate(agents-plugin/rsrc)` fails if any file drifts from `manifest.json`.
  Adding `explore/explore.md` without regenerating manifest will fail this test.

## Constraints

- `WSRSRC_REGEN=1` must be set when running `TestGenerateRealManifest`; without it the test
  skips silently. Not obvious from test output. The regen must be run from `agents-plugin-tool/`
  so the relative path `../../../agents-plugin/rsrc` resolves correctly.

- `TestValidateRealTree` uses `wsrsrc.Validate(root)` which walks the entire rsrc directory
  and checks every file against the manifest. Adding `explore/explore.md` without regen causes
  `ErrUnlistedFile`; manifest drift (editing `explore.md` after regen) causes `ErrHashMismatch`.
  Both fail the test.

- `playbookTerminologyTable` in `playbook_tools.go#L22-L39` is the single source of truth for
  all three harness rows. Tests via `terminologyForHarness(h)` call the same function. The
  anti-tautology hardcoded-string asserts in `TestPlaybookPrintGoldenDelegateSample*` (lines
  657-660, 685-689) guard against a wrong table silently passing derived checks — new explore
  golden tests must include at least one hardcoded literal per harness.

- Delegate tip detection string is `"Continuity tip"` (the header word used in
  `delegationTip()` at line 158 of `playbook_tools.go`). Tests assert
  `strings.Contains(body, "Continuity tip")`.

## Risk Signals

- `agents-plugin-wsflow/tests/test_wsflow_skill_bundle.py#L84-L88` —
  Possible **mirroring-gap** risk: this test asserts `"Use subagents when a task benefits from
  scoped exploration"` and `"Write subagent prompts in English."` exist in the **wsflow** copy
  of `lead-workflow-manual/SKILL.md`. The brief rewrites the **full-ws** copy only. The wsflow
  copy is not edited here. However, if the wsflow copy diverges from the new full-ws text in a
  way that makes the wsflow test assertion stale, it will silently pass (it checks for presence,
  not absence). No immediate breakage, but the follow-up wsflow mirroring ticket should verify
  these assertions remain accurate against the post-M2 wsflow copy.

- `agents-plugin-wsflow/tests/test_wsflow_skill_bundle.py#L73-L82` —
  Possible **scope confusion** risk: `SKILLS_DIR` resolves to `agents-plugin-wsflow/skills/`
  (the wsflow copy), not `agents-plugin/skills/`. The `FORBIDDEN_PATTERNS` dict (L44-L54)
  includes `\bsubquery\b` and `\bws/`. These patterns scan ONLY wsflow skills. Editing
  `agents-plugin/skills/*/SKILL.md` (full-ws) does NOT trigger this scanner.
  Confirmed: `FULL_PLUGIN_SKILLS_DIR` is defined at line 7 but never passed to `rglob` in
  the forbidden-pattern test — only `SKILLS_DIR` is. Full-ws edits are safe from this gate.

- `agents-plugin-tool/internal/mcp/playbook_tools_test.go#L116-L129` — `delegatePlaybookContent`
  fixture: the test fixture already uses all three terminology vars and `delegates: true` /
  `kind: render`. New `explore` real-rsrc golden tests (following lines 639-711) reference the
  live rsrc file, not this fixture. If the fixture is accidentally used instead of the real path,
  the test would not catch explore.md regressions. Not a blocker, but worth noting the two-level
  test structure: fixtures for unit isolation, real-path for CI gate.

## Opinion

- The survey is unambiguous; no escalation is needed. Every reuse point is pinned.
- `lead-forge-spec` has 14 `ws/subquery` call sites spread across multiple parallel-dispatch
  blocks (lines 43-75, 120-155, 201, 253). These are mechanically similar but structurally
  distinct (4-query Phase 1 block, 4-query Phase 2 block, single Phase 3 check, Phase 4 update).
  The implementer should read the full file before editing to avoid partial replacement.
- No full-ws test currently asserts on literal `ws/subquery` skill text. The only assertions
  on full-ws skill files are in `wsgit/git_test.go` (path fixtures for git-status parsing, not
  content scanning). The prose audit (`grep -rn "ws/subquery(" agents-plugin/skills`) is manual.
