# Brief: subquery → Explore playbook (260609 M2 Phase 1)

## Intent

Absorb the embedded `subquery` worker prompt into a new harness-aware **Explore
playbook** under the rsrc tree, and shift every `ws/subquery` delegation
reference in shipped full-ws skill text to a host-neutral native-Explore
delegation pattern. This converges the full-ws skill surface onto the M1 playbook
model (`playbook.print`/`playbook.render` + `wsrsrc` loader + harness terminology
table) for scoped fact-finding. No runtime tool is deleted and no internal skill
body is migrated in this slice.

## Scope Boundary

**In scope (Phase 1 only):**
1. New render-kind Explore playbook at `agents-plugin/rsrc/explore/explore.md`
   (terminology vars + `delegates: true`).
2. Regenerate `agents-plugin/rsrc/manifest.json` to include the new file.
3. Shift `ws/subquery(...)` delegation references in the shipped full-ws skills
   (`agents-plugin/skills/*/SKILL.md`) to the native-Explore delegation pattern.
4. Golden render tests for the Explore playbook (claude / codex / neutral +
   delegation tip) in the M1 test home.

**Out of scope (defer, do not touch):**
- `agents-plugin-tool/internal/wsagent/subquery.go`, its `server.go` registration,
  or any `agents.*` runtime code — the `ws/subquery` tool stays callable. Runtime
  removal is **M3**.
- Migrating the 9 internal skill bodies to `playbook.print`, or reducing entry
  skills to shims — that is **M2 Phase 2**. The
  `260610-entry-skill-surface-reduction` spec stem stays 🚧.
- `agents-plugin-wsflow/` skills (see Constraints — handled by a follow-up
  ticket, not edited here).
- `prompt.render` (wsflow-only) and its embedded-prompt allowlist.

## Caller-Visible Contract

- A new playbook named `explore` renders through `playbook.print` /
  `playbook.render`: claude and codex receive harness-correct
  `{{.ExploreAgent}}` / `{{.SpawnIdiom}}` / `{{.ContinueIdiom}}` substitutions;
  any unrecognized harness (including `""`) renders the neutral row. Because the
  playbook is `delegates: true`, the rendered output carries the always-on
  delegation (mercenary-tip) fragment.
- Shipped full-ws skill text no longer instructs `ws/subquery(...)` for new
  scoped-exploration delegation. Instead it delegates to a native Explore-style
  subagent, taking the worker brief from the `explore` playbook. The async
  fire-and-forget + deferred-result shape maps to native background subagents.
- The `ws/subquery` MCP tool remains advertised and callable (no contract
  removal); `lead-workflow-manual` keeps one short note that it is retained but
  no longer the shipped-skill delegation path.

## Contract Instructions

**Explore playbook** — `agents-plugin/rsrc/explore/explore.md`:
- Frontmatter: `kind: render`, `delegates: true`,
  `variables: [ExploreAgent, SpawnIdiom, ContinueIdiom]`. These three are the
  M1 reserved terminology names (config/terminology-injected by the tool layer;
  callers cannot override them). Declare a variable only if its `{{.Name}}`
  actually appears in the body (else `ErrUnprovidedVar`); do not declare a
  reserved name you do not use.
- Body: adapt `wsagent.SubquerySystemPrompt` (see Details) into a generic
  "scoped Explore worker" brief — parse question type, breadth-first before
  opening files, confirm non-obvious answers with a second search, read-only,
  English-only output, lead with a one-to-two-sentence direct answer, cite
  file references, add Assumptions/Gaps only when needed. Replace the
  tool-specific word "sub-query"/"subquery" with Explore-worker framing. Weave
  the terminology vars in where the harness-specific agent name, spawn idiom, and
  continue idiom belong.
- Single base file. Add `explore.codex.md` overlay ONLY if a real structural
  divergence is needed; terminology-var substitution alone does not justify an
  overlay (default: no overlay).

**Manifest** — regenerate `agents-plugin/rsrc/manifest.json` via
`wsrsrc.GenerateManifest` (the existing generator path / test helper). Do NOT
bump `SupportedSchemaVersion` (no schema-shape change). Do NOT edit
`agents-plugin/runtime.json` or any `runtime.json` — rsrc text is decoupled from
the prompt-bundle hash; only `manifest.json` regenerates.

**Skill-text shift** — edit each shipped full-ws skill that names `ws/subquery`
(reference map in Details). Pattern:
- `lead-workflow-manual` is the canonical home: replace the `ws/subquery`
  primitive description with a "Scoped Exploration (native Explore)" primitive
  that documents the pattern — render the `explore` playbook
  (`playbook.render(name: "explore", context: {...})` to hand a worker a brief
  file, or `playbook.print` for inline), then spawn a native Explore-style
  subagent, then collect the deferred result. Keep one short line that
  `ws/subquery` remains callable but is not the shipped-skill delegation path.
- Every other skill: replace its `ws/subquery(question: ...)` +
  `ws/agents.result(name: <subquery-key>, ...)` call lines with the native
  Explore delegation pattern, referencing the `lead-workflow-manual` primitive /
  `explore` playbook. Preserve each skill's original scoping intent (e.g.,
  `lead-forge-spec`/`lead-forge-mental-model` "broad tracing" surveys map to a
  broad-scope Explore worker; parallel multi-query dispatch maps to multiple
  concurrent native subagents).

**Forbidden:**
- Deleting or disabling `subquery.go` / the `ws/subquery` registration.
- Hard-coding harness-specific agent names (e.g., literal "Task tool" / "Explore
  agent") in skill text — terminology lives in the playbook and renders per
  harness.
- Writing native-as-exclusive delegation prose (see Implementation Strategy
  Decisions — native is the default, not the only path).
- Editing any `agents-plugin-wsflow/` file.

## Implementation Strategy Decisions

Settled — do not reopen:
- The Explore playbook is `kind: render` (worker brief handed to a native
  subagent via a tmp path), not `kind: print`.
- Native delegation is the **default, not the exclusive** path. The epic 260605
  option-B mercenary surface (M3) stays lead-invokable; the `delegates: true`
  tip fragment **is** the always-on mercenary-tip seam. Marking the playbook
  `delegates: true` preserves the seam — do not inline native-only prose and do
  not wire any mercenary runtime/routing here (M3).
- Terminology stays in the playbook (rendered per harness), never duplicated as
  per-harness literals in skill text. Skill text is host-neutral.
- `ws/subquery` tool is retained; only skill-text references move.
- `manifest.json` regen only; no `runtime.json`, no schema-version bump.

## Rejected Alternatives

- **Delete `subquery.go` now** — rejected; runtime removal is M3, and skills must
  keep working during migration.
- **`kind: print` Explore playbook** — rejected; a delegation worker prompt is
  rendered with caller context and handed to a subagent (render semantics), not
  emitted inline as a lead procedure.
- **Editing wsflow skills in this slice** — rejected; wsflow already forbids
  `subquery`/`agents.*` and uses `prompt.render`, and rsrc-playbook convergence
  for wsflow is epic non-scope. Captured as a follow-up (see Constraints).
- **A separate `.codex.md` overlay by default** — rejected; terminology vars
  cover the per-harness difference without structural divergence.

## Approach

- Author `explore.md`; regenerate `manifest.json`.
- Add golden render tests; run `go test ./...`; confirm green.
- Add the `lead-workflow-manual` native-Explore primitive; then shift the other
  skills' subquery call sites to reference it.
- Run the fresh-reader skill-text audit (lead-skill-authoring) on changed skill
  text before reporting.

  mirrored full-ws skills requires same-change wsflow update OR a follow-up
  ticket. Do NOT edit wsflow here; the slice instead records a follow-up
  (lead owns ticket creation at doc closeout) for wsflow explore-playbook /
  delegation-parity convergence, justified by epic 260605 non-scope (wsflow
  convergence deferred) and the fact that wsflow skill text is already
  subquery-free. Excluded-from-wsflow skills touched here (`lead-salvage`,
  `lead-skill-authoring`, `lead-write-skeleton`) need no wsflow action.
- Skill/agent/prompt edits run the lead-skill-authoring fresh-reader audit after
  local reread (the Fit reviewer covers this).
- All authored text is English.
- Preserve each skill's existing structure, doctrine, and invariant style; this
  is a surgical reference shift, not a skill rewrite.

## Out of scope

  `260610-entry-skill-surface-reduction` spec behavior.

## Details

**Source prompt to adapt** — `agents-plugin-tool/internal/wsagent/subquery.go`,
`const SubquerySystemPrompt` (24 lines): scoped sub-query worker; constraints
(answer only the question, no editorializing, confirm non-obvious with a second
search, read-only, English-only); process (parse question type, broad search
first, breadth-first for under-specified, follow evidence, stop at scope);
output (direct answer first, cite codebase claims, Assumptions/Gaps only when
needed). Subquery suppresses delegate orientation because it is self-contained
(`#260505-async-subquery-ephemeral-agent`).

**M1 render shape reference** — `agents-plugin/rsrc/delegate-sample/delegate-sample.md`
is the `kind: render` + `delegates: true` + `[ExploreAgent, SpawnIdiom,
ContinueIdiom]` fixture; mirror its frontmatter shape. Reserved terminology and
the "Add a playbook" recipe are documented in `prompt-bundle.md`
(`#260609-playbook-harness-rendering`, Extension Points).

**Skill-text reference map** (`ws/subquery` delegation call sites to shift;
line numbers approximate, re-grep before editing):
- `lead-workflow-manual/SKILL.md` — primitive doc (lines ~28, 56, 61-64, 196-198):
  the canonical native-Explore primitive lives here.
- `lead-discuss/SKILL.md` — ~19, 44.
- `lead-verify-discussion/SKILL.md` — ~25-26.
- `lead-sprint/SKILL.md` — ~115-116.
- `lead-salvage/SKILL.md` — ~50-51 (excluded from wsflow).
- `lead-skill-authoring/SKILL.md` — ~52 (excluded from wsflow).
- `lead-write-ticket/SKILL.md` — ~13.
- `lead-write-spec/SKILL.md` — ~15, 37.
- `lead-forge-spec/SKILL.md` — many (~13-253; parallel multi-query survey blocks).
- `lead-forge-mental-model/SKILL.md` — many (~13-148; parallel multi-query).
- `lead-write-skeleton/SKILL.md` — ~45-46 (deprecated skill, excluded from wsflow).

`lead-forge-spec` and `lead-forge-mental-model` are the heaviest: they dispatch

keys. Map these to multiple concurrent native Explore subagents with a
broad-tracing scope, preserving the "dispatch all in one turn, collect all
before synthesizing" structure.
